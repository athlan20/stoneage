# PK：玩家决斗（设计）

STAGE-305。**说人话**：想被挑战的人打开「接受决斗」开关，同一张地图上的人就能向他发起决斗，双方（连同各自的真人队友和宠物）进同一场战斗。输赢**不给经验、不掉石币和物品、不扣魅力、不送回记录点**，只改变一个新数值「决斗点数（DP）」：打倒别人拿走对方 DP 的一成，被打倒丢一成，中途逃跑丢两成。以后按 DP 排「强者表」。规则全部照原版 2.5，只把“面对面”换成“同一张地图”。

相关文档：附近玩家与真人组队 `social-players.md`，交易 `trade.md`（请求、开关、校验顺序的写法都沿用它们），战斗协议 `protocol.md` 第 10 章（特别是 10.14 真人队同场）。

## 一、原版怎么做（原版服务端，已查实）

出处都在 `original-data/gmsv/`。

### 1.1 发起

- 客户端按“决斗”按钮发 `DU`（`callfromcli.c:889` `lssproto_DU_recv`）：找**面朝方向前一格**上的玩家。
- 对方必须**打开了决斗开关**（`CHAR_ISDUEL`，客户端用 `FS` 标志设置，`callfromcli.c:1144`）；没开的跳过（`950`）。对方在战斗中也跳过。
- **没有二次确认**：开关就是同意，找到人立刻开战（`BATTLE_CreateVsPlayer`）。前一格有多个人时弹窗让发起者选（`1030-1060`，显示“名字 [团体/单独]”），选完再校验一遍开关和距离（`char/char.c:4155-4170`）。
- **发起者是队员时整个请求不处理**（`910` 的 `!= CHAR_PARTY_CLIENT`）：只有单人和队长能发起。
- **对方是队员时找他的队长**（`1013-1017`），整队应战；但检查的开关是**被点到的那个人**的，不是队长的。
- 同一队伍不能互打（`battle.c` `BATTLE_ERR_SAMEPARTY`）。
- 失败时提示：前方没人「那里没有任何人。」，有人但都不能打「无人可以对战。」，开战失败「遭遇失败！」。

### 1.2 开关的生命周期

- **登录时强制关**（`char/char.c:1243`）。
- **每打完一场决斗自动关**（`battle.c:1241-1248`，退出 PvP 战斗时清掉 `CHAR_ISDUEL` 并把新标志推给客户端）。
- 所以开关是“这一次我接受挑战”，不是长期状态。

### 1.3 战斗

- `BATTLE_CreateVsPlayer`（`battle.c:2296`）：类型 `BATTLE_TYPE_P_vs_P`，`dpbattle = 1`。发起方整队进 0 号方，被挑战方整队进 1 号方（`BATTLE_PartyNewEntry`），各自带出战宠物。
- **不能中途加入**：两边的 `BSIDE_FLG_HELP_OK` 都清掉（`2326`），乱入请求直接拒绝（`1394`）。
- 回合、超时、整场时限与真人队同场战斗相同（120 秒、无默认指令、超时踢出、3600 秒，见 `battle-party-research.md` 第 4 节）。
- PvP 特有的分支：

  | 规则 | 出处 |
  |---|---|
  | **逃跑必定成功**（不看幸运和等级） | `battle_event.c:3496` |
  | 异常状态的命中**不计等级差**修正 | `battle_event.c:4388` |
  | 复活类精灵（`MultiRessurect`、`MultiResAndDef`）**对人物无效**，宠物照常 | `battle_magic.c:596`、`1598` |
  | 敌方求援（`ENEMYHELP`）不发生 | `battle_event.c:5403` |
  | 不给经验、石币、掉落，改结算 DP（`GetProfit`/`AddProfit` 的 `dpbattle` 分支） | `battle.c:3332`、`4886` |
  | 倒下、打飞：**不扣魅力、不降宠物忠诚、不计宠物死亡次数、不送回记录点** | `battle.c:4259`、`4311`；`BATTLE_NormalDeadExtra` 只对 `P_vs_E` 生效（`4368`） |
  | 倒下的人退场后 1 血，留在原地 | `_BATTLE_Exit`（同普通战斗） |
  | 宠物技能「偷窃」**只对真人有效**：50% 成功；成功时一半概率让对方**石币减少 8–12%**，一半概率**销毁**对方背包（不含装备栏）里随机一件物品。偷到的东西不归偷的人，直接消失 | `battle_event.c:4990` `BATTLE_Steal` |

### 1.4 决斗点数（DP）

- 新角色 **100**（`include/defaultPlayer.h:85`），下限 0，上限 1 亿（`char_base.h:42`），比例 `DUELPOINT_RATE = 0.1`（`battle.h:13`）。
- **人物倒下时当场结算**（`BATTLE_AddDuelPoint`，`battle.c:4490`，本服没开 `DANTAI`，用的是这一版）：
  - 倒下的人物丢 `floor(自己 DP × 0.1)`；
  - 被对方打倒：这份平分给本次出手打倒他的人（宠物出手算主人），每人至少 1；
  - 被自己人打倒（误伤）：这份平分给对方还活着的人，每人至少 1；
  - 宠物倒下不涉及 DP。
- **逃跑、掉线、超时踢出**（`BATTLE_EscapeDpSend`，`battle.c:4426`；掉线 `char/char.c:1501`；超时走同一个逃跑函数，`battle_event.c:3607`）：逃跑者丢 `2 × max(1, floor(DP × 0.1))`，其中一份平分给对方还活着的人。
  - **免罚逃跑**：第一回合里双方都还没人出过攻击类指令、也没人倒下时逃跑，不扣 DP（`BATTLE_FLG_FREEDP`，`battle_command.c:52`、`454`）。
- 离开战斗时把这场累计的增减写进 DP（`BATTLE_GetDuelPoint`，`battle.c:3049`）：累计为 0 不变，否则至少 ±1；结果窗口显示“增减 | 现值”（`RD` 封包）。
- 原版角色上还有决斗场数、胜、负、连胜、最高连胜五个字段（`CHAR_DUELBATTLECOUNT` 等），**只存不写**，是死字段。

### 1.5 周边

- **任何地图都能决斗**（`_BATTLE_FLOOR` 强制战斗地图没开）。家族 PK 地图另有规则，不属于本设计。
- **竞技场**（地图 130，`mapnames_gen.go` 名「竞技场」）：各村「斗技场向导」凭门票（物品 2597）传送进去，组队不能入场（`data/npc/genout/wpm_1000_56_59`）。新服务端的传送员已经支持（`server/character/warpman_test.go`）。竞技场本身没有特殊规则，只是大家约在这里打。
- **强者表**（`npc/npc_duelranking.c`，竞技场里和各村都有）：选「强者们」看按 DP 排的世界排行（每页 10 人），选「自己」看自己的名次。
- **观战**（`BATTLE_TYPE_WATCH`）：可以旁观别人的战斗。
- 本服编译开着的私服扩展 `_AUTO_PK`（地图 20000 的定时 PK 赛、全服广播战况、冠军记录），以及没开的 `_BATTLE_PK`（强制 PK 道具）、家族庄园战，都**不属于 2.5 原版玩法，本设计不做**。

## 二、新版规则

### 2.1 总表

| 规则 | 说明 |
|---|---|
| 范围 | **同一张地图**（沿用“附近玩家”，原版“前一格”对应成同图）。隐身者视同不存在 |
| 开关 | 角色的社交设置 `duel`（「接受决斗」），**默认关**。**进入世界（登录、断线重连）时重置为关；每打完一场决斗（胜、负、平、逃跑、被踢出都算）自动关**。不持久化（原版 1.2） |
| 同意 | **开关就是同意**：对方开着开关，挑战立即开战，不再弹确认（原版 1.1；见“已拍板”1） |
| 谁能发起 | 单人或真人队队长；队员回复 `NOT_PARTY_LEADER`（原版）。挑战者自己的开关开不开都可以 |
| 对方是队员 | 整队应战；看**对方队长**的开关（与原版不同：原版看被点到的人，会出现队员一个人替整队答应；见“已拍板”2） |
| 分身队 | **有分身队的不能决斗**，双方都是（`ALREADY_IN_PARTY` / `TARGET_IN_PARTY`）。分身是项目新增的，不能让一个人带 4 个自己去打别人（见“已拍板”3） |
| 同队 | 不能和自己的队友决斗（`INVALID_TARGET`） |
| 状态 | 双方所有参战者都没倒下、不在战斗中、不在交易中（真人队里不会有人在交易中，见 `trade.md`） |
| 地点 | 任何地图都可以，没有安全区（原版） |
| 中途加入 | 不允许（原版 1.3） |
| 回合与超时 | 同真人队同场战斗（`protocol.md` 10.14）：本回合第一条被接受的指令起 120 秒，没有默认指令，没交齐的被踢出；整场 3600 秒平局 |
| 逃跑 | **必定成功**；扣 DP（2.2） |
| 捕捉 | 不允许（`allow.capture` 为 `false`） |
| 奖励 | **没有**经验、石币、掉落。精灵熟练度与抗性照常成长：原版 `Magic_ComputeAttExp` / `Magic_ComputeDefExp`（`battle_magic.c:1155`、`1262`、`3438`、`3520`）没有 PvP 判断，施法失败涨攻击熟练度、人物挨魔法涨防御熟练度；决斗里对方也是人物，所以挨打的一方同样会涨。即时写进角色，逃跑、掉线也保留 |
| 惩罚 | **没有**魅力减少、宠物忠诚下降（倒下类）、送回记录点。倒下的人物结束后 1 血留在原地（原版 1.3）。装备耐久照常消耗：原版 `BATTLE_ItemCrushSeq`（`battle_event.c:623`，`2444` 等四处调用）只看“造成了伤害”和“是人物”，没有 PvP 判断；决斗里攻防双方都是人物，所以打人的磨武器、挨打的磨防具，两边都掉耐久（打怪时只有自己这边掉） |
| 偷窃 | **决斗里无效**（与原版不同，2026-10-26 拍板）：对人物使用一律“没偷到”，不扣石币、不毁物品，同对怪物的现行行为。原版会让对方石币减少 8–12% 或销毁一件背包物品，决斗是双方同意的切磋，不该有财物损失 |
| DP | 见 2.2 |
| 频率 | 同一挑战者对同一目标 10 秒内最多发起一次（`RATE_LIMITED`）；因对方没开开关被拒（`TARGET_REFUSES`）不计数 |

### 2.2 决斗点数（DP）

照原版 1.4，用整数运算：

- `share(dp) = floor(dp / 10)`。新角色和老角色迁移时都是 **100**，范围 `[0, 100000000]`。
- **人物倒下**（不含宠物、不含分身——分身不会进决斗）：
  - 倒下者本场累计 `-share(倒下者 DP)`，这里的 DP 是**开战时**的值（原版同样用 `CHAR_DUELPOINT`，战斗中不更新）；
  - 对方打倒的：这份按人平分给本次行动的出手者（宠物出手、合体技的每个参与者都按主人算，同一主人算一份），`max(1, share / 人数)`；
  - 自己人打倒的（误伤、反弹、混乱）：平分给对方当前活着的人物，`max(1, share / 活着人数)`；
  - 同一个人在一场里可以倒下多次（被宠物复活后再倒），每次都按开战时的 DP 结算一次（原版如此）。
- **逃跑成功 / 超时踢出 / 掉线**（人物还活着时）：本场累计改为 `-2 × max(1, share)`（**覆盖**此前累计，原版 `setWorkInt`），其中 `max(1, share)` 平分给对方活着的人物。
  - **免罚**：第 1 回合，双方都还没有人提交过攻击类指令（攻击、精灵、宠物技能、道具；防御、逃跑、换宠不算），且没人倒下，此时逃跑不扣 DP。
- **结束写回**：每名人物离开战斗时，`DP = clamp(DP + 累计, 0, 1e8)`；累计非 0 时至少 ±1。累计里加的那部分来自别人的损失，所以全服 DP 总量只因“至少 1”与下限 0 而略有浮动，与原版一致。
- 赢了的一方如果没打倒任何人（对方全员逃跑），只拿逃跑者分出来的那份。

### 2.3 战斗中的其他差异（引擎）

- 宠物技能、精灵里“对怪物 / 对玩家”的分支：PvP 里敌方人物走“玩家”分支，以原版对应函数的 `CHAR_TYPEPLAYER` 判断为准，开工时逐个对照 `battle-topics.md` 的清单。唯一例外是偷窃：决斗里对人物无效（2.1）。
- 复活对人物无效，精灵和道具都一样（宠物可以）：道具复活 `ITEM_useRessurect`（`battle_item.c:606`）和复活加防护的 `ITEM_ResAndDef`（`977`）最终都调 `BATTLE_MultiRessurect`，那里对 PvP 的人物直接跳过（`battle_magic.c:1598`）。**道具照样被消耗**（`BATTLE_ItemUseDelete` 在跳过之后无条件执行），界面上对倒下的对手或队友人物用复活道具时要提示“决斗中不能复活人物”，客户端在选目标时就把人物灰掉。
- 异常状态命中率的等级差修正为 0。
- 怪物专属行为（AI 出招、求援、怪物逃跑、稀有度幸运）在 PvP 里不出现，敌方全是真人。

### 2.4 断线与离场

同 `protocol.md` 10.14：掉线立即退场，按逃跑扣 DP（2.2）；离场不结算其他东西。队长逃跑、超时、掉线照 10.14 解散队伍，队员留在战斗里继续打。

## 三、协议草案

### 3.1 社交开关 `duel`（扩展 5.69）

- `social_settings` 的请求和 `social` 对象加 `duel` 布尔字段：**默认 `false`，不持久化**，进入世界时为 `false`。
- 决斗结束（每名人物自己离开战斗时）服务端把它的 `duel` 置为 `false`，值变了就推 `social_changed`。
- `duel` 在战斗中也能改；改了不影响正在打的这场。

### 3.2 附近玩家（扩展 5.66）

- `players` 和 `players_changed` 的玩家条目加 `duel: bool`（他是否接受决斗）。开关变化时推 `update`（隐身者不推，同 5.69）。
- 理由：没有走路和面朝，玩家得知道“谁现在可以打”，否则只能一个个试。原版客户端看得到别人头顶的状态图标，这是对应物。

### 3.3 `duel_challenge`（操作类，世界中，必须拥有控制权）

```jsonc
{"id": 90, "type": "duel_challenge", "data": {"name": "阿牛"}}
// 成功：先推送双方所有参战者的 battle_start，再回响应
{"id": 90, "type": "duel_challenge", "ok": true, "data": {"battle_id": "b_31"}}
```

**校验顺序**（第一个不满足的回复对应错误码，沿用 `trade.md` 2.2 的写法）：

1. 功能开关 `duel.enabled` 关闭 → `WRONG_STATE`（`message`：“决斗暂未开放”）
2. 控制权 → `CONTROLLED_BY_AGENT` / `CONTROLLED_BY_PLAYER`
3. 自己倒下 → `CHARACTER_DEAD`；自己战斗中 → `IN_BATTLE`；自己交易中 → `IN_TRADE`
4. 自己是队员 → `NOT_PARTY_LEADER`；自己有分身队 → `ALREADY_IN_PARTY`
5. 对方存在、在线、可见 → `PLAYER_NOT_FOUND`；同图 → `PLAYER_NOT_NEARBY`
6. 不是自己、不是自己队友 → `INVALID_TARGET`
7. 对方（是队员时看他的队长）没开 `duel` → `TARGET_REFUSES`（“对方没有接受决斗”）。放在这一步之前不暴露对方的战斗、交易、队伍状态
8. 对方队伍正在战斗 → `TARGET_IN_BATTLE`；对方交易中 → `TARGET_IN_TRADE`；对方有分身队 → `TARGET_IN_PARTY`；对方（队长）倒下 → `TARGET_DEAD`（新增）
9. 频率 → `RATE_LIMITED`（带 `retry_after_seconds`）

不新增“请求”对象：原版没有等待对方答复这一步。

### 3.4 战斗推送的变化（扩展第 10 章）

- `battle_start.kind` 新取值 **`duel`**。`scene` 写地图名。`allow` 为 `{"escape": true, "capture": false}`。
- **单位号**：发起方队长 0、队员 1–4；被挑战方队长 10、队员 11–14；宠物号 = 主人号 + 5。每名参战者各收一条 `battle_start`，`you` 是自己的号（被挑战方是 10–14）。客户端已经按 `you / 10` 区分己方（`client/src/app/battle/mod.rs` `me_side`），敌方的人物单位按 10.2 带 `hp` 等字段的规则改为：**对方人物只给血量百分比**（同怪物），不泄露具体数值和 MP。
- `battle_start.duel`：`{"sides": [{"leader": "勇者小明", "members": [{"no": 0, "name": "勇者小明"}, ...]}, {"leader": "阿牛", "members": [{"no": 10, "name": "阿牛"}]}]}`，代替 `party`。
- 回合推送、`battle_progress`（`total` 是双方所有在场真人）、`battle_leave` 都照 10.14。
- `battle_end`：`result` 照旧（`win` / `lose` / `draw` / `escaped` / `forced_out`）；`rewards` 为 `null`，没有 `penalty`；新增 `duel_point: {"change": -10, "total": 90}`。
- 结束后照常推 `status_changed`（10.10），角色数值里新增 `duel_point`（见 3.5）。

### 3.5 角色数据

- `enter_world`、`status` 的角色数值加 `duel_point`（整数）。
- （第二批）`duel_ranking`（查看类，世界中）：`{"page": 1}` → `{"top": [{"rank": 1, "name": "…", "level": 80, "duel_point": 2310}], "page": 1, "pages": 7, "me": {"rank": 152, "duel_point": 100}}`，每页 10 人，同分按达到时间先后（再按名字）。强者表 NPC 打开的就是它。

### 3.6 新增错误码

- `TARGET_DEAD`：对方（或对方队长）已倒下，不能挑战。

### 3.7 agent

- `duel_challenge`、`social_settings` 里打开 `duel`：`agent-guide.md` 第 6 节**先问玩家**（会让角色进战斗、改变 DP）。
- agent 操控中的角色被挑战：照常开战（开关是玩家或 agent 自己开的）。

### 3.8 用例

`duel_basic`（开关→挑战→一方全倒→DP 写回、开关自动关）、`duel_refused`（没开开关、对方战斗中、隐身、队员发起、分身队）、`duel_escape`（免罚逃跑与扣两成）、`duel_party`（队对队，对方队员被点到看队长开关、单位号 10–14）、`duel_offline`（掉线扣 DP）、`duel_switch_reset`（重新登录开关为关）。

## 四、服务端实现要点

### 4.1 存储

- 迁移（编号以合并时为准）：`characters.duel_point integer not null default 100`。`duel` 开关只在内存（会话 / 角色在线状态）里。
- 新表 `duel_logs`：`battle_id`、开始结束时间、地图、双方成员（角色 id + 名字）、每人 DP 变化、结果。用来查刷分和申诉。

### 4.2 引擎（`server/battle`）

- 新入口 `NewDuel(id, scene, sideA, sideB []PartyMate, rnd)`：两边都是真人，复用真人队同场的指令、截止、离场机制（`party.go` 顶部注释的调用顺序不变）。
