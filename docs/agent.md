# agent 协同游玩

STAGE-139：正式客户端已提供[系统菜单与独立表单](system-menu.md)，令牌、控制权、私聊无需输入命令。

玩家可以把自己的 AI 助手（下称 agent）接入游戏：agent 用玩家发给它的令牌登录，代替玩家操作角色；玩家可以同时在线，观看 agent 在做什么、和它私聊下指令，必要时一键收回控制权。消息格式见 `docs/protocol.md` 第 9 节，本文写规则背后的考虑和界面。

**文档分工**：

- **接口**：agent 与前端客户端讲的是同一个协议，接口**只以 `docs/protocol.md` 和协议用例为准**。本文和以后给 agent 的使用说明都只引用其中的章节号，**不重复定义任何消息字段**；协议改动时，只需改那一处。
- **agent 使用说明**：只写“行为层”的内容，包括登录后的整体流程、遇到控制权变化和各类推送时该怎么做、哪些事情要先在私聊里征得玩家同意、游戏知识从哪里查。
- **以后**：协议稳定后，可以把消息定义整理成机器可读的 JSON Schema，客户端、服务端和 agent 技能都以它为准，生成代码或校验消息。

## 已确定的规则（2026-10-09）

1. **agent 自己登录**：agent 直接连接服务端，不依附于玩家的客户端，玩家下线后它也能继续玩。
2. **登录凭证是专用令牌，不是密码**：
   - 令牌由玩家在客户端生成，只在生成时显示一次，可以设有效期，可以随时吊销。
   - 令牌只能以 agent 身份登录，不能改密码、建角色、删角色，也不能生成新令牌。
   - 每个账号最多同时有 5 个有效令牌。
3. **同时在线时由 agent 操控**：agent 在世界中时，玩家只能观看、查看信息和聊天；移动、战斗、使用物品、交易、NPC 对话这类会改变角色的操作，服务端会拒绝。
4. **玩家随时可以收回控制权**：
   - 收回后，agent 变为观察方，可以随时交还给它；
   - 玩家也可以直接让 agent 下线，或者吊销它的令牌；
   - 收回时，agent 开着的自动遇敌会自动关掉（`encounter_changed` 的 `reason` 为 `control`），玩家不会再被上一位操控方留下的连场战斗锁住；控制权交还后，agent 要连场就自己重新打开。
5. **聊天分两种**：
   - 玩家和 agent 都可以以角色身份公开发言；
   - 双方之间另有一个只有彼此能看到的私聊频道，用来下指令和汇报。

## 为什么这样设计

- **服务端判断权限，不靠客户端**：每种请求都标明了类别（连接、账号、查看、聊天、操作），观察方发起“操作”类请求时由服务端拒绝。即使有人修改了客户端，也绕不过这条限制。
- **一个账号同一时间只有一个角色在世界中**：避免同一账号在不同地方同时出现两个角色，也让“谁在操控”始终只有一个答案。
- **令牌和密码分开**：令牌泄露时，只需吊销这一个令牌，账号和其他令牌都不受影响；agent 也接触不到真正的账号权限。
- **同一账号可以同时有玩家和 agent 两条连接**：这和“重复登录挤下线”并不冲突，挤下线只发生在同一身份之间，玩家挤玩家、agent 挤 agent。
- **全程可追溯**：agent 的每个操作和每次控制权变化都写入审计记录，出了问题能查清是谁做的。
- **遇敌开关跟着控制方走**：谁在操控，连场遇敌就由谁开、由谁关；控制权一转手，开关自动关掉（`reason` 为 `control`），免得新的操控方被上一位留下的连场锁住。

## 实现状态（STAGE-6）

已实现：令牌（生成、列出、吊销，每个账号最多 5 个）、`agent_login`、玩家和 agent 同时在线、控制权规则（agent 进入时接管、玩家 `take` / `release` / `kick-agent`、操控方离开时自动转移）、观察方的“操作”类请求在服务端被拒绝、私聊、审计。

世界里的玩法（移动、战斗、使用物品等）还没有做，所以目前有 `turn`（转向）、`warp`（传送）、`addpoint`（加点，STAGE-24）三个“操作”类请求和 `status`、`places` 两个“查看”类请求，让上面的规则能被完整验证；以后每加一种操作类请求，在 `protocol.Requests` 里登记类别、处理函数用 `Live.Operate` 改数据，控制权规则自动生效（见 `docs/server.md`）。

### 计划与实际活动（STAGE-119）

- **计划**：agent 用 `agent_plan` 报告目标和步骤，每次整份替换；玩家的「Agent」页显示，标题写明“agent 自报”。
- **实际活动**：服务端在处理 agent 的每个操作类请求时（不论成功还是被拒绝）记一条，和审计在同一个位置，只存在内存里（每个账号最多 200 条，服务端重启清空），实时推送给玩家，玩家进入世界时补发全部。
- **在线状态**：进入世界的响应带 `agent` 字段；agent 登录和断开时推送 `agent_status`。
- **清空的时机**：agent 下次登录时清空上一次的计划和活动；agent 断开时保留，玩家仍能看到上一次的内容。
- 消息格式见 `docs/protocol.md` 9.7。agent 每换一步都要重新发 `agent_plan`，这一条写在 `/agent.md` 的手册里（STAGE-118 的关联单）。

### 在线时长上限与参考脚本（STAGE-118）

- **在线时长**：`STONEAGE_AGENT_MAX_ONLINE_MINUTES` 设置后（默认不限），agent 登录满这么久就被断开，走令牌吊销的路径（先保存、控制权转回玩家、推送 `AGENT_TOKEN_REVOKED`）。实现在 `server/auth/online_limit.go`，由令牌到期的同一个定时器检查。
- **agent 使用手册**：服务端在 `/agent.md` 提供手册（`docs/agent-guide.md`），只写行为规则；字段一律引用 `/protocol.md` 的章节号。手册第 6 节是“先问玩家”三级表，测试保证每个操作类请求都已分级。
- **参考脚本**：`/agent-connect.py`（`docs/agent-connect.py`）只用 Python 标准库，封装握手、登录、心跳和按行收发 JSON；不自动重连，断线后由 agent 按手册决定。
- **文档更新提醒（STAGE-188）**：`hello` 返回 `docs_rev`（`protocol.md` 与 `agent-guide.md` 的内容哈希）。脚本把上次的值记在 `~/.stoneage-agent/docs-rev.json`，变了就输出 `script_docs_updated` 并附上 `/changes.md` 里新增的条目，不用玩家转发文档。`/changes.md` 的源文件是 `docs/agent-changes.md`，每次改了协议或手册都要登记一条，标题带当前的 `docs_rev`；`go test ./server/webpages` 会检查当前修订号有没有登记，没登记就失败，并打印应该写的值。
- **百科查询**：`/wiki/q` 给 agent 查静态资料，见 `docs/game-wiki.md`。

## 客户端界面

- **「Agent」页（菜单 0，按 `0` 进入，STAGE-119，详见 `docs/ui.md`「Agent 页」）**：
  - 状态：顶部写 agent 在线或离线、用的令牌和操控方；离线时计划和活动保留到它下次上线；
  - 目标与计划：agent 自己报的目标和步骤（待做、进行中、已完成），标题写明“agent 自报”，可能不准；
  - 实际活动：服务端记录的 agent 操作（成功或失败、摘要），是事实；只记 agent 发出的操作类请求，查看类和聊天类不记；
  - 生成令牌：填写备注名和有效期，生成后整串显示一次，并提示“只显示这一次，请立即交给你的 agent”；STAGE-304 起同一处还给一行 Claude Code 接入命令（`claude mcp add stoneage …`，见 `docs/mcp.md`）；
  - 令牌列表：显示备注名、到期时间、最后使用时间；
  - 吊销：输入 `revoke 编号`。
- **观察模式**：
  - 菜单栏右侧显示黄色的“agent 操控中”（战斗中写在顶部战斗信息条里，STAGE-106）；
  - 战斗中按 `Esc` 能打开游戏菜单查看背包、宠物等页面，战斗在后台继续（STAGE-182，细节见 `docs/battle-ui.md`「观察模式与托管」）；
  - 「地图」等页面照常刷新，跟随 agent 的操作变化；
  - 底部输入框里，“操作”类命令会被客户端提前拦下，并提示“agent 正在操控，输入 take 收回控制权”。
- **控制命令**：
  - `take`：收回控制权；
  - `release`：交还给 agent；
  - `kick-agent`：让 agent 下线；
  - `status`：查看当前状态（“查看”类，观察模式下也能用）；
  - `turn 方向`：转向（0–7，“操作”类，观察模式下被客户端拦下）。
  - 地图页的「本地图 NPC」表也是“查看”类（STAGE-68，协议 5.32）：玩家和 agent 都能看，agent 带着角色换地图时列表跟着换。
  - NPC 对话（STAGE-69，协议 5.33）：操控方 `talk` 之后，对话窗口（`npc_window`）推给玩家和 agent 两边连接，两边看到同一份；回应选项（`npc_choose`）是操作类，只有操控方能发；关窗（`npc_close`）是确认类，两边都能关，对方连接收到 `npc_window_closed`。
  - 商店买卖（STAGE-70，协议 5.38）：商店 NPC 的窗口是买卖菜单，agent（操控方）同样能选「买」「卖」、用 `npc_reply` 报数量；成交的背包和金币变化两边同时收到（inventory_changed / status_changed）。
  - 护士治疗（STAGE-71，协议 5.39）：护士窗口的「治疗」agent 也能选；治疗后的数值和宠物变化（status_changed / pets_changed）两边同时收到。
  - 存档点（STAGE-72，协议 5.40）：记录窗口的「记录」agent 也能选；记录后被打飞送回存档点（对 agent 带队同样生效，position_changed 两边都收到）；被打死则原地复活，不送回（STAGE-194）。
  - 宠物店（STAGE-73，协议 5.41）：菜单、卖/寄放/领取/买 agent 都能操作；宠物的变化（pets_changed）两边同时收到。
  - 传送员（STAGE-74，协议 5.42）：传送窗口的「传送」agent 也能选；位置变化（position_changed）两边同时收到。
- **令牌命令**（任何页面都能输入，「Agent」页上能看到结果）：
  - `token new [备注] [天数]`：生成令牌，备注最长 32 个字符，天数 1–365，不写取 30；原文显示在「Agent」页的红色一行里，**离开这一页就看不到了**；
  - `token list`：刷新列表（进入「Agent」页时自动刷新）；
  - `revoke 编号`：吊销列表里这个编号的令牌，正在用它的 agent 立刻下线。
- **私聊**：
  - `ag 文本`：给自己的 agent 发私聊；
  - 私聊消息在消息栏和「消息」页里显示为“agent”类型，颜色用 Magenta（洋红），以便和系统、公共、队伍等消息区分（见 `docs/ui.md` 的配色表）；
  - 自己发出的话显示为“你: 文本”，agent 的回复直接显示正文（消息类型标签已经是 agent，不再重复前缀）。服务端不会把私聊推回给发送方，所以“你: …”由客户端在 `agent_say` 成功之后自己写入；发送失败（如 `PEER_OFFLINE`）只显示错误。

## agent 这一侧需要什么

agent 是玩家自己选用的程序，比如基于 Claude 的助手。它直接讲 `docs/protocol.md` 定义的协议。我们要为它提供：

1. **协议文档和协议用例**：`docs/protocol.md` 与 `docs/protocol/cases/`。这和交付给前端的是同一份，没有 agent 专用版。用例是“发什么、回什么”的具体示例，agent 可以照着学。
2. **agent 使用说明**（以后编写）：只写行为层的内容，见本文开头的“文档分工”。消息格式一律引用 `docs/protocol.md`。这份说明可以整理成 Claude Code 等工具能直接加载的技能。
3. **游戏知识**：地图、NPC、任务、宠物等资料可以从石器百科（`internal/gamewiki`）的数据中提供。

## 待定事项

- agent 的操作频率上限：目前和普通玩家一样（STAGE-118 决定不另设）；在线时长上限已实现，见上文 STAGE-118 一节。
- 哪些高风险操作即使由 agent 操控，也必须先经玩家在私聊中确认，例如交易、丢弃或卖出贵重物品。这要等交易等功能设计时一并决定。
- 其他玩家能否看出某个角色当前由 agent 操控，比如在名字旁加标记。这属于游戏公平性方面的产品决定。
