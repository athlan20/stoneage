## 世界图的依据

原版创建角色、选择出生地时的背景就是一整张世界地图：`assets/original/bitmaps/bitmap_9125.png`（640×480）。图上有两座大岛和右上角一个小岛，四个出生村用红点标出。

客户端不直接显示这张图片，而是用服务端地图数据重新生成海岸线，再按这张图的布局拼起来。这样形状更精确，也符合 demo 的风格。

## 数据格式

### LS2MAP 地图文件

数值都是大端，文件大小正好等于 `44 + 4·w·h`：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 6 | 魔数 `LS2MAP` |
| 6 | 2 | floor 编号（u16） |
| 8 | 32 | 地图名，GBK 编码，`\0` 结尾；部分地图名后带 `|0` 之类的后缀，显示时去掉 `|` 及其后的内容 |
| 40 | 2 | 宽 w（u16） |
| 42 | 2 | 高 h（u16） |
| 44 | 2·w·h | 地面层，u16，按行存储，下标为 `y*w + x` |
| 44+2·w·h | 2·w·h | 物件层，u16，画海岸线时不用 |

- **海的判定**：地面层编号为 193、194、195、196（四种海面贴图）或 0 的格子是海，其余都算陆地。萨伊那斯中部的湖也用海面贴图，会显示成镂空，和原图一致。
- **坐标方向**：x 向东，y 向南。原图就是正上方俯视，格子坐标和图上位置直接成比例，没有斜视角旋转。
- **边缘杂点**：加鲁卡最后一行（y=1199）有 47 个零散的非海格子，生成海岸线时要剔除，否则图底会多出一排杂点。萨伊那斯的陆地范围是 x 11–775、y 25–787，没有这个问题。

### 传送关系

- `data/map/mapwarp.txt`，共 2981 行，格式为 `NONE:NULL:源floor,x,y:目标floor,x,y:NULL`，表示踩到源坐标就传送到目标坐标。
- `data/npc/**/*.create` 里的 `enemy=npcgen_warp|目标floor|x|y` 也是传送点，源坐标是同一块定义里的 `floorid` 和 `borncorner`。
- 三座主岛（100、200、300）之间在这两类数据里都没有直接连接，应该是靠船或 NPC 对话传送过去的，具体是哪个 NPC 还没查到。

## 世界坐标

世界坐标以格为单位，原点是原图左上角：

```text
世界坐标 = 岛偏移 + 岛内格子坐标(x, y)
原图像素 = 世界坐标 × 0.2121
```

| 岛 | 偏移（世界格） | 偏移（原图像素） |
|---|---|---|
| 100 萨伊那斯 | (142, 198) | (30.2, 42.0) |
| 200 加鲁卡 | (669, 753) | (141.8, 159.8) |

这些数值是用四个出生村对齐求出来的：每个村的入口格子取自 `mapwarp.txt`，红点像素位置是在原图上目测的。拟合方式是两座岛共用一个缩放系数，每座岛各自求偏移，误差都在 4 像素以内（约 19 格）：

| 村庄 | 入口格子 | 换算到原图（像素） | 原图红点（像素） |
|---|---|---|---|
| 1000 萨姆吉尔村 | 100 岛 (710, 487) | (181, 145) | (180, 143) |
| 2000 玛丽娜丝渔村 | 100 岛 (113, 663) | (54, 183) | (55, 185) |
| 3000 加加村 | 200 岛 (588, 318) | (267, 227) | (271, 231) |
| 4000 卡鲁它那村 | 200 岛 (300, 641) | (205, 296) | (201, 292) |

按这些参数拼出来的图，岛的形状、中部的湖、西南角的半岛都和原图一致。想更精确的话，可以用程序从 `bitmap_9125.png` 里找出红点的中心，再重新拟合。

## 渲染规则

- **控件**：使用 `Canvas`。开启 `--unicode` 时用 `Marker::Braille`，关闭时退回 `Marker::Dot`，和 demo 的 `enhanced_graphics` 开关一样。
- **配色**（只用 16 色具名颜色）：
  - 海岸线和陆地：白色，对应 demo 里的 `Map`。
  - 出生村：黄色 `X` 加村名，对应原图的红点。
  - 玩家：绿色 `@`。
  - 选中的目的地（如果以后做移动）：用黄色 `canvas::Line` 和玩家连起来，对应 demo 里服务器之间的连线。
- **y 轴要翻转**：ratatui 的 `Canvas` 是 y 向上，世界坐标是 y 向南，画的时候要用 `-y`，或者把 `y_bounds` 反过来设。
- **保持比例**：`x_bounds`/`y_bounds` 取两座岛陆地范围的外接框，再留一点边距。一个盲文字符是 2×4 个点，终端字符大约宽 1、高 2，所以每个点基本是正方形。画布区域的“列数×2 : 行数×4”要和外接框的宽高比一致，多出来的地方留白，否则岛会被拉伸变形。
- **清晰度**：常见终端尺寸下，一个点大约代表 10–15 格。玩家走十几步，`@` 才会移动一个点，只适合看大致方位。
- **面板标题**：写当前所在地图的名字和坐标，例如 `萨姆吉尔村 (1000) 121,111`。地图名取自 LS2MAP 文件头。

## 玩家位置

玩家的位置来自服务端的 `floor, x, y`。

1. floor 是 100 或 200：直接按“岛偏移 + (x, y)”标出。
2. 其他 floor（村庄、室内、洞窟等）：沿传送关系（`mapwarp.txt` 加上 `npcgen_warp`）反向广度优先搜索，找到第一个能到达 100 或 200 的入口，把 `@` 标在这个入口在岛上的位置。面板标题仍然写玩家实际所在的地图名。
3. 找不到入口的 floor（吉鲁岛、波拉岛、部分剧情地图等）：图上不标 `@`，只在标题里写地图名和坐标，处理方式见“待定事项”。

“floor → 岛上入口”的对照表应该离线生成，不要在客户端运行时去查这几千条传送记录。

## 生成方式

不要在客户端运行时解析 LS2MAP 文件：单个文件 1.4–3.8 MB，而且服务端数据不随客户端发布。做法是写一个离线工具，读取 `gmsv/data/map` 和 `gmsv/data/npc`，生成：

- 两座岛的陆地点阵或海岸线（降采样到画布能用的精度即可）；
- 岛偏移与缩放系数；
- floor → 岛上入口坐标的对照表；
- floor → 地图名（转成 UTF-8）的对照表。

这些都是生成文件，可以编译进客户端，不受代码行数限制；游戏数据变了就重新生成。中间产物放在 `build/`。

## 快捷传送目录（STAGE-161）

**说人话**：目录是一棵审核过的树，玩家从岛屿一路选到具体楼层，服务端只认这棵树里的地图。

- **权威数据**：`server/gamedata/travel_catalog.json`（人工审定）→ `tools/build-travel-catalog.py` → `server/gamedata/travel_catalog_gen.go`（运行表 + 落点表 + 版本号）。脚本同时产出审核报告 `build/travel-catalog-report.md`（覆盖数、排除理由、每个落点的来源）。
- **盘点口径**：扫描 `gmsv/data/map/**` 全部 LS2MAP 文件头，按 floor 唯一计 696 张（4 个 floor 有两份文件，报告里单列）。其中正式 684 张、排除 12 张，待审核 0 张。
- **排除项**：777（地图名就是“测试用地图”）、501/516–522（地图名是 `aabbccddee`/`abc`/纯编号的占位图）、999/5561/5581（整图地面层全是海面或空白，没有可站立格，是坐船/剧情过场用的海域）。理由逐条写在 `travel_catalog.json` 的 `excluded` 里。
- **层级**：根是岛屿/大区（萨伊那斯 100、加鲁卡 200、吉鲁岛 300、沙姆岛 400、波拉岛 5540、五十年前波拉岛 500），另有天空之岛、家族与竞技场、活动与社交、猜谜三兄弟的家、伊甸园波拉几个根分组。往下是村庄/地区、建筑/洞窟分组、具体楼层。地图节点本身也能有子节点（萨伊那斯 → 萨姆吉尔村 → 村长家）。
- **1级宠物入口**（STAGE-251）：快捷传送根层末尾的「1级宠物」不属于这棵包含树（它不是地图，没有节点编号），只是同一页根层的另一个入口，目录口径见下文「1 级宠物目录」。
- **纯分组**：没有地图编号的中间层（“洞窟与通路”这类），只用来分层，不能传送。
- **落点**：每张正式地图都要有一个，取值顺序是 ① 清单里显式指定 → ② `mapwarp.txt` 里作为目标的第一条 → ③ 同一文件里作为源的第一条（玩家从这张图走出去的位置，必然可站）→ ④ NPC 脚本的 `borncorner` → ⑤ 从地图中心向外螺旋找第一个非海格。②–⑤ 都要求边界合法且地面层不是海（193–196 与 0 是海面/空白）；当前 684 张里 591 张沿用原版目标、49 张用源坐标、44 张靠地图数据扫描。
- **校验**（生成阶段就挡）：未登记地图、重复登记、父节点不存在、成环、孤儿、落点缺失或越界、正式与排除集合重叠、覆盖不完整，任何一条不过就以非 0 退出，不会生成运行表。
- **一致性**：目录里的地图节点集合与 `maps` 平面表的 floor 集合完全相等；客户端和 NPC 可达判断都读同一份目录。
- **改地图之后**：新增地图必须先在 `travel_catalog.json` 里登记（formal 或 excluded），否则生成失败——测试图不会被自动放进玩家目录。

## 地图页方案（主界面第 1 页）

主界面只有这一张世界地图，**没有走路和寻路**：想去哪里，直接打命令传送。因此「1 地图」页分两步做，每步一个需求：

| 步 | 内容 | 协议改动 |
|---|---|---|
| A（STAGE-20） | **只读显示**：世界地图 + 玩家 `@` + 右侧位置面板（本节详述） | 无，用现有的 `enter_world` / `position_changed` |
| B（STAGE-22） | **命令传送**：右侧列出可去的地点，`warp 编号` 直接传送过去 | 新增地点列表和传送请求。STAGE-40 起地点分两组：四个出生村在村内地图上（按入口对照表标在村的入口）、四个野外练级点在大岛上（站在遇敌区域里，开遇敌开关就能打） |

走路、`goto`、寻路、可行走数据一律不做（原 STAGE-21 已取消）。

### A：只读显示

**页面布局**（中间区域，宽度 ≥ 100 列时）：

```text
┌世界地图 · 萨姆吉尔村 (1000) 121,111────────────────────────────────────┐
│                                         ┌当前位置────────────────┐│
│   （Canvas：海岸线、地点 X、玩家 @）    │ 所在  萨伊那斯岛       ││
│                                         │ 石币  1000000          ││
│                                         │ 遇敌  关               ││
│                                         │       （入口位置）     ││
│                                         │ @ 你  X 地点           ││
│                                         └────────────────────────┘│
└──────────────────────────────────────────────────────────────────┘
```

- **左**：`Min` 宽度的 `Canvas`（不再单独套边框，外层标题已写地图名和坐标），复用 `client/src/ui/worldmap.rs` 的 `draw`（创建角色选出生地用的同一张图），给它加一个可选的玩家参数。图上的黄色 `X编号` 是服务端地点表里的地点，编号就是 `warp` 的参数（STAGE-81 去掉了右侧的「地点」表）。
- **右**：固定 34 列的「当前位置」面板（“（入口位置）”单独占一行，避免撑出边框）（`Paragraph`），写所在岛、石币和遇敌开关（STAGE-40，开时绿色显示“开（自动战斗中）”）。地图名、编号和精确坐标由页面标题给出（如 `世界地图 · 萨姆吉尔村 (1000) 121,111`）；STAGE-81 去掉了面板里和标题重复的「地图、编号、坐标、朝向」4 行，朝向整页不再显示。原因：一个点约 10–15 格，`@` 要走十几步才动一下，精确位置必须用文字给出。
- 窗口宽度不足 100 列（内容区 98 列）时不画右侧面板，只留地图，坐标仍在面板标题里。
- HP/MP 已经在菜单栏右上角显示，这一页不再重复画进度条（现在占位页里的两条 `Gauge` 随占位页一起删除）。

**玩家 `@` 怎么定位**（沿用上文“玩家位置”三条规则）：
1. floor 是 100 或 200：按“岛偏移 + (x, y)”直接标。
2. 其他 floor：查离线生成的 `FLOOR_ENTRANCE` 表，标在入口所在岛的位置；面板里“所在”写 `萨伊那斯岛`，并在坐标旁标注“（入口位置）”，避免玩家以为 `@` 就是精确位置。
3. 表里没有的 floor：不画 `@`，面板的“所在”写“地图外”，其余信息照常显示。

**离线数据**：扩展 `tools/gen-worldmap.py`，再生成一个 `client/src/ui/worldmap_floors.rs`（生成文件，不手改）：
- 内容是 `FLOOR_ENTRANCE: &[(floor, 岛编号, 入口 x, 入口 y)]`，按 floor 排序，客户端二分查找；
- 来源是 `mapwarp.txt` 加上 `data/npc/**/*.create` 里的 `npcgen_warp`，从 100、200 两座岛反向广度优先搜索，取离岛最近的入口；
- 不需要 floor → 地图名的表：地图名由服务端在 `position.map_name` 里给，客户端直接显示。

**一期不做**：
- 右上角小岛、吉鲁岛（300）、波拉岛（5540）不画，位置落在这些岛上时按第 3 条处理；
- 不画其他玩家、NPC、怪物；
- 地图不可缩放、不可滚动，永远是整张图。

**验收**：
1. 新建角色进入世界（村长之家 1006 等），`@` 出现在对应出生村附近，面板显示“所在：萨伊那斯岛（入口位置）”；
2. floor 100 / 200 上的角色，`@` 随 `position_changed` 实时移动；
3. 不在表里的 floor 不画 `@`，不报错；
4. `--unicode false` 时退回 `Marker::Dot`，界面仍可读；
5. 80×24 到 200×60 之间任意尺寸，图不变形、不越界；
6. 单元测试覆盖：入口表的搜索结果（四个出生村的室内 floor 都能查到）、`@` 的三种定位、不同尺寸下的渲染；模拟服务端加一个“角色在 floor 100 / 室内 / 地图外”的场景。

### B：命令传送（STAGE-22，已实现）

- **用法**：输入 `warp 3` 或 `warp 加加村` 就直接传送过去，中间没有任何移动过程；名字可以只写唯一的一段（`warp 萨姆吉尔`）。传送免费，不扣石币。
- **任意正式地图**（STAGE-82，STAGE-161 收紧准入）：纯数字不是地点编号时当地图编号（floor），`warp 1006` 直接去村长家。能传的只有**快捷传送目录里的正式地图**（684 张，见下文“快捷传送目录”）；落点由服务端给，来源见 `build/travel-catalog-report.md`。地图编号在 `status` 的位置里能看到；目录外的地图（测试图 777、占位图 501/516–522、整图是海面的 999/5561/5581 等）回复“地图 X 不在快捷传送目录里”。地图名也能搜索（STAGE-83）：进入世界时客户端取一次地图表（`docs/protocol.md` 5.42），`warp 村长` 能找到“萨姆吉尔的村长家”；名字先找地点，再找地图，只有一个能对上才传送，同名的地图（如几张“迷宫”）要写编号。编号或名字不对只在消息栏提示（编号不对时提示“地图上的 X 标记就是地点编号”，名字不对时把现有地点列出来），位置不变。agent 在操控时，玩家的 `warp` 和其他操作类命令一样被拦下。
- **页面**：STAGE-161 起菜单第 1 页是**快捷传送目录**（`docs/ui.md`「快捷传送页」），按岛屿 → 村庄/地区 → 建筑/洞窟 → 楼层逐级选择，选定就直达；原本画在这一页的世界地图不再绘制。地点编号仍是 `warp` 的参数，世界图数据（`ui/worldmap*.rs`、`FLOOR_ENTRANCE`）保留给出生地选择页和以后的主界面复用。
- **地点表由服务端维护**：进入世界后客户端发一次 `places` 取列表（编号、名字、floor、x、y），`warp` 只带编号，服务端改位置并推送 `position_changed`，协议见 `docs/protocol.md` 5.15、5.16。客户端按 floor/x/y 自己换算世界图位置和所在岛，不带任何地图数据，地点增删只改服务端 `server/gamedata/places.go`。
- **一期地点**：四个出生村在大岛上的入口，坐标见上文“世界坐标”的对照表。传送后角色站在岛上（floor 100 / 200），`@` 就是精确位置。
- **主岛之间怎么来往**：各岛的地点都直接标在世界图上，传送即可，不再需要查船或 NPC。
- **暂不限制**：游戏里还没有战斗、交易，也没有传送冷却；做这些玩法时再决定“战斗中、交易中不能传送”和频率限制。
- **验收**：`warp` 能传到每个地点，位置、地图名、`@` 都对；编号或地点名不存在时有明确提示；玩家和 agent 两端都收到位置更新；agent 操控期间玩家 `warp` 被拒绝。对应检查见 `docs/smoke.md`。

### C：找 NPC（STAGE-68，已实现）

- **页面**：窗口 ≥ 100 列时，右侧「当前位置」面板下方是「本地图 NPC」`Table`（编号、名字、类型，黄色表头），标题里带总数（如「本地图 NPC（34）」）；这张地图上没有 NPC 时显示“这里没有 NPC”。NPC 表拿右栏剩下的全部高度（STAGE-81 去掉地点表后，右栏只有「当前位置 + 本地图 NPC」两块，最小可用的窗口里也看得见）。
- **数据在服务端**：`tools/gen-npcs.py` 把原版 NPC 创建文件（GBK）转成 `server/gamedata/npcs.tsv`，只收录已实现和接下来要实现的类型（对话、告示牌、商店、护士、存档点、宠物店、传送员，STAGE-69 起再加报时、摆设），任务、事件、赌博等以后增量补。进入世界后客户端发一次 `npcs` 取当前地图的列表，换地图（`position_changed` 里 floor 变了）就重取，协议见 `docs/protocol.md` 5.32。任务脚本可能把 NPC 移到别的地图（STAGE-93，`docs/quest.md`「NPC 移位」），这时服务端推 `npcs_changed`（5.46），客户端用推送的列表替换，不用重取。NPC 编号全表唯一，以后的 NPC 交互命令（对话、买卖等）沿用。
- **本期没有走路**：坐标只是出生区域的中心，用来展示和以后做地图用，不要求站在 NPC 旁边。

- **验收**：四个出生村能看到商店、存档点、告示牌等 NPC（名字不乱码）；没有 NPC 的地图显示“这里没有 NPC”；玩家和 agent 两端都能查看。对应检查见 `docs/smoke.md`。

### D：精简右侧面板（STAGE-81，已实现）
