# 主界面（一期）

场景页使用四列（STAGE-152 为三列，STAGE-273 在 NPC 与遇敌之间加了附近玩家列）：第一列为当前地图普通出口，末尾保留“传送到其他地点 / 查找并直接对话 / 回城”；第二列为本图 NPC；第三列为附近玩家（见下「附近玩家列」）；第四列为本图的遇敌区域。默认第一列，←→ 在四列间切换、到边界停住，↑↓、Home/End、PgUp/PgDn 只导航当前列，四列各自保存选择和滚动位置。Enter 对出口直接通过（不二次确认）、对 NPC 沿用直接对话、对可用区域弹出「遇敌 1 次 / 无限遇敌 / 取消」（默认「遇敌 1 次」）；固定地点的原有流程仍保留。普通字母不输入，/ 命令、Esc 菜单及弹窗优先级保持。

出口显示目标名、代表触发坐标、格数、时段和单程标记。关闭或冲突的门仍显示，Enter 只说明原因。Tab 打开完整名字、所有触发格和不可用原因，↑↓/翻页阅读、Tab/Esc 返回；F5 重查焦点列。加载、失败可重试与确实为空分别显示，占位和分隔线不能执行。焦点标题带 * 且加粗，选中行带指示符，Unicode 关闭时改用 ASCII 指示符。80×24 保证两列、固定入口和完整信息入口可达。

**遇敌列（STAGE-152）**：只列本图真正可选的区域——有生效范围、能抽出敌人、CEP 上限不为 0；被高优先级安全区完全盖住的不列。行显示「区域 #编号」、主要敌人与等级、最多几只；暂时受道具条件限制的区域保留并标 `[禁]`，Enter 只说明原因。能遇到 1 级宠物（抓宠点）的区域行首加标记：unicode 下 `◆ `，`--unicode false` 时 `[宠] `，黄色（队员灰显时跟着变灰），行尾不加字；Tab 详情多一行「1级宠物：A、B」，道具挡住的区域补「（持有指定道具后可抓）」（STAGE-286）。Tab 打开完整详情：地图、原始矩形、代表落点、全部候选敌人与各自等级区间、每场人数范围、缺什么道具。加载、失败可重试与「本地图没有可遇敌区域」分别显示，不能把空图误报成加载失败。选中可用区域后立即定位并开第一场，不二次确认；「无限遇敌」持续到手动停止或自动停止，**不会顺带打开自动战斗**。停止遇敌另有固定入口，当前这场照常打完。战斗中停止自动挂机也会联动停止后续遇敌（STAGE-153，单向）：开始挂机不打开遇敌、也不改这里的次数与无限模式。加载时机：进世界、换地图（含重连刷新）时与出口、NPC 一起拉取，不需要先把光标移到这一列（STAGE-160；此前是按需加载，面板常驻却一直停在「加载中…」）。

**附近玩家列（STAGE-273）**：场景页第三列，列出本图其他在线玩家（不含自己），按等级从高到低、同级按名字排。行格式「标记 名字 Lv等级」，行尾的标记：战斗中 `⚔`（`--unicode false` 为 `!`）优先，否则接受决斗的人标 `决`（`--unicode false` 为 `D`，STAGE-307）；真人队成员的行用黄色显示（STAGE-274）。名字过长截断，等级和战斗标记保留。`Tab` 打开详情，`F5` 刷新焦点列，`/players` 把焦点切到这一列并刷新。`Enter` 打开动作面板：「查看资料」可用；「邀请组队」「申请加入」「请出队伍」（STAGE-274 已实现）「交易」和「决斗」（STAGE-307：对方没开「接受决斗」「对方在战斗中」、自己在别人的队里（只有队长能发起）时灰掉并写原因；能打时 `Enter` 弹确认窗口（默认取消），问句写清对方的等级、单独或队伍，以及「不掉经验和物品；倒下丢一成决斗点数，逃跑丢两成」；确认后发 `duel_challenge`，开战由 `battle_start` 推送接管，没有答复步骤；`duel 名字` 命令同路径，`duel 名字 yes` 不问）；「交易」（STAGE-295：倒下、自己或对方战斗中、交易中、真人队中时灰掉并写原因，能做时发 `trade_invite`，窗口见 `docs/trade.md` 第五节；`/trade` 命令同路径）：不能做时灰掉并写原因（如「队伍已满（5 人）」「对方在战斗中，不能邀请」），`Enter` 只在消息栏说明，不发请求；能做时 `Enter` 直接发请求；agent 操控时灰掉并说明「agent 正在操控，输入 take 收回控制权」；「取消」关闭。三种空状态分别显示：「加载中…」「加载失败：原因 · F5 重试」「本图没有其他玩家」。进入世界、换图、重连时与出口、NPC 一起拉取，之后靠服务端 `players_changed` 增量更新。80×24 下玩家列内宽约 16 格（设计见 `docs/social-players.md` 1.3）。

进入、换图、重连刷新出口与 NPC；按服务端游戏时段到期重查出口。请求按响应 id、地图和位置/连接世代隔离；旧响应（含 A→B→A）不能覆盖当前地图。失败不冒充空列表，重连完整刷新前只读；连续 Enter 不重复使用出口。服务端返回权威位置后才换图，并停旧自动动作。数据、时段、权限、错误码见 [普通出口协议](protocol/exits.md)。

## 场景与游戏菜单（STAGE-131）

**说人话**：进游戏先看到自己在哪、这张图有哪些 NPC；按 `Esc` 打开功能菜单，选一项进去做事，再按 `Esc` 一层层退回。要打命令按 `/`。

- **场景页**（栈底）：位置、角色状态、本地图 NPC（名字、类型和到角色的距离），以及「传送到其他地点」「查找并直接对话」两个入口。`↑↓` 选，`Enter` 打开（本地图 NPC 用协议编号直接对话），`Esc` 打开游戏菜单，`/` 打开命令栏。场景不是文字输入层：普通字符不写进命令栏，也不静默触发动作。NPC 多到一屏放不下时列表跟着光标滚（STAGE-147，规则见「页面选择」的「滚动」）。
- **快捷传送**（STAGE-161，原名「传送到其他地点」）：从场景进入时打开的是和游戏菜单「快捷传送」**同一个**层级目录，不再另开一份只有 8 个地点的列表。
- **查找并直接对话**（STAGE-134）：打开 **NPC 目录页**——顶部是名字搜索框，`Tab` 在「全部可达 / 本地图」两个分类之间切换，`Enter` 查询（改过搜索词或分类后第一下 `Enter` 就是重查）；下面按服务端给的顺序列出候选（本图的在前，本图的标「本图」并写出距离，其余写出在哪张地图），`↑↓` 选、`PgUp`/`PgDn` 翻页、`Enter` 对选中的这一个做事。目录走服务端的 `npc_list`（`docs/protocol.md` 5.47），**不是拿精确搜索拼出来的**。
- **候选选中以后**：就在本图直接对话；在别的图上先问一句「要传送过去吗」，确认后传送过去再对话。同名 NPC 会作为**多个候选**列出来，玩家选哪个就是哪个（用它的全局编号），不会静默采用第一个。
- **回城（存档点）**：用服务端在 `enter_world` / `status` 里给的**存档点落点**（`docs/protocol.md` 5.8）传送回城；没有记录过存档点的角色，服务端给的是出生地。已经在该地图时只提示一句。
- 距离只用于显示，取切比雪夫距离（格数取 dx、dy 中较大的一个，和服务端的排序与对话距离判定一致，STAGE-263），排序和可达性都以服务端为准，客户端不做寻路。
- **游戏菜单**：`Esc` 从场景打开，列出角色、宠物、背包、任务、快捷传送、社交、消息、自动战斗、百科、系统（STAGE-162 起「社交」也开放了，里面只有「队伍」一栏；STAGE-173 加了「自动战斗」）。`↑↓` 选，`Enter` 进功能页，`Esc` 回场景。
- **功能页**：从菜单进入；`Esc` 退一层回菜单，栈里没有菜单层时（从场景入口直接进来的）回到场景。功能页之间仍用数字键或 `←` `→` 换页，换页只换栈顶那一层、不叠层。
- **命令栏**：非文字输入时按 `/` 打开；`Enter` 执行，命令成功收起、未知命令留在栏内报错；`Esc` 收起并保留草稿。

## 快捷传送页（菜单 1，STAGE-161）

**说人话**：想直接去某张图，就从最大的岛屿一路选下去——岛屿、村庄、村长家；选中就过去，不用记地图编号。

- **层级**：从岛屿/大区开始（萨伊那斯、加鲁卡、吉鲁岛、沙姆岛、波拉岛、五十年前波拉岛，另有天空之岛、家族与竞技场、活动与社交、猜谜三兄弟的家、伊甸园波拉几个根分组），逐级进入村庄或地区、建筑或洞窟、具体楼层。层数随真实包含关系变化，不强行拉平。
- **有下级的地图**：`Enter` 进入下一级；下一级的**首项**是「传送到本图 · 地图名」，其余是它的下级。所以岛屿本身、村庄本身都能作为目的地。
- **没有下级的地图**：`Enter` 直接传送。**纯分组**（洞窟与通路这类没有地图编号的层）不能传送，名字后面带 `›` 表示还能往里走。
- **每行右侧**是地图编号（纯分组没有），**行尾**「← 当前」标出角色现在所在地图。选中当前地图时只提示「已经在这里」，不发传送请求。
- **标题**写当前路径（`快捷传送 › 萨伊那斯 › 萨姆吉尔村`）和这一层的项数；底边写 `光标 / 总数`。宽屏（内容区 ≥ 88 列）右侧多一块「目的地」详情：名字、地图编号、下级数量、是否已经在这里、目录版本。
- **按键**：`↑↓` 选，`Enter` 下钻/传送，`Esc` 逐级返回，根层再 `Esc` 退出页面；`Home`/`End` 到首尾，`PgUp`/`PgDn` 翻一屏。每层各记光标和滚动位置，退回来时停在原来那一项。普通字符不抢页面按键，要打命令按 `/`。
- **成功后回场景页**，消息栏写「已传送到 X」，位置以服务端推送的 `position_changed` 为准。失败留在原目录并保留选择，消息栏写原因；传送在途时再按 `Enter` 不会重复发送。
- **目录不可用**（原版服务端不返回节点树，或者查询失败）：整页显示原因和「`Enter` 重新获取」，不退回用平面表冒充全地图。
- **窄屏**（80×24）：只有列表，长名字按终端宽度截断，光标始终可见。
- `/warp 地图名`、`/warp 编号`、Tab 补全继续可用，全部按服务端给的正式地图集合工作。

### 根层的「1级宠物」（STAGE-251）

**说人话**：想遇某只 1 级宠物，但不知道去哪找，就从这里按宠物找：列出能在野外遇到的 1 级宠物，选中看它的遇敌点，选定就传送过去开战。

- **入口**：快捷传送根层末尾固定一项「1级宠物」，不是地图，不在地图包含树里（没有地图节点，行尾没有「← 当前」）。它不依赖地图目录，目录加载中或不可用时也在，能进去。选中它打开宠物目录；目录还没取过就发一次 `pet_encounter_catalog`（`docs/protocol.md` 5.62），之后用缓存。
- **三层**（`Enter` 下一层，`Esc` 退一层）：
  - **L1 宠物列表**：标题 `1级宠物 · N 只`（有筛选词时 `1级宠物 · 筛选“词” · N 只`）。每行左边是 `名字（俗称 · 系列）`，没有俗称或系列就只写名字；右边是最强的属性和数值加可遇点数（如 `风 100 · 3处`，四项全为 0 写 `—`）。顺序是服务端给的拼音序，没有可遇点的宠物不列。
  - **L2 遇敌点**：标题 `宠物名 · N 个遇敌点`。每行左边是地图名和落点坐标（如 `萨姆吉尔村 (x,y)`，同一只宠物有同名地图时补 `· 楼层`），右边是区域原编号、同场上限，同点还有别的 1 级宠物时带上它们的名字。
  - **L3 动作**：标题 `宠物名 · 地图名（x,y）`，四项：`直接开战`（once）、`连续遇敌`（infinite）、`只传送不遇敌`（travel）、`取消`（回到 L2，不做任何事）。
- **筛选框**：L1 第一行。`/` 或 `f` 把焦点交给框（只在 L1 有效；L2/L3 里 `f` 不起作用，`/` 照常打开命令栏）。框里的字符都进框，列表立即按词过滤，光标回到第一条。匹配名字、俗称和系列，不区分大小写和全半角，多个词用空格分开、每个词都要命中一项（如 `人龙` 命中人龙系，`蓝 人龙` 只命中蓝人龙）。框拿着焦点时 `↑↓` 仍能移动列表。
  - `Enter`：应用筛选，焦点回到列表，停在第一条命中。
  - `Esc`：有字就先清空，没字就只把焦点交回列表。
  - `Backspace`：只删一个字符，框空了也不退出。
  - 没有命中时列表写「没有匹配的宠物 · Esc 清空筛选」。
- **右侧详情**（内容区去掉边框后 ≥ 88 列，右栏标题「详情」）：L1 是选中宠物的名字、四项属性、体型与捕捉难度、俗称、系列、可遇点数；L2/L3 是选中遇敌点的地图名（楼层）、区域号、矩形范围、落点、同场上限和约多少格一场、同点其他 1 级宠。**候选敌群构成（这个区域会出现哪些敌人及等级）暂未显示。**
- **窄屏**（内容区不到 88 列，如 80×24）：只有列表，没有详情。L2 的地图名、坐标、区域和上限都写在行上，L3 的地图名和坐标写在标题里。
- **按键**（焦点在列表时）：`↑↓` 选，`Home`/`End` 到首尾，`PgUp`/`PgDn` 翻一屏（一屏行数按列表高度算）。`Enter` 进入下一层或执行 L3 的动作。`Esc` 先看有没有筛选词：L1 有筛选词就先清空，否则退一层；L1 没有筛选词时 `Esc` 离开目录，回到快捷传送根层。`Backspace` 在列表焦点时和 `Esc` 一样；在筛选框里只删字符。
- **记住位置**：L1、L2、L3 各记自己的光标和滚动位置，退回来时停在原来那一项。筛选词只在 L1 保留，离开宠物目录时清空。
- **开战与传送**：L3 选一项发 `pet_encounter_start`（`docs/protocol.md` 5.63），`mode` 为 `once` / `infinite` / `travel`。在途时不再发第二条。角色已经在这个遇敌点的区域里（同一张图且坐标在矩形内）时，只在消息栏写「已经在这里：地图名」，不发请求，留在目录。
  - 成功：离开目录、回场景。开战（once 或 infinite）写「已传送到 X，开始遇敌」，只传送写「已传送到 X」，X 是遇敌点所在地图名。位置以服务端推送的 `position_changed` 为准。
  - 失败（例如服务端回 `PET_ENCOUNTER_NOT_FOUND`）：留在 L3，消息栏写服务端给的原因，可以换一项再选。
- **目录取不到**：L1 第一行写「目录加载中…」，或「目录不可用：原因（Enter 重试）」；`Enter` 重新取一次。列表为空时写「没有可以显示的宠物」，遇敌点为空时写「这只宠物没有遇敌点」（正常目录里不会出现，目录只收有遇敌点的宠物）。
- **输入行提示**：目前沿用快捷传送页的通用提示（`hint.rs` 里没有单独的宠物目录分支），以代码为准。

### 根层的「练级传送」（STAGE-279）

- **入口**：快捷传送根层「1级宠物」之下（末尾）的固定一项「练级传送」，与「1级宠物」并列，互不影响。同样不依赖地图目录，目录不可用时也能进。
- **L1 等级段**：标题 `练级传送 · 13 段`。13 行，每行左侧 `1-10 级`，右侧 `条目数 · 涉及地图数`（如 `63 个点 · 39 图`）。光标默认落在玩家当前等级所在段；空段照样列出。第一次进入时取 `leveling_catalog`（`{}`，只取摘要），选中段时再取该段（`{"segment": N}`），之后用缓存。
- **L2 练级点**：标题 `11-20 级 · 63 个点`。每行左侧是怪物名加段内等级（`乌卡鲁 11-12、乌宝宝 11-12、威威 11-12`；超过 3 种写前 3 种加“等 N 种”），右侧是落点数（`14 处`）。空段在列表区写「本段没有野外遇敌点」，`Esc` 返回 L1。条目只列本段的怪；该区域的敌群里若还有相邻等级段的怪，开战时会混入，不在条目上显示（见 `docs/map.md`「练级传送目录」）。
- **L3 落点**：只有一个落点时跳过这一层，直接进 L4。多个落点时列出 `地图名 (x,y)` 加区域号、同场上限、约多少格一场。
- **L4 动作**：`直接开战` / `连续遇敌` / `只传送不遇敌` / `取消`，语义与「1级宠物」完全相同（`once` / `infinite` / `travel`）。
- **右侧详情**（内容区 ≥ 88 列）：选中练级点的全部怪物及段内等级、其余落点、区域矩形、约多少格一场。窄屏（80×24）只有列表，地图名与坐标写在行上。
- **按键、记忆光标、传送成功回场景并写消息栏、失败留在原层显示服务端原因**，全部沿用「1级宠物」目录的实现（同一套三层骨架加动作层），不另造一套。
- **输入行提示**：同快捷传送页的通用提示。

## 页面选择（方向键，STAGE-112）

**说人话**：不用记命令也能逛。输入行为空、没有弹窗和战斗时，`←` `→` 换菜单页，`↑` `↓` 在页面的列表里挑，挑中哪个右边就显示哪个；`Tab` 换到页面的另一栏；`Enter` 看得见的直接打开，要改数据的只把命令填进输入行，再按一次 `Enter` 才执行。

## 背包对象动作（STAGE-132）

**说人话**：选中一样东西，回车，直接选「装备、使用、移动、丢弃」，不用看英文命令。背包是整次改版的第一个完整样板。

- **动作列表**：按选中格给出。装备格（0–4）是「卸下、说明」；背包格（5–19）里能穿的给「装备」、能用的给「使用」，都会带上「移动、丢弃、说明」。做不了的动作仍然显示，后面用灰字解释原因（例如「数量不是 1，先拆开再装备」）。`↑↓` 选，`Enter` 执行，`Esc` 回背包页。
- **装备 / 卸下**：选完直接提交，不再多问一次。
- **使用**：先按协议给的目标类型选目标——只能对自己用（`self`）、己方全体（`ally_all`）的直接提交；己方一个（`ally`）列出自己和宠物让玩家选；倒下的己方（`ally_down`）只列倒下的宠物；敌人（`enemy`）在非战斗时给出「只能对敌人用，战斗中才能用」。
- **移动**：目的格用 5 列 × 3 行的网格铺出 5–19 全部背包格，「◆」表示那一格有东西（交换），「·」是空格（可以直接放进去）。当前格灰掉不可选，选中它会说明原因。
- **丢弃**：先进入数量表单（1–持有数以内的整数），`Enter` 进入确认；数量填错留在表单里解释，`Esc` 取消不发任何请求。确认沿用全局的「默认取消」（消息栏问一句，输入 `y`）。
- 动作调用与 `item` 命令**同一批请求函数**（`client/src/app/items.rs`）和同一套校验，服务端仍是最终裁判。列表里已经消失的对象（被用掉、被换走）会让动作作废并退回背包页，不会把操作套到别的物品上。

### 精工（STAGE-299，设计见 `docs/inlay.md` 2.8）

**说人话**：背包里有可镶的武器或防具（物品带 `inlay` 字段）时，动作列表多一项「精工」；现有数据下没有这一项。

- **入口**：目标是 `inlay.role = gear` 的格子（在背包或穿着都行），动作列表里多一项「精工」。镶满（`free = 0`）的灰掉，回车说明「已镶满，不能再精工」；agent 操控时同样灰掉。
- **选材料**：`↑↓` 选，`Space` 勾选或取消。只列背包里 `role = material` 的格子，最多勾目标剩余的空格数且不超过 3 件，勾满后再按 `Space` 只提示。标题写「已选 N/M」。`Enter` 进入确认，`Esc` 回动作列表。
- **确认**：消息栏问一句，焦点默认在「取消」，文字写「将 A、B 镶到 C 上，永久占用 N 格、可能覆盖原有精灵」。`Enter` 确认、`Esc` 取消，同其他确认（`docs/interaction.md`）。
- **命令**：`item inlay <目标格> <材料格…> [yes]`，别名 `精工`。没有 `yes` 先问，带 `yes` 直接发出。格子没有东西、材料超过 3 件、材料重复等在本地报错；类别码、镶满等由服务端判断。
- **消息栏**：全部镶上是绿色「C 镶上了 N 件材料」；镶到一半满了是黄色「镶了 N 件，其余没有镶上：武器或防具已经镶满了。」；其他失败直接显示服务端台词，也是黄色。

## 宠物对象动作与角色加点（STAGE-133）

**说人话**：宠物也像背包一样，选中一只回车，直接选「出战、待命、休息、骑乘、改名、技能、放生」；人物加点填个数字就行。

**宠物**（`client/src/app/pet_action.rs`）

- **动作列表**：选中栏位回车打开，八项——出战、待命、休息、骑乘、改名、技能、对话、放生。对话（STAGE-239）休息、骑乘中的宠物灰掉并说明（「休息中的宠物不在身边，先设为待命或出战」「骑乘中的宠物不能对话」），其余直接发请求，台词进消息栏。已经在某个状态的项灰掉并说明（「已经在出战中」「已经在待命」「已经在休息」），倒下（HP 0）的宠物「出战」写「倒下的宠物不能出战」。
- **骑乘**（STAGE-243）：标签随这只宠物的状态变，不新增第二项——没在骑写「骑乘」，骑的就是它写「下骑」。选中直接提交，成功和失败的原因都进消息栏。客户端先本地拦下（灰掉并说明，不发请求），顺序与服务端 `pet_ride` 一致：已经在骑别的（「已经在骑 N 号栏的宠物，先下骑」）；出战或待命（「出战或待命的宠物不能骑，先设为休息」）；骑乘等级为 0（「你还没有学过骑乘，先去庄园的骑乘训练师学习」）；宠物等级高于骑乘等级（「你目前只能骑乘等级小于等于 N 级的宠物」）；忠诚低于 100（「该骑宠的忠诚小于 100」）；转生超过 2 次（「转生次数超过 2 次的宠物不能骑」）。外形与种族只有服务端知道，不本地灰，由服务端拒绝并回显原因。骑乘中的宠物，出战、待命、休息灰掉并说明「骑乘中的宠物不能改状态，先下骑」，放生灰掉并说明「骑乘中的宠物不能放生，先下骑」；改名、技能照常可用。命令 `pet ride <编号>` / `pet ride off` 不变，请求函数共用。
- **面板高度**（STAGE-249）：动作面板和技能面板画在详情下面，宠物表（8 行）和详情（至少 8 行）先各留够，剩下的给面板，最少 4 行（2 行可见 + 边框）、最多 10 行（8 项 + 边框）。80×24 和 120×24 的中间区域只有 12 行，所以面板只露 2 行，动作靠 `↑↓` 滚动：第 8 项「放生」滚到就能看到并选中，灰字说明跟着它所在的行显示。宽终端或高终端（约 30 行以上）面板能露全 8 项。
- **状态类动作**直接提交；一只出战、多只待命这类上限由服务端裁定。
- **改名**：专用表单，长度上限 16 字（与服务端 `normalizePetName` 一致），进来时**预填现在的名字**，清空即恢复种族名；名字中间有空白留在表单里解释，`Esc` 取消不改名。
- **技能**（STAGE-208 起可以合成）：列表写出栏位号、名字和目标类型。光标在「加工」「料理」（技能 id 200、201）上时提示行有 `Enter 选材料`，进入合成选材料（见下一小节）；别的技能 `Enter` 只在消息栏说明（不用材料；战斗外要用它请输入 `pet skill`）。`Esc` 回动作菜单。
- **放生**：进入全局确认（消息栏问一句，默认取消），问句里写**真实的名字和栏位**。确认期间动作面板留着、光标停在「放生」：Esc（或 Enter 取消）只取消确认，消息栏写「已取消放生」，面板仍开（STAGE-256）；选「确认」后面板收掉，和以前一样。
- 请求与 `pet` 命令共用 `pets_manage.rs` 的同一批函数；宠物在流程中被放生或换走时，动作作废并退回宠物页。

**合成（STAGE-208）**（`client/src/app/pet_merge.rs`、`client/src/ui/petmerge.rs`；协议 5.55，设计见 `docs/synthesis.md`）

- **选材料**：整页列出背包 5–19 格的物品。`↑↓`、`Home`、`End`、`PgUp`、`PgDn` 移光标，`空格` 勾选或取消（`[1]` `[2]` 是勾选顺序，第一件决定是食物还是道具），最多 15 件。`Esc` 回技能列表，光标停在刚才那一项。
- **Enter**：不到 2 件，或食物与道具混在一起，只在消息栏说明，不发请求。够了进入确认。
- **确认**：全局确认，默认取消，消息栏写 `用加工合成：…（共 N 件，材料不论成败都会用掉）`；`←→` 切到确认按钮，`Enter` 确认，`Esc` 取消（不发请求）。确认后发 `pet_skill`（带 `items`）。
- **非材料**：协议没有给出“能不能合成”的字段，客户端不判断；非材料由服务端回 `ITEM_UNUSABLE`，材料不扣，留在选材料里改。
- **结果页**：成功（`created`）绿色；还料（`fallback`）和冷却（`cooldown`）黄色；食物与道具混合（`illegal`）红色。最后一行写用掉了哪些材料。`Enter` 再合成一次（回到空的选材料），`Esc` 回技能列表。
- **命令**：`pet skill <宠物> <技能栏位> <背包格号…>`，格号 5–19、2–15 件、不重复。本地先查格号和食物道具混合，通过后直接发请求，不弹确认。别的技能后面带格号时报错。

**角色**（`client/src/app/char_action.rs`）

- 焦点在能力栏时回车打开**加点表单**，填 1–未分配点数之间的整数，`Enter` 提交，`Esc` 取消（不发请求）。
- 没有未分配点数时**不开表单**，直接在消息栏说明；填错（0、超过剩余点数）留在表单里解释。
- 数值由 `status_changed` 推送更新，客户端不自己算 HP 或属性。
- 精灵栏保持只读（只在战斗中使用），`Enter` 不起作用。
- **任务**：窄屏（不到 110 列）时攻略替换列表，打开攻略后焦点就在攻略栏，`↑↓` 逐行滚动，`Esc` 回列表，焦点回到列表栏。宽屏并排时打开攻略后焦点留在列表栏，可以边选边看，`Tab` 进攻略栏滚动。切换显示范围（`quest doing` 等）时选中项落到新列表里同一个任务；那个任务不在新列表里时，落到原来位置最近的一项（同「页面选择」的一般规则）。攻略开着且并排时，列表的选中项每动一次，攻略就跟着换成这一条的（焦点在列表栏时）。
- **百科**：词条栏的选中项移到本页以外时自动翻页（等于 `wiki next`/`wiki prev`），`PgUp`/`PgDn` 跳一页。宽屏打开词条后焦点留在词条栏、详情跟着选中项换；窄屏详情替换列表，焦点到详情栏。`Esc` 等价 `wiki back`：先关词条（焦点回词条栏），再清搜索，再回分类目录（焦点回分类栏）。分类栏里当前分类仍是黄色加粗，选中项另加 `▶`。


## 社交页的队伍（STAGE-162）

**说人话**：在游戏菜单里选「社交」，没有队伍时回车一下就有一支 5 人队伍——自己当队长，另外 4 个是“当前状态的自己”的分身，一起走路、一起打架；解散队伍分身就全部消失。协议见 `docs/protocol.md` 5.57，战斗里的展示见 `docs/battle-ui.md`「分身队」。

- **入口**：游戏菜单「社交」不再灰显；进入后路径条是“场景 › 社交”，`Esc` 逐层退回。社交页只有一个栏目「队伍」（名片簿、邮件、社交开关还没做，页里不出现）。数字页号 6 作为兼容入口保留。
- **顶部状态行**：有队伍时右侧多一段绿色的“队伍 5/5”，在场景和任何页面都看得到队伍还在。
- **没有队伍**：面板里一行入口「组成分身队」（`Enter` 直接发 `party_clone`，不二次确认——无损失），下面是规则说明（`Paragraph` + `Wrap`）：会复制什么、不复制什么、分身不领奖励、解散就消失。已倒下、agent 操控中入口仍显示，但灰字并在后面写明原因；这时 `Enter` 在消息栏说明原因，不发请求。战斗中能组、能解散（STAGE-189）。
- **组队带方案**（STAGE-195）：组成分身队时客户端把当前生效的自动战斗方案一起发给服务端（`party_clone` 的 `auto_profile`），分身按它出招；响应里 `applied` 消息栏写“分身会按当前自动战斗方案出招（方案：<名字>）”，`ignored` 写“服务端不认这份自动战斗方案，分身按默认方式出招”。方案在组队时收下，之后改方案要解散重组。
- **有队伍**：带黄色表头的 `Table`（序号、名字带 `[队长]`/`[分身]` 标记、Lv、HP 迷你条加数字、MP、出战宠物），最多 5 行，队长在第一行；面板标题写“队伍 · 1 队长 + 4 分身”。迷你条的颜色同战斗血条（>50% 绿、20–50% 黄、<20% 红，倒下灰），`--unicode false` 时用 `#` 和 `-`。
- **选择与动作**：`↑↓` 选成员（按稳定编号 `index` 记，战后恢复满血、数据刷新后仍选中同一个成员；成员消失回到第一行），`Enter` 打开动作菜单（`Layer::Action`，面板画在表下面）：
  - 「查看详情」：压一层只读的 `Layer::Detail`，显示名字、等级、HP/MP、能力、衍生数值、装备、精灵、出战宠物（含技能）和位置；`↑↓` `PgUp` `PgDn` 滚动，`Esc` 回动作菜单。分身的详情标注“创建时的快照，只会普通攻击，不领奖励”。
  - 「解散队伍」：有损失，进入默认取消的确认（`解散队伍？4 个分身会立即消失`）；确认后发 `party_disband`。agent 操控中、没有队伍时保留显示并写明原因，`Enter` 不发请求。战斗中照常能解散，正在打的这一场分身打完为止。
  - 对分身不出现私聊、交易、邀请这类动作（它们不是真人）。
- **窄屏**（< 110 列）：详情不并排，只在「查看详情」那一层整页替换列表；宽屏时右边并排显示选中成员的详情。
- **命令**：`/party` 打开社交页，`/party clone` 组成分身队，`/party disband` 解散（先确认，默认取消；`/party disband yes` 直接解散），菜单和命令走同一批函数（`client/src/app/party.rs`）。未知参数留在命令栏里报错并给用法；`help`、Tab 补全里都有 `party`。
- **消息**：组成分身队、解散队伍、分身倒下、战后恢复写“队伍”类消息（Green）；失败原因（已有队伍、倒下、agent 操控中）写进消息栏，不弹模态。
- **战斗里指定分身的攻击目标**（STAGE-186）：战斗中按 `f` 打开「分身」面板，给分身和分身的宠物各指定一个敌方目标；不选的分身按合击顺序打第一个（STAGE-312）。按键、面板和命令 `clone` 见 `docs/battle-ui.md`「分身队」。
- **断线重连**：队长所有连接断开后分身已消失，重连后的 `enter_world` 带 `party: null`，界面不残留队伍，消息栏说一句“分身已随断线消失，现在没有队伍”；agent 一直在线保住了队伍时不提示。
- **观察模式**：agent 操控时社交页可以浏览、看详情；组队和解散在客户端被拦下，提示“agent 正在操控，输入 take 收回控制权”。
- 实现：`client/src/app/party.rs`（状态、推送、请求、命令）、`party_action.rs`（动作菜单与详情层）、`client/src/ui/socialpage.rs`（页面）。测试：`tests/render_social.rs`（画面与按键）、`tests/scenarios_party.rs`（模拟服务端用例 `ui_party`、`ui_party_battle`、`ui_party_agent`）。

## 社交页的真人组队与请求（STAGE-274，协议先行）

**说人话**：可以和同一张图上的玩家组队，最多 5 个真人，队长带队，队员跟着队长走。收到邀请会弹窗，默认选“拒绝”；暂时不想决定就按 `Esc`，请求会留到过期。协议见 `docs/protocol.md` 5.67，规则见 `docs/social-players.md` 第二节。

本节已实现（STAGE-274，服务端和客户端都已完成）；下面写的是现在的行为。

- **队伍栏（真人队）**：沿用分身队的 `Table`（黄色表头），列为序号、名字（队长带 `[队长]`，自己带 `[我]`）、Lv、HP 迷你条加数字、MP、出战宠物，最多 5 行，队长在第一行；面板标题写“队伍 · N/5 真人”。宽屏右侧详情只显示 5.67 里有的字段（名字、等级、HP/MP、出战宠物、位置），不显示属性和装备。
- **队员动作**（`Enter` 选中成员）：

  | 选中 | 动作 |
  |---|---|
  | 自己（非队长） | 离开队伍（默认取消的确认） |
  | 自己（队长） | 解散队伍（默认取消的确认，写明“队员都会离队”） |
  | 队员（自己是队长） | 查看详情、转让队长（默认取消的确认）、请出队伍（默认取消的确认） |
  | 队员（自己是队员） | 查看详情 |

  没有队伍时 `Enter` 打开两项：「组成分身队」（沿用）和「去邀请附近玩家」（回场景并把焦点放到附近玩家列）。
- **请求栏**（社交页第二栏「请求」）：列出收到的邀请 / 申请（可答复）和自己发出、等待答复的请求（可撤回），每条带剩余秒数（每个 tick 刷新）。`Enter` 对收到的请求打开下面的弹窗；对发出的请求给「撤回」，直接发 `party_cancel`，不二次确认。没有请求时写「没有待处理的组队请求」。
- **请求弹窗**：任意页面（场景、游戏菜单、功能页）上方弹出居中窗口；战斗中和 NPC 对话窗口里不弹，只在消息栏提示，战斗结束或关窗后若还没过期再弹。

  ```text
  ┌ 组队邀请 ───────────────────┐
  │ 阿牛 邀请你加入队伍（2/5）  │
  │ 剩余 23 秒                  │
  │       [拒绝]    [加入]      │
  └─────────────────────────────┘
  ```

  - 焦点默认在「拒绝」（默认取消）；`←→` 切按钮，`Enter` 激活；`Esc` = **稍后处理**：收起窗口，请求保留到过期，不发任何请求。
  - 申请（`apply`）的标题写“申请加入你的队伍”。
  - 同时有多条请求时排队，一次弹一条。过期自动关闭，消息栏写「阿牛的组队邀请已过期」。
  - 答复后按钮显示“处理中”，直到响应或推送到达，期间不重复发送。
- **队员灰显**（自己是队员时，灰字后面写原因「跟随队长，离队后才能自己行动」）：场景页的出口列整列、固定入口「传送到其他地点」「回城」、遇敌列；快捷传送页的“传送”动作。灰显只是提前提示，按 `Enter` 只在消息栏说明原因，不发请求；服务端回复 `PARTY_FOLLOWER` 时同样写原因。对话、买卖、用道具、背包、任务照常可用。
- **消息栏**（队伍类，Green）：阿牛邀请了你；小红加入了队伍；小红离开了队伍；小红被请出了队伍；队长换成了小红；你被请出了队伍；邀请被拒绝 / 已过期 / 已撤回。14 个组队错误码各自写中文原因（客户端 `party_error_hint`），其余错误码沿用服务端的文字。
- **命令**（与菜单共用 `client/src/app/party.rs` 的函数）：`party invite 名字`（`邀请`）、`party join 名字`（`加入`）、`party accept [名字]`（`同意`，不带名字时取最早的一条，多条时必须带名字）、`party decline [名字]`（`拒绝`）、`party leave`（`离队`，先确认，`leave yes` 直接离）、`party kick 名字`（`踢`，先确认，`kick 名字 yes` 直接踢）、`party leader 名字`（转让队长，先确认，默认取消；`leader 名字 yes` 直接转让，无别名）、`party say 文本`（别名 `队聊`，直接发到队伍，不用确认）。
- **agent 操控时**：组队动作在客户端被拦下，提示“agent 正在操控，输入 take 收回控制权”；看列表、看详情照常。

## 社交页的开关（STAGE-276，协议先行）

**说人话**：社交页第三栏「设置」有三个开关（STAGE-295 起第三个是「接收交易邀请」，默认开，关掉后别人邀请交易会被直接拒绝，协议见 5.69）。「对附近玩家可见」关掉就是隐身：别人的附近玩家列表里看不到你，你仍能看到别人，也能主动邀请和申请。「接收组队邀请」关掉后，别人邀请你会被直接拒绝，你自己的申请和主动邀请不受影响。协议见 `docs/protocol.md` 5.69，规则见 `docs/social-players.md` 第三节第 4 项。

- **位置**：社交页第三栏「设置」（队伍、请求、设置），四行：`对附近玩家可见`、`接收组队邀请`、`接收交易邀请` 和 `接受决斗`（STAGE-307，协议 5.69，`docs/pk.md` 3.1），右边写状态：开（Green）、关（Red）。前三个默认都是开；`接受决斗` 默认关、不存库，进入世界、重新登录，或打完一场决斗后自动关。第四行下面的说明写：「打完一场或重新登录后自动关闭；开着时同图的人可以直接向你发起决斗。」切换成功消息：「已开启接受决斗：同图的人可以直接向你发起决斗」「已关闭接受决斗」。命令 `duel on|off` 与设置栏同路径。
- **操作**：`↑↓` 选行，`Enter` 或空格切换，发 `social_settings`，只带被改的那个字段（如 `{"visible": false}`）。请求在途时不重复发送；成功后以响应里的 `social` 为准更新显示；失败时在消息栏写原因，显示保持原值，不弹模态。

### 宠物的数据模型（来自原版服务端）

**宠物模板**：`gmsv/data/enemybase.txt`（952 行，GBK）。每个模板有名字、地水火风、最多 7 个技能、技能栏位数（`E_T_SLOT`）、图像编号、宠物标志（`E_T_PETFLG`）、体型、等级限制（`E_T_LIMITLEVEL`），这几项的确切含义还没核对；另外还有决定能力的几个数：

| 字段 | 含义 |
|---|---|
| `E_T_INITNUM`、`E_T_LVUPPOINT` | 基础值和每级增长，能力 = ((等级 − 1) × LVUPPOINT + INITNUM) × 资质 |
| `E_T_BASEVITAL/STR/TGH/DEX` | 四项资质（体力、腕力、耐久力、速度），每只宠物生成时在模板值上随机 ±2，再随机追加 10 点 |
| `E_T_MODAI` | 忠诚计算用的系数，≤ 0 时按 100 |

**生成一只宠物**（`gmsv/char/enemy.c`，`ENEMY_createPetFromEnemyIndex` 一带）：等级定好后，用上面的公式算出体力、腕力、耐久力、速度四项能力；同时把“±2 之后、追加 10 点之前”的四项资质打包保存（`CHAR_ALLOCPOINT`），升级时按它分配成长。同一个物种的两只宠物，资质不同，长大后的强弱就不同——这是玩家养宠、挑宠的核心乐趣。

**宠物实例**要保存：物种编号、自己起的名字、等级、经验、四项能力（单位 1/100 点）、四项资质、品质等级（`CHAR_PETRANK`，0–5，升级时的成长系数随它浮动）、忠诚的可变部分（`CHAR_VARIABLEAI`）、当前 HP、状态、技能列表（最多 7 个）。

**衍生数值**：宠物和玩家用**同一个函数**（`CHAR_initcharWorkInt`）算，公式见上文“角色页”；区别只是宠物的能力以 1/100 点保存，显示时再舍去小数。

**忠诚**（`CHAR_initcharWorkInt` 里宠物分支）：
- 忠诚 = min(100, 主人等级 × 主人魅力 × 1.1 ÷ (宠物等级 × MODAI) × 100) + 可变部分 × 0.01；
- 主人转生过的，再加 (140 − 主人等级) ÷ 2；
- 结果限制在 0–100。
- 所以忠诚由服务端每次现算，不存；它随主人魅力和等级、宠物等级变化。

**状态**（原版服务端的 `CHAR_DEFAULTPET`、`SPET` 待命掩码、`CHAR_RIDEPET`）：
- **出战**：最多 1 只，战斗开始时自动上场；死亡（HP 为 0）的宠物不能出战；
- **待命**：最多 3 只，战斗中可以换上场（对应原版服务端的 `SPET` 待命掩码，具体换宠规则在战斗需求里核对）；
- **休息**：默认状态，不参战；
- **骑乘**：最多 1 只，有等级等条件，放到 E 步。
- 战斗中不能改状态。

- **成长率**（`growth`，口径见 `docs/protocol.md` 5.19）：括号里是每升一级平均涨多少，两位小数（如 `7.25`）。左列表头按口径写：`raised`（1 级起养）写“基础属性（成长/级）”；`caught`（捕获时已有等级）写“基础属性（成长/级，自 Lv5 起）”，只统计到手之后的升级；`unknown`（历史宠物，没有起始记录，不倒推）和原版服务端没有这个字段时写“基础属性（成长：无记录）”。**`—` 的含义**：算不出，即没有记录，或刚获得、还没升过级（现在的等级不高于起始等级）；不是 0。
- **隐藏素质（五档）**（`quality`）：只显示素质点和档位，不显示模板资质。档位是这项素质距离满值的差：0 写“满”（绿色），−1 到 −4 写 `−1`…`−4`（黄色；`--unicode false` 时减号用 ASCII 的 `-`）。没有这个字段时四项都写 `—`。
- **80×24**：详情区域 44 列 × 12 行（含边框），内容 10 行（底部消息栏占 9 行，中间区域 12 行），汇总行放得下。**动作面板打开时**（STAGE-249）中间区域只剩 12 行，面板占 4 行，详情内容只剩 6 行：**表头、HP 与四项属性、两行汇总（总成长、总掉档）必留**，昵称（名字、种族、忠诚）、技能栏、等级、地水火风让位，技能栏在这时省略（一期定的取舍，面板关闭后恢复）；省略时详情的下边框写一句提示「技能栏放不下，关闭动作菜单后查看」（STAGE-256，写在边框上，不占内容行，宽度不够就 `…` 省略；技能栏放得下、面板关闭时不写）。面板是 2 行可见，宠物表只露一部分，选中行始终可见（STAGE-346）。内容区高度按 `parts_for`（`ui/petdetail.rs`）取舍：多出 1 行给昵称，2 行给技能栏，3 行给等级，4 行给地水火风；所以 80×32 这类高终端面板打开时详情也能回来一部分。
  - **窄屏降级**（STAGE-242、STAGE-249）：内容区不足 10 行时，两行汇总不再一起省略，而是保留；其余行按上面的顺序省略。左右两列在 80 列下是 26 列和 16 列（宽终端时各占一半），`基础属性（自 Lv5 起）` 这类表头放得下；放不下时表头先去掉“成长/级”，再去掉括号。技能栏在 80 列下放不下全部 7 个栏位：技能名是两个字时约放得下前 6 个，名字更长就更少，后面的栏位被裁掉（一期已知限制，原来的写法也是这样，见 STAGE-217 的说明）。
- **刻度**：宠物的地水火风是模板值，范围 0–100（角色的属性点是 0–10，见角色页）。经验是累计值，显示“当前/升到下一级所需”；已是最高级（`next_exp` 为 -1）时写“满级”。
- 没有宠物时，右侧写灰色的“还没有宠物”。

**服务端**：
- 宠物模板：复用 `internal/gamecatalog` 解析 `enemybase.txt` 的代码，补上现在没读的 `INITNUM`、`LVUPPOINT`、四项资质、`MODAI`、品质相关字段，离线生成 UTF-8 的宠物表编译进服务端（放 `server/gamedata/`）；技能表同理读 `petskill.txt`；
- 数据库：新表存宠物实例（角色、栏位 0–19，STAGE-346、物种、自起名字、等级、经验、四项能力、四项资质、品质、忠诚可变部分、HP、状态、技能）；
- 管理命令：`go run ./cmd/stoneage-admin givepet <角色名> <宠物编号> [等级]`，按“生成一只宠物”的规则随机资质，放进第一个空栏位；栏位满了报错；
- 协议（先改 `docs/protocol.md` 和用例）：`pets` 查看类请求返回 20 个栏位的宠物；推送 `pets_changed`，内容与 `pets` 响应相同，玩家和 agent 两端都收到。每只宠物发：栏位、物种名、自起名字、等级、经验与下一级所需、HP/最大 HP、攻击、防御、敏捷、忠诚、地水火风、状态、技能列表；另有成长率 `growth` 和五档素质 `quality`（STAGE-216，见 `docs/protocol.md` 5.19）。**模板资质本身不发给客户端**（防止外挂一眼挑宠）；这只宠物的素质点和档位（`quality`）按 STAGE-212 的要求公开，显示在 STAGE-217。

**一期不做**：宠物图像、宠物邮件、家族守护兽、转生宠物的特殊规则。

**验收**：
1. 新角色进入世界，宠物页 0–2 号栏是出生送的三只（出生地宠物、配套虎、配套雷龙，STAGE-62），3–19 号栏空；
2. 用管理命令发一只宠物后，页面立刻出现它，数值与公式一致；
3. 发多只后，`pet status N` 切换详情正确；
4. 出战的宠物标绿，已倒下的标红；
5. 重新登录后宠物仍在；
6. 80×24 到 200×60 之间不越界，`--unicode false` 仍可读；
7. 单元测试（模板解析、生成规则、衍生数值、忠诚公式、渲染）、协议用例、模拟服务端新场景、冒烟测试同步更新。

### B：管理宠物（STAGE-32，协议见 `docs/protocol.md` 5.22–5.24）

- `pet battle <编号>` 设为出战，原来的出战宠自动变成休息；`pet standby <编号>` 设为待命；`pet rest <编号>` 设为休息。规则：最多 1 只出战、3 只待命；已倒下（血量为 0）的宠物不能出战，待命满 3 只时再设待命回复错误，状态都不变。 战斗结束（不论胜负、逃跑、平局）时血量为 0 的随身宠物自动回到 1 血（STAGE-245，同原版 BATTLE_Exit），之后可以再设出战。
- `pet rename <编号> <名字>`：名字去掉首尾空白后 1–16 个字符，不能含空白或控制字符（原版服务端 16 字节 GBK，这里按字符数计）；不带名字时恢复种族名。
- `pet talk <编号>`：和宠物对话（STAGE-239，协议 5.61）。只能对出战或待命的宠物说话；台词进消息栏，没有对话的宠物写“没有反应”。改了上限会推送 `pets_changed`，发了道具会推送 `inventory_changed`。
- `pet drop <编号>`：放生，宠物消失。新设计没有局部地图，不会掉在地上，所以放生是不可恢复的。客户端的做法：输入 `pet drop <编号>` 后在消息栏问一句，不发请求；紧接着的下一条输入是 `y`（`yes`、`是` 也行）才真正放生，输入别的内容都视为取消，并在消息栏写一句“已取消放生”，这一条输入照常当命令处理。命令末尾直接带 `yes`（`pet drop <编号> yes`）时不问，直接放生。确认的规则见 `docs/interaction.md`「确认」（STAGE-103）。骑乘中的宠物、交易中不能放生（骑乘和交易以后补）。
- 战斗中不能做以上操作；agent 操控期间玩家发起时，按“操作类”请求被拒绝。
- 守护兽不能改名、放生：一期宠物表没有守护兽标志，暂不检查，待核对。
- 命令名用 `pet` 命令组：待命逐只设置，比用掩码更容易理解。

### C：成长（依赖战斗，STAGE-33）

- 战斗胜利后，出战宠物和人物各自按自己的等级算等级差（STAGE-244，原版 `battle.c` 对每个参战单位各算一遍），基础经验来自 `server/gamedata/exp.go` 的 `EnemyExp`；经验够了升级；宠物和人物共用一张经验表（原版 `CHAR_GetLevelExp` 对两者都查 `NeedLevelUpTbls`）。
- 每升一级，四项能力在现有基础上**累加**一次随机成长（`gmsv/char/char_data.c` 的 `CHAR_PetLevelUp`，新服务端是 `gamedata.PetLevelUp`）：
  - 先把 10 个随机点逐个随机分到四项上；
  - 再在品质对应的区间里随机一个成长系数：品质 0–5 依次是 4.50–5.00、4.70–5.20、4.90–5.40、5.10–5.60、5.30–5.80、5.50–6.00（`RankRandTbl`）；
  - 每项增量 = (资质 + 分到的随机点) × 成长系数（1/100 点，按原版的 float 运算截断）。资质是生成时保存的那套（`CHAR_ALLOCPOINT`）。
  - 所以能力只升不降；同种宠物因为资质、每级的随机点和系数不同，长大后强弱不同。
- 升级时忠诚的可变部分 +5（`AI_FIX_PETLEVELUP`，可变部分限制在 ±100）；血量不变，不回满。忠诚本身每次现算，玩家等级、魅力变化也会改变它。
- 等级上限：宠物自己的上限（对话可改写，STAGE-234，见 docs/quest.md「宠物对话」）没有的话，模板填了 `LIMITLEVEL` 的按它，到了上限不再升、经验清零；其他宠物停在 140 级（原版开了自定义经验，宠物超过 `setup.cf` 的 `LEVEL=140` 需要转生条件）。上限时宠物页的“下一级”显示满级。原版的转生分支（`PETTRANS`）在 `setup.cf` 里是 -1，所以上限只看 `LIMITLEVEL`，转生次数不改变上限（STAGE-196 核对）。
- 转生次数（STAGE-196）显示在详情的等级行“转生”一项，新宠物与旧宠物都是 0；超过 2 次的宠物不能骑（`docs/ride.md` 第 9 条）。
- 捕捉到的宠物原样带走怪物的能力、资质和品质，血量是被抓时剩下的（`PET_createPetFromCharaIndex`）。
- 宠物的经验、等级、能力、忠诚的可变部分、血量与状态在战斗结束时整张写回数据库（`savePets`），下线、重启后不丢。
- **未对照**：原版 2.5 的升级会从经验里扣掉这一级所需的经验（`CHAR_HandleExp`，按级计算而不是累计），`setup.cf` 还挂了自定义经验表 `data/exp.txt`；新服务端的人物和宠物目前都按累计经验计算，要不要改另立缺陷处理。

### D：获得宠物（依赖战斗）

- 捕获（战斗中，成功率来自模板的 `E_T_GET` 和捕获道具）、商店购买、孵化、NPC 赠送。
- 新手赠送的宠物已由 STAGE-62 完成（建角色时送出生地宠物、配套虎和雷龙，见 `server/gamedata/newplayerpets.go`），不在这里。

### E：宠物技能与骑乘（依赖成长）

- 骑乘的条件、对角色数值的影响。

### 格子与编号

沿用本文“菜单”一节的依据：协议的物品槽位是 0–19 的绝对编号，**0–4 是装备，5–19 是背包**。页面上显示的编号就是命令参数（`item equip 7`）。

| 槽位 | 部位 | 能放的物品类型（`gmsv/item/item.c` 的 `ITEM_getEquipPlace`） |
|---|---|---|
| 0 | 头 | 头盔（`ITEM_HELM`） |
| 1 | 身 | 铠甲（`ITEM_ARMOUR`） |
| 2 | 手 | 拳套、斧、棍、枪、弓、投掷类武器 |
| 3、4 | 饰品 1、2 | 手镯、乐器、项链、戒指、腰带、耳环、鼻环、护身符 |

饰品先放 3 号位，3 号位有东西时放 4 号位（对应原版服务端 `CHAR_DECORATION1/2`）。盾牌在原版服务端数据里被注释掉了，一期不支持。

- **布局**：左右两块，各一个带黄色表头的 `Table`。空格子也占一行，名称位置写灰色的 `—`，这样编号始终固定。

- **高度不够时**：物品表要 15 行加表头和边框共 18 行，终端高度低于约 30 行时放不下，`PgUp`/`PgDn` 滚动物品表，标题写 `物品 · 5–12 / 19`。

**物品从哪来**（服务端）：
- 物品模板（名字、效果文字、类型、等级等）来自原版服务端 `gmsv/data/itemset.txt`（12622 行，GBK）。仓库里 `internal/gamecatalog` 已经有解析代码（`ParseItems`），**复用它**，不要重新数列；离线生成一份 UTF-8 的物品表，编译进服务端（放 `server/gamedata/`）。
- 角色的物品存在数据库：每个物品一行，记录角色、槽位、物品模板编号、数量。同一角色同一槽位只能有一个。
- 服务端发给客户端的是**已经转成 UTF-8 的名字和效果文字**，客户端不需要任何物品数据。
- 管理命令：`go run ./cmd/stoneage-admin give <角色名> <物品编号> [数量]`，放进第一个空的背包格；背包满了报错。

### B：穿脱与整理（STAGE-29，协议见 `docs/protocol.md` 5.25–5.28）

- `item` 命令组把“穿戴”从 `item use` 里分出来：`item equip <编号>` 穿上（背包格 5–19）、`item unequip <编号>` 卸下（装备格 0–4）、`item move <从> <到>` 移动或互换、`item drop <编号> [数量] yes` 丢弃。格子编号的范围在本地先检查，不对就报错、不发请求。
- **穿戴**：部位由物品类型决定（`ITEM_getEquipPlace`，见上文“格子与编号”）。目标部位已有装备时两件互换，原装备回到穿戴的那个背包格。饰品先放 3 号，3 号有东西放 4 号；两个都有东西时与 4 号互换（原版服务端没有规定，这里是我的选择）。数量不是 1 的格子不能穿。
- **要求**：只检查等级（`itemset.txt` 的 `lv` 列，例如大的棍棒要 25 级）。腕力、速度、转生的要求来自原版服务端的 `itemset4.txt`，仓库里的数据目录没有这个文件，一期不检查，待核对。不满足时拒绝，说明写明要求和现在的等级。
- **卸下**：放进第一个空的背包格；背包 15 格都有东西时拒绝（`BAG_FULL`），什么都不改。
- **移动**：背包格之间移动或互换；背包格和装备格之间按穿脱的规则检查；装备格之间不能直接换（先卸下）。
- **属性变化**：攻击、防御、敏捷 = 能力公式的结果 + 穿着的装备的加成合计（不低于 0）。加成来自 `itemset.txt`：攻击取 `ma` 列，防御取 `mh` 列，敏捷取 `mq` 列；这三列在数据里各有两列写同一个值，统计上与效果文字“攻 / 防 / 敏”对得上。魅力、运气也有装备修正（第 49、47 列，STAGE-61），加在基础值上夹在范围内；地水火风**不**从装备推算（数据里没有可靠的列）。穿脱后服务端推送新的 `status`，角色页立刻变化。
- **丢弃**：就是销毁，没有局部地图，不会掉在地上。没有 `yes` 时客户端在消息栏问“丢弃后不能恢复……输入 y 确认”，不发请求，下一条输入是 `y` 才丢弃（确认层，STAGE-103）；命令末尾带 `yes`（`item drop 7 yes`）时直接丢弃。服务端也要求 `confirm` 为 `"yes"`。
- **丢弃石币**（STAGE-328，`protocol.md` 5.76）：命令 `gold drop <数量> [yes]`，数量是正整数且不超过持有。没有 `yes` 时在消息栏问“丢弃后不能恢复……输入 y 确认”，确认层同上；带 `yes` 直接丢弃。石币丢掉后是销毁，不可恢复。石币在上限附近时用它把持有量压下来，卖东西就不再因 `GOLD_FULL` 失效。
- 战斗中、死亡时不允许穿脱（死亡已实现，战斗中待战斗做出来后补上）。交易中的限制以后补。
- agent 操控期间玩家发起这些命令，按“操作类”请求被拒绝（`CONTROLLED_BY_AGENT`）。

**验收**：
1. 背包里的斧头穿到“手”位，攻击从 5 变成 14；卸下后恢复到 5；
2. 不能穿的物品、等级不够、背包满时有明确提示，数据不变；
3. 两件装备互换正确，饰品放第 2 位正确；
4. 玩家和 agent 两端都看到格子和数值的变化；
5. 协议文档、用例（`world_item_equip`、`world_item_errors`、`control_item`、`ui_item_manage`）、单元测试、模拟服务端场景和冒烟测试同步更新。

### C：使用物品（STAGE-30，协议见 `docs/protocol.md` 5.31 与 10.5 的 item）

- 命令 `item use <槽位> [目标]`，目标默认自己，约定 1–5 是宠物，6–10 是队友。槽位要在本地检查（5–19、格子上要有东西），目标只在本地解析成数字，合不合法（组队、宠物栏位、倒下、物品的目标类型）由服务端判断，提示写进消息栏。
- 一期只做三类效果：回复 HP（物品表参数“体N”）、回复 MP（“气N”）、解除异常状态（“毒”“麻”等，只在战斗中有效）；“全”是 HP 回满加 MP 回满（或解掉全部异常）。回复量 `RAND(0.9N, 1.1N)`，HP 再乘恢复率（人物 1+0.0001×体力、宠物 1+0.00005×体力），MP 不乘；按上限截断。传送、投掷毒药、复活、魅力等其他效果另立需求，服务端回复“还不能使用”。
- **战斗外**：成功后消息栏写“对 XX 使用了 YY，血量回复 N”（有气力变化时加上“气力回复 N”）；服务端推送 `status_changed`（自己）、`pets_changed`（宠物）、`inventory_changed`（数量减 1，用完格子消失）。
- **战斗中**：指令条选“道具”或输入 `item <槽位> [目标]`（目标规则同上，还可以选己方单位）；结算的事件是 `item`（名字、`heal` 回复或 `status_remove` 解状态），道具在 `battle_round` 前扣掉并推 `inventory_changed`。“全己方”的物品不带目标时对己方全体生效。
- 使用限制按物品表的“可使用场合”：只能在战斗中用的（如结婚蛋糕、解状态的肉）在世界中用回复“只能在战斗中使用”，只能在战斗外用的一样处理。
- 使用中目标死亡、场合不对、物品不能用时给出明确提示，数量不变；回复量为 0（满血满魔）也照常消耗，消息栏不写回复量。

## 任务页（菜单 5，STAGE-86）

玩家接了任务以后，在这里看“我做到哪一步了”。纯查看，没有操作；数据来自服务端（协议见 `docs/protocol.md` 5.44、5.45），进入世界后取一次，之后靠 `quests_changed` 推送更新。

```text
┌任务 · 进行中 1 · 已完成 1─────────────────────────────────┐
│ 编号  任务                        状态                     │
│    3  猜谜3兄弟 拿蓝暴            进行中                   │
│    1  成人仪式                    已完成                   │
└────────────────────────────────────────────────────────────┘
```

- **表**：带黄色表头的 `Table`，列是 编号 / 任务 / 状态。编号是任务编号（原版 `jobdaily.txt` 的编号），和任务表对应；状态“进行中”黄色、“已完成”绿色。进行中的排在前面，同一状态内按编号从小到大。
- **标题**：`任务 · 进行中 N · 已完成 M`，数量不受显示范围影响；显示范围不是全部时标题末尾多写一句“只看进行中”或“只看已完成”。
- **空提示**：一个任务都没有时，表的位置写灰色的“还没有接到任务，去和村里的 NPC 聊聊吧”；只是当前范围里没有任务（如只看已完成却没有已完成的）时写“没有已完成的任务”之类。
- **显示范围**：`quest`（别名 `任务`）切换，`quest doing` 只看进行中，`quest done` 只看已完成，`quest all` 或不带参数是全部。命令同时切到任务页；纯本地操作，不发请求，agent 操控时也能用。
- **翻页**（STAGE-115）：焦点在列表时 `PgUp`/`PgDn` 让选中项跳一屏（行数是表的可见行数），列表跟着选中项走，选中项到了边上它就是第一行或最后一行；`Tab` 进攻略栏后，`PgUp`/`PgDn`、`↑↓`、`Home`/`End` 滚动攻略。方向键选任务、`Enter` 打开攻略见「页面选择」（STAGE-112）。窄屏时攻略替换列表，焦点只能在攻略栏上。
- **实时更新**：任务进度一变，服务端推送 `quests_changed`，任务页不用刷新就变化；消息栏写一句“任务【成人仪式】进行中”或“任务【成人仪式】已完成”。清除（管理命令 `quest … clear`）时列表里少一条，不提示。
- **攻略**（STAGE-89）：`quest 编号` 打开任务列表里那一条的百科攻略（只能查列表里有的任务，编号是任务表里的编号）。
  - **布局**：宽度 ≥ 110 列时，列表占左边 40%，攻略占右边；更窄时攻略替换列表，同百科页的规则。标题是 `攻略 · 任务名`；详情的换行、滚动与百科词条共用同一个面板。
  - **内容**：任务名；同一篇攻略有多个步骤时写“当前进度：第 k 步 / 共 n 步”（步骤按任务编号排）；然后是词条详情（名称、说明、位置、等级、流程等，不显示图片、CDN 链接、来源和署名，与百科页一致）。一个任务对应多篇词条时（如“琉璃洞窟”），每篇标“攻略 1/2”“攻略 2/2”。
  - **没有攻略**：灰色的“百科里暂时没有这个任务的攻略。”，并给出建议命令 `wiki find 任务名第一个词`。
  - **跳到百科**：`quest 编号 wiki` 切到百科页并打开第一篇攻略（等价于 `wiki open quest:xx`），之后用 `wiki back` 退回。没有攻略时留在任务页，消息栏提示。
  - **关闭**：`quest back`（或 `quest 返回`）、`Esc` 回到列表；切换显示范围（`quest doing` 等）也回到列表。
  - **对照表**：任务编号到百科词条的对应关系是人工维护的，放在 `tools/quest-wiki-map.json`（空数组表示没有攻略，`_说明` 写了判定规则），客户端编译时嵌入（`client/src/wiki/quest_map.rs`）。`tools/gen-quests.py` 生成任务表时校验对照表覆盖全部任务编号，缺了或多出编号都会报错。百科快照重新生成后词条 key 可能变，`cargo test` 的 `every_mapped_key_exists_in_the_snapshot` 会报出失效的 key。
- **验收**：
  1. 进入世界后按 `5` 进任务页，新角色是灰色的空提示；
  2. 管理命令设一个任务进行中，任务页不用刷新就出现这一条，消息栏有提示；再设成已完成，状态变绿并排到后面；
  3. `quest doing` / `quest done` / `quest all` 过滤正确，`quest 乱写` 提示用法；
  4. 离开再进入，进度还在；
  5. `quest 6`（恐龙博士 抓鲁尼帖斯）在宽屏并排显示攻略、标“第 1 步 / 共 2 步”；`quest 7` 标“第 2 步”；窄屏（80 列）时攻略替换列表，`quest back` 或 `Esc` 回列表；
  6. `quest 9`（水田迷宫，无攻略）显示灰色提示和 `wiki find 水田迷宫`；`quest 36`（琉璃洞窟）显示“攻略 1/2”“攻略 2/2”；`quest 6 wiki` 跳到百科并打开“恐龙博士”。

```text
┌分类──────────────────────┐┌宠物与生物 · 搜索“乌”· 共 3 条───────┐┌词条 · 乌力──────────────────┐
│1  任务              97   ││编号  名称      摘要                  ││乌力                          │

│3  装备              9874 ││2     乌力王    …                     ││编号：pet:1                   │
│…                         ││                                      ││模板编号：1  图号：100250 …   │
└──────────────────────────┘└─────────────────────── 第 1/1 页 ────┘└──────── 第 1–10/48 行 ───────┘
```

- **布局**：左边「分类」表固定宽 26 列（编号、名称、词条数，当前分类黄色加粗）；剩下的地方放词条列表（`Table`，黄色表头），打开词条后宽度 ≥ 110 列时列表缩到 40% 并排显示详情，更窄时详情替换列表。最小窗口（80×24）下放不下全部 11 个分类，分类表跟着当前分类滚动，底边写“共 11 类”。
- **分类**共 11 个：任务、宠物与生物、装备、物品、宠物技能、战斗 NPC、敌人、地图、城镇与任务 NPC、野外遭遇、Agent（以快照的 `catalog.json.gz` 为准，约 2.1 万个词条）。STAGE-185 起「本服任务验证」「未放置 NPC 模板」「新增与修改指南」不在目录里（`wiki/mod.rs` 的 `HIDDEN_CATEGORIES`），词条还在快照里，搜索和详情照旧。
- **命令**（登记在命令表里，纯查询，agent 操控时也能用）：

| 命令 | 作用 |
|---|---|
| `wiki` | 回到分类目录 |
| `wiki 分类` | 进分类，列出全部词条。分类可以写左边的编号（`wiki 2`）、id（`wiki pet`）或名字里的几个字（`wiki 宠物`）；id 精确匹配优先 |
| `wiki find 词…` | 搜索。已进分类时只搜这个分类，否则搜全部分类；多个词用空格分开，需同时满足；匹配编号、名称、说明、位置、技能等文本，不区分大小写 |
| `wiki open 编号` | 打开列表里该编号的词条（编号是整个列表里的序号，翻页后不变） |
| `wiki open key` | 按词条编号打开，如 `wiki open pet:1`；详情末尾的“相关词条”给出这些 key，可以直接跳转 |
| `wiki next` / `wiki prev` | 列表翻页，选中项落到新一页的第一条（也可以用 `PgDn` / `PgUp`：焦点在词条栏时选中项翻一屏，焦点在详情栏时滚动详情） |
| `wiki back` | 一层层退：先关词条，再清搜索，再回分类目录 |

- **方向键**：分类、词条、详情三栏用 `Tab` 切换，`↑↓` 选，`Enter` 进分类或打开词条，`Esc` 等于 `wiki back`（STAGE-112，见「页面选择」）。
- **详情**：词条名（青色加粗）、说明、分组、词条编号，然后是字段（`标签：值`）、表格（小节标题洋红加粗，表头黄色，列之间用 `│`，`--unicode false` 时用 `|`）、备注、相关词条。按宽度换行，按显示行滚动，窗口底边写当前行号范围。
- **不显示**：网页版的图片、CDN 链接、素材下载包；外部攻略来源与署名（和网页版一致，用户页面不显示）；网页版里的“原始名称”字段（旧表的 GBK 误读乱码）。
- **验收**：
  1. `9` 进百科页，11 个分类和词条数正确，最小窗口下用 `wiki 11` 能进到最后一类（Agent）；
  2. 每个分类都能列出词条、`wiki open 1` 能打开详情，各尺寸下不崩；
  3. `wiki find` 能按名字和编号命中；`wiki open key` 能跳转；翻页、滚动不越界；
  4. `--unicode false` 时详情不出现画线字符；
  5. `cargo test` 通过（`wiki` 模块单元测试、`tests/render_wiki.rs`）。

## 消息

- 消息用滚动的 `List`，每行前面是定宽的类型标签，标签着色，正文用默认颜色。
- 配色只用 16 色具名颜色：

  | 类型 | 颜色 |
  |---|---|
  | 命令（回显与结果） | Cyan |
  | 系统 | Blue |
  | 公共聊天：本图（`[本图]`） | 默认 |
  | 公共聊天：世界（`[世界]`） | LightBlue |
  | 队伍 | Green |
  | 队伍聊天（`[队]`） | Green |
  | 战斗 | Yellow |
  | 错误 | Red |
  | agent 私聊 | Magenta |
  | 耐久（“X因过度损坏而消失。”，服务端 `red` 为假） | Yellow |
  | 耐久（“X是受损的。”等等级变化，服务端 `red` 为真） | Red |

- 新消息出现在最下面。底部消息栏固定显示最近 5 条，不能滚动；要看更早的消息，切到「7 消息」页。
- 登录、注册、角色选择这类表单页的消息面板是另一块（`widgets.rs` 的 `render_messages`）：显示最近几行，正文过长时换行、续行缩进到标签后（STAGE-100，服务端的升级提示要看得全）；世界页的底部消息栏仍是一行一条、过长截断。
- 两处显示的是同一份消息记录。客户端在内存里保存本次登录以来的消息，退出后不保留；条数上限 1000，超出时丢弃最早的。战斗中，战斗日志区也从这份记录取最近几条（STAGE-248），战斗文字与系统、错误、命令、队伍、耐久提示按时间混排在一处，同一条只出现一次。
- 启动时后台查到新版本，系统消息写一行「有新版本 x.y.z，运行 stoneage update 升级」（只写一次，见 `docs/client.md`「升级」）。
- 消息记录目前有命令、系统、错误、agent、战斗、队伍、耐久七种类型（战斗记录见 `docs/battle-ui.md`，队伍类型记组队、解散、分身倒下、战后恢复，Green，STAGE-162；队伍聊天（STAGE-277）标签为 `[队]`，同样 Green；耐久记战斗里装备受损、消失的提示，标签「耐久」，颜色以服务端的 `crush[].red` 为准，STAGE-225）；公共聊天（STAGE-278，标签 `[本图]` 默认色、`[世界]` LightBlue，设计见 `docs/chat.md` 第三节）在界面实现时加入，消息页不用跟着改。

### 消息页（菜单 7）

```text
┌消息 · 第 321–345 / 356 条──────────────────────────────────── 有 3 条新消息 ↓ ┐
│ 命令  warp 萨姆吉尔村                                                           │
│ 系统  已传送到 萨姆吉尔村                                                       │
│ agent 勇者的 agent: 我在村口，要不要先去买点补给？这一行很长，超过终端宽度时    │
│       自动换行，换行后和正文对齐，不压到标签下面                                │
│ 错误  未知命令：fly                                                             │
│                                      …（占满中间区域，最新的在最下面）          │
└─────────────────────────────────────────────────────────────────────────────────┘
```

- **内容与配色**：和底部消息栏用同一份记录、同一套定宽标签和颜色（复用 `widgets.rs` 的 `message_items`）。区别只有两点：占满整个中间区域；过长的正文**自动换行**，续行缩进到标签后面（底部消息栏仍是一行一条，过长的截断）。
- **标题**：写当前显示的范围，例如 `消息 · 第 321–345 / 356 条`；没有消息时写 `消息 · 暂无`，页面中间写灰色的“本次登录以来还没有消息”。
- **滚动**：进入页面时停在最新。
  - `PgUp` / `PgDn` 翻一页（页高减 1 行，保留一行重叠）；
  - 输入行为空时 `↑` / `↓` 逐行滚动（STAGE-112 设计，STAGE-116 实现，按换行后的行走，锚点消息的每一行都停得住）；
  - 屏幕顶部或底部露出一半的消息只显示露出的行（列表截掉其余行），不留空行；跟随最新时也一样，顶部那条可能只露出后几行（STAGE-116）；
  - `Home` 回到最早，`End` 回到最新，这两个键在输入行为空时才作滚动，输入行有内容时仍是光标的行首、行尾；
  - 离开消息页再回来，重新停在最新。
- **跟随与锚定**：停在最新时，新消息来了自动跟随；翻到更早的位置后，**视图不动**（以屏幕顶部那条消息为锚点，不是按“距最新多少行”算），标题右侧用黄色提示“有 N 条新消息 ↓”（N 是翻走之后新到的条数），按 `End` 回到最新。
- **丢弃最早消息**：超过上限丢掉最早的消息时，如果视图正停在被丢掉的位置，就停在现存的最早一条。
- 其他页面（地图、角色等）的消息仍然只显示在底部消息栏，不受这一页的滚动状态影响。

**一期不做**：按类型筛选、搜索、消息存盘（退出后不保留）、每条消息的时间。等消息类型多起来、玩家确实需要时再单独提需求。

**验收**：
1. 切到「7 消息」页显示全部历史消息，配色与底部一致，最新在最下；
2. `PgUp`/`PgDn`/`Home`/`End` 按上面的规则滚动，翻到顶或到底时不越界、不报错；
3. 翻到旧位置后新消息到来，视图不动且出现“有 N 条新消息”提示；`End` 后提示消失并跟随；
4. 中文长句、全角标点在 80 列宽下正确换行，不截断、不错位；
5. 超过 1000 条后，丢弃最早的消息，滚动状态不异常；
6. 单元测试（换行、滚动、锚定、上限）和渲染测试通过。

## 命令

- **Tab 补全**（STAGE-26）：补全命令名和第一个参数（地点名和地图名、`addpoint` 的能力名、`item`/`pet`/`token` 的子命令、`revoke` 的令牌编号等）。候选只有一个时补全并加空格；不止一个时补到公共前缀，没有进展就把候选写进消息栏（地图名有几百个，最多列 20 个，并写明总数）。

## 按键

按键的统一含义、分层、确认方式和提示行都以 `docs/interaction.md`《交互规范（全局）》为准，本节只列主界面在规范之内用到的键：

| 按键 | 作用 |
|---|---|
| `1`–`9` | 输入行为空、没有弹窗和战斗时切换菜单；有弹窗时用 `page N` 切换（STAGE-103） |
| `←` / `→` | 输入行为空、没有弹窗和战斗时切换到左边 / 右边的菜单页，循环（STAGE-112）；有内容时移动光标 |
| `Enter` | 有内容时执行命令；空行时打开选中项的详情或把常用命令填进输入行（STAGE-112，「页面选择」） |
| `Tab` | 有内容时补全命令和参数；空行时切换页面的焦点栏，`Shift+Tab` 反向（STAGE-112） |
| `↑` / `↓` | 空行时移动页面的选中项（消息页逐行滚动，系统页、社交页翻历史）；有内容时按前缀翻历史命令（STAGE-112）；战斗中空行用来选指令和目标 |
| `PgUp` / `PgDn` | 焦点栏是列表时选中项跳一页（「背包」「任务」「百科」），是详情时翻一页（「消息」页、任务攻略、百科词条） |
| `Home` / `End` | 输入行为空时到最前 / 最后（列表是第一项 / 最后一项）；有内容时移动光标 |
| `Esc`（备用 `Backspace`） | 有字时清空输入行；空行时退一步：关弹窗、「任务」页先关攻略（STAGE-89）、「百科」页照 `wiki back` 退一层（STAGE-112）。`Backspace` 在能返回的层里同样退一步（STAGE-172）；有文字焦点、战斗、确认、窗口时只删字或不接管，场景根页不接管。规则见 `docs/interaction.md`「返回键」 |
| `Ctrl+C` | 退出（会先确认），不用 `q` 退出，因为 `q` 要用来打字 |

## 服务端驱动的界面

下面这些界面不属于菜单，服务端发来对应的包时自动出现：

- **战斗**：中间区域换成战斗画面，菜单栏的标签行换成战斗信息条（回合、阶段、自己和出战宠物的血量，STAGE-106），边框变红并写“战斗中”，这期间 `1`–`9` 不切换菜单，输入行为空时数字键用来选指令和目标。完整设计见 `docs/battle-ui.md`（站位、单位卡片、指令输入、结算回放、结果窗口）。战斗结束后回到原来的菜单页。
- **决斗（STAGE-307，`docs/pk.md` 五、协议 5.74）**：标题写「决斗 · 地图名」（不写「敌左我右」），己方按 `you` 判断（应战方 `you` 为 10–14）。结果窗口只写胜负和「决斗点数 -10（现在 90）」（增加写 `+`，不变写「不变」），没有经验、石币和掉落行。被挑战时没有弹窗：消息栏写「X 向你发起了决斗」，直接进入战斗页。
- **NPC 对话、商店**：中间区域上方弹出一个居中的带边框窗口（用 `Clear` 清掉底下的内容），选项带编号，用 `choose N` 或 `reply …` 回应。窗口打开时，输入行为空的情况下按数字就是选选项，而不是切换菜单；想看底下的页面用 `page 4` / `page 背包`（STAGE-103，`docs/interaction.md`）。对话窗口已实现（STAGE-69）：`talk 编号` 弹窗，没有选项的窗口按数字或 `Esc` 关闭，正文由服务端推送（`npc_window`）。任务 NPC 的暗号（STAGE-92）：脚本有暗号块时，闲聊或台词窗口上多一个选项 `1. 说暗号`；选了以后窗口转成文字输入（`accepts_text`），正文下面提示 `reply 文本 发送 · Esc 关闭`，这时数字键是文字，不关窗也不切菜单，用 `reply 暗号` 说出来（文字原样发送，不去掉空格）。商店的买卖菜单也是这个窗口（STAGE-70）：选「买」逐级进入商品列表、数量询问（`reply 数量` 成交），选「卖」列出背包可卖的物品（选格即卖）。
- **强者表（STAGE-308）**：竞技场和各村的「强者表」NPC 用同一个对话窗口，选「强者们」或「自己」后，窗口正文换成一张带黄色表头的表格（名次、决斗点数、等级、名字），自己那行名字前有 `★`；表上方是页码和自己的名次，表下面的选项 `1 下一页`、`2 上一页` 用数字翻页（`docs/protocol.md` 5.75）。
- **交易请求、组队邀请**：先在消息里提示，再用 `trade …`、`party …` 命令处理；交易进行中用弹窗显示双方报价。
