# 攻击精灵的作用范围（STAGE-218）

攻击类精灵（`magic.tsv` 编号 301–325，共 25 个）的“打一个 / 打一排 / 打全体”和魔法闪避，以原版源码为准。
结论先行：**范围既不是只看 `magic.txt` 的目标码，也不是只看 `attmagic.bin` 的 `uiAttackType`**——
目标码决定“选什么”，`attmagic.bin` 里的 `siField`（3×5 命中掩码）决定实际打到哪些格子，`uiAttackType` 只影响表现。

## 出处

| 内容 | 位置 |
| --- | --- |
| 目标枚举、`tagAttMagic` 结构 | `original-data/gmsv/include/magic_base.h` |
| 读 `attmagic.bin` | `gmsv/magic/magic_base.c` 的 `ATTMAGIC_initMagic` |
| 攻精灵入口、取格 | `gmsv/battle/battle_magic.c` 的 `MAGIC_AttMagic_Battle`、`BATTLE_MultiAttMagic` |
| 魔法闪避 | 同文件的 `BATTLE_MagicDodge` |
| 数据 | `gmsv/data/magic.txt`（GBK）、`gmsv/data/attmagic.bin` |

## 怎么算出来的

`magic.txt` 的攻击系每行（`MAGIC_AttMagic`）有 9 列，后 5 列是整数：
`ID, 使用场所, 目标, 复活旗标, 攻击精灵索引`。第 9 列（`MAGIC_IDX`）是 `attmagic.bin` 里的索引。

`attmagic.bin` 每个精灵 132 字节（4 个 `uint` + 14 个 `int` + `int[3][5]`，64 位平台 4 字节对齐），
文件里每个精灵两份（敌方/玩家），`magic.txt` 的索引 `N` 对应第 `N*2`、`N*2+1` 条，两份的掩码相同。
最后 60 字节是 `siField[3][5]`：1 表示这一格会被打到。

`BATTLE_MultiAttMagic` 按目标码取格：

- **目标码 1/9（敌方一个人）**：客户端给一个敌人，服务端以它的格子为中心，用掩码的 3 行 × 5 列取格
  （目标格是掩码第 1 行第 2 列，上下各扩一行、左右各扩两列），超出本方的两排/五列就裁掉。
- **目标码 10（敌方一排）**：客户端给排号（原版 `toNo` 23–26），服务端把这一排对到掩码第 1 行，
  上一排用第 0 行、下一排用第 2 行，列从 0 到 4。
- **目标码 11（敌方所有人）**：不用选，遍历敌方两排，第 0 排用掩码第 0 行、第 1 排用第 1 行（原版 `toNo` 20/21）。

`uiAttackType`（0 单人、1 整排、4 全体）只用在 `BATTLE_AttMagicEffect` 的回包和客户端表现上；
反例：巨岩撞击（304）是 `uiAttackType=0`，掩码却是十字 5 格，实际打 3–4 个。

**“一排”实际怎么打**：原版把一排对到掩码第 1 行，所以掩码是“整排 5 格”的精灵正好打这一排 5 个
（土石流、龙卷风）；龙卷风的掩码是十字，打这一排 3 个 + 相邻排 1 个。它**不等于全体**：
满员时全体是 10 个，一排是 5 个。STAGE-202 说“一排等同全体”是召唤龙阵的 `BATTLE_MultiToCallDragonMagic`
（那里的循环不看掩码），攻击精灵不是那条路径，不能照搬。

**25 个精灵的分布**：单体 11 个、2–5 个 4 个、一排 5 个 4 个、全体 10 个 6 个。

## 复现

```sh
python3 tools/decode-attmagic.py
# 或指定文件：
python3 tools/decode-attmagic.py \
  original-data/gmsv/data/attmagic.bin \
  original-data/gmsv/data/magic.txt
```

脚本按上面的结构解 `attmagic.bin`，按目标码模拟原版取格，打印 25 个精灵的目标码、掩码、`uiAttackType`
和满员敌方里的命中数（最少–最多）。

## 新服务端怎么实现

- 协议**不新增目标类型**。`target_type` 仍是 `enemy`（要选敌方一个）或 `enemy_all`（不用选）：
  目标码 1/9/10 是 `enemy`，11 是 `enemy_all`。范围由服务端按掩码展开，一次 `magic` 事件里给出多条 `effects`。
- `magic.tsv` 多两列：原版目标码、掩码（15 位，行优先）。生成器 `tools/gen-magic.py` 从 `attmagic.bin` 读，
  不再按目标码 8/9 猜全体；`MagicTemplate.Target`、`MagicTemplate.Mask` 见 `server/gamedata/magic.go`。
- `server/battle/magic_range.go` 按上面的取格规则算命中集合；目标码 10 仍然只让玩家选一个敌人，
  用这个敌人所在的排作为“一排”（选这一排的哪个敌人都一样，和回旋镖横扫一排的做法一致），不新增协议字段。
  目标码 1/9 选中的敌人是掩码的中心，周围的格子按掩码一起命中。
- 每个被打的目标先判一次魔法闪避（`BATTLE_MagicDodge`）：人物是运气 × 3，宠物和怪物是等级 × 0.2（封顶 30），
  掷 1–100 小于等于闪避率就闪过，效果写 `dodge`、不扣血。人物那一项原版还加属性抗性 0.15 倍，
  新服务端没有抗性属性，复用 STAGE-202 的 `magicDodge`，只算运气（和龙阵同一条已知差异）。
- 精灵的 `effect` 文字按掩码写“敌方一个 / 敌方一排 / 敌方十字范围 / 敌方全体”，
  不再只看 `all`（否则熔岩爆发、暴风冰刃会被写成全体）。
