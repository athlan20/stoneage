# 公开聊天（设计）

状态：**协议已定**（2026-10-22，STAGE-278）：规则已并入 `protocol.md` 5.68（9.5 的预留已改成指向它）、`ui.md`、`interaction.md`、`server.md`，服务端和客户端还没实现。本文随后只保留设计依据。与 `social-players.md`（附近玩家、真人组队）配套：玩家列的固定入口、队伍频道都复用这里的聊天框架。

**说人话**：现在玩家之间没法说话。要做两个公开频道：「本图」（同一张地图上的人都能看到）和「世界」（全服都能看到，有冷却和等级门槛防刷屏）。说话的入口放在场景页「附近玩家」列底部的固定一行，也可以用 `/say`、`/world` 命令。管理员能禁言。

## 现状（设计依据）

| 方面 | 现状 |
|---|---|
| 私聊 | 只有同账号的玩家与 agent 之间的 `agent_say`（`protocol.md` 9.5），200 字符上限，不经过其他玩家 |
| 公开发言 | 9.5 只写了“以后定义的世界内聊天请求，属于聊天类，不受控制权限制，审计记录标明实际发出者” |
| 客户端 | 消息记录没有“公共聊天”类型（`ui.md` 配色表里只预留了“默认色”）；`say` 命令没做；聊天长度上限旧约定 70 个字符（UTF-8 字符数，不按 GBK 字节） |
| 推送 | `Hub.Publish` 已支持“一个键多个观看者”，`npcs_changed` 就是按地图推送 |
| 限流 | 已有 `RATE_LIMITED`（带 `retry_after_seconds`） |

## 一、规则

### 1.1 频道

| 频道 `channel` | 谁能收到 | 限制 |
|---|---|---|
| `map` 本图（默认） | 同一张地图上、在世界中的所有角色的**玩家连接**（含发送者自己） | 每人 1 秒 1 条 |
| `world` 世界 | 全服在世界中的所有角色的玩家连接 | 等级 ≥ 5；每人 30 秒 1 条；两项都是服务端配置 |
| `party` 队伍 | 本队的真人成员（含自己），见 1.5 | 每人 1 秒 1 条（同 `map`）；须在队伍里 |

`whisper`（玩家对玩家私聊）、家族频道不在本期，名字保留。

### 1.2 谁能说、说给谁

- 必须**在世界中**；战斗中也能说（聊天类，不受控制权限制，观察方也能说）。战斗中客户端按键归战斗界面，只能走 `/say`、`/world` 命令。
- agent 操控期间，玩家连接和 agent 连接都可以以角色身份公开发言；服务端审计记录里写明实际由谁发出（`by: player|agent`）。
- **agent 连接收不到别人的公开聊天**（有意）：公开频道里的文字谁都能写，进了 agent 的上下文就是提示词注入的入口。agent 要知道玩家在说什么，仍走 `agent_say` 私聊。`agent-guide.md` 第 6 节：agent 公开发言属于**第三级**（必须先问玩家），且公开聊天不用于汇报。
- 没有聊天记录回放：进入地图、重连、重新登录都不补发历史。客户端只保留本次登录的消息（`ui.md` 的 1000 条上限）。

### 1.3 文本

- `text` 去掉首尾空白后 1–70 个 UTF-8 字符（中英文都算 1 个），不能含控制字符（含换行、制表）；不满足回复 `BAD_REQUEST`。
- **屏蔽词**：词表文件由 `.env` 的 `STONEAGE_CHAT_FILTER_FILE` 指定（UTF-8，一行一个词，CRLF/LF 皆可；`#` 开头是注释，`!词` 是白名单，命中的部分落在白名单词内时不替换；单字词忽略）；没配则用内置 `server/gamedata/chat_filter.txt` 的少量词。匹配前先归一化（全角转半角、转小写、丢掉空白、标点、符号、零宽字符），所以夹符号的写法（如「傻.逼」「s b」）也命中；命中的相邻字符之间最多夹 3 个被丢掉的字符，超过就不算。命中的原文整段（含夹在中间的符号）换成等长的 `*`，消息照常发出，不给发送者“被屏蔽”的提示（避免被拿来试词）。纯英文词只在两侧不是字母数字时才算命中（`ass` 不误伤 `class`）。
- **重复消息**：同一人 10 秒内发完全相同的文字（同频道）静默丢弃，不推送，响应仍然成功（不让刷屏者知道被拦）。
- 聊天内容**不写数据库**；协议日志与审计日志里有（和其他消息一样），审计里带发送者角色、频道、实际发出者、文字。

**名字**：角色名（创建角色）和宠物改名命中同一份词表时回复 `INVALID_NAME`，错误说明只写“角色名含有不允许的内容”或“宠物名字含有不允许的内容”，不回显是哪个词。

### 1.4 禁言

- 管理命令：`stoneage-admin mute <角色名> --minutes N [--reason 文字]`、`unmute <角色名>`、`mutes`（列出当前仍在禁言的）。禁言只影响公开频道（`map`、`world`、`party`），不影响 `agent_say`。
- 持久化：角色表加字段 `chat_muted_until`（时间戳，空为未禁言），需要数据库迁移（迁移号注意别和别的需求撞）。禁言期间 `chat` 回复 `CHAT_MUTED`，`error.data.until_ms` 给到期时间；实现上每条发言前读一次 `chat_muted_until`，所以管理命令写完库就对在线角色立刻生效，不需要 PostgreSQL 通知（每条发言多一次按主键的查询，聊天频率有限流，可以接受）。`--reason` 只在命令行回显，不入库。
- 玩家屏蔽别人（个人黑名单）不在本期，见第四节。

### 1.5 队伍频道（`party`，STAGE-277）

**说人话**：组了队的人可以在队里说话，只有队员能看到。用法和公开频道一样（`/party say 文本`，别名「队聊」），消息显示成绿色的「[队]」。

- **谁能说**：在世界中、且在真人队里；没有队伍或只有分身队都回复 `NOT_IN_PARTY`。战斗中能说。agent 可以发（第二级，做完汇报），但 agent 收不到队聊（同公开聊天，防提示词注入）。
- **谁能听**：本队真人成员的玩家连接，含发送者自己。同图但不在队里的人收不到；离队、被请出、队伍解散后不再收到。不补发历史。
- **规则沿用公开频道**：文本 1–70 字符、屏蔽词、10 秒内同文静默丢弃、禁言（`CHAT_MUTED`）都与「本图」相同；限流每人 1 秒 1 条，与本图各自计时；不检查等级。
- **分身队**：已定（2026-10-23）：分身队不能发队聊，回 `NOT_IN_PARTY`——分身没有连接，队聊只会回到发言者自己，和“只有队友看得到”的目的不符。
- 协议见 `protocol.md` 5.68「队伍频道」，用例 `docs/protocol/cases/party_chat.jsonl`。服务端、客户端还没实现。

## 二、协议草案

聊天类请求（不受控制权限制，观察方也能发），世界中。

```jsonc
{"id": 90, "type": "chat", "data": {"channel": "map", "text": "有人去加加村吗"}}
{"id": 90, "type": "chat", "ok": true, "data": {}}
// 所有接收者（包括发送者自己）收到的推送
{"type": "chat_message", "data": {"channel": "map", "from": "阿牛", "level": 30,
 "text": "有人去加加村吗", "time_ms": 1760000000000}}
```

- `channel` 省略时当作 `map`。发送者也收到推送，所以客户端**不要自己回显**，以推送为准（和私聊不同）。这样各人看到的顺序一致；被静默丢弃的重复消息没有推送，发送者也不会看到假回显。agent 发的公开聊天，agent 自己不收推送（它本来就收不到公开聊天），只推给玩家连接。
- 响应只表示“服务端收下了”。`chat_message` 的 `from` 是角色名，`level` 是发送时的等级（客户端用来显示 `阿牛(Lv30)`）；不带账号、不带 `by`。
- 错误码：`BAD_REQUEST`（文本不合规、`channel` 不认识）、`WRONG_STATE`（不在世界中）、`RATE_LIMITED`（带 `retry_after_seconds`，`map`/`world` 各自独立计时）、`CHAT_MUTED`（带 `until_ms`）、`CHAT_LEVEL_LOW`（`world` 等级不够，`error.data.min_level`）。
- 服务端配置（`protocol.md` 第 8 节新增）：`chat.world_min_level`（默认 5）、`chat.world_cooldown_seconds`（默认 30）、`chat.map_interval_ms`（默认 1000）。
- 推送范围实现：`map` 用与 `players_changed` 相同的“按地图”键，只发玩家连接；`world` 遍历 `Hub.Sessions()` 里在世界中的玩家连接。接收者不含 agent 连接（1.2）。

## 三、界面

**入口**（三选一，同一批函数）：

1. **场景页「附近玩家」列底部的固定一行「聊天…」**（依赖 STAGE-273 的第四列；固定行的做法同遇敌列的「停止遇敌」）：`Enter` 打开聊天输入框。
2. **命令**：`/say 文本`（别名 `/s`、`说`；战斗中 `s` 是宠物技能简写，战斗里请用 `say`、`说`）发本图；`/world 文本`（别名 `/w`、`喊`）发世界；不带文字的 `/say`、`/world` 打开聊天输入框并选好频道。战斗、NPC 窗口等不方便开输入框的地方用命令。
3. 在场景和菜单里**普通字符仍不接收**（`interaction.md`），不为聊天破例。

**聊天输入框**（专用文字输入层，和系统页私聊同一类，输入焦点内 `Backspace` 只删字）：

```text
┌ 聊天 ────────────────────────────┐
│ 频道: [本图]  世界     Tab 切换  │
│ > 有人去加加村吗_                │
│ 8/70                             │
└──────────────────────────────────┘
```

- `Tab` 切频道（本图 / 世界）；`Enter` 发送并**保持打开**，输入清空，方便连续说话；`Esc` 关闭，未发的草稿保留到再次打开。
- 超出 70 字符不能再输入（计数变红）；等级不够 / 冷却中，输入框下一行显示实际原因（如「世界频道需要 5 级」「还要等 12 秒」），不弹额外窗口。
- 请求在途时 `Enter` 不重复发送；失败留在输入框并保留文字。
- 观察方（agent 操控中）：聊天可以发，不拦（聊天类）；agent 操控期间提示一行“agent 正在操控，你的发言仍以角色身份公开”。

**消息显示**：消息记录增加类型「聊天」，标签随频道：

| 频道 | 标签 | 颜色 |
|---|---|---|
| 本图 | `[本图]` | 默认色（`ui.md` 配色表已预留“公共聊天 默认”） |
| 世界 | `[世界]` | LightBlue |
| 队伍 | `[队伍]` | Green（STAGE-277） |

行格式：`[本图] 阿牛(Lv30): 有人去加加村吗`。自己说的话同样用推送显示，名字处写「你」。底部消息栏、消息页、战斗日志区都走同一份记录，不另做聊天窗口。`--unicode false` 没有额外变化。

## 四、不做与后续

- 玩家个人屏蔽（黑名单，持久化，服务端过滤）、玩家举报、`whisper` 私聊、家族频道、表情、聊天历史回放：以后再开单。公开频道上线后看骚扰情况决定屏蔽名单的优先级。
- 不做频道订阅开关（关闭世界频道）；需要时放在系统页设置里，另开单。

## 五、验收要点

1. 两个账号同图：A 在本图说话，A 和 B 都收到；B 在别的地图收不到；世界频道两人都收到。
2. 1 秒内连发被 `RATE_LIMITED`；世界频道 30 秒冷却和 5 级门槛生效，提示说明实际原因。
3. 屏蔽词被替换成 `*`，夹符号、大小写、全角半角的写法也要替换（如「傻.逼」「ＳＢ」）；名字命中屏蔽词回复 `INVALID_NAME`；10 秒内重复同一句只有第一次推送。
4. 禁言后发言得到 `CHAT_MUTED`，到期自动恢复；`unmute` 立即恢复；私聊不受影响。
5. agent 连接收不到 `chat_message`；agent 公开发言在审计里写明 `by: agent`。
6. 战斗中用 `/say` 能说话；输入框连续发送、Esc 保留草稿、80×24 可用。
7. 协议用例：两账号 + 一个 agent 连接，覆盖上面各项；`go test ./server/webpages` 的分级表补全 `chat`。
