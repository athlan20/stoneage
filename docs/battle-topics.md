# 战斗动作主题逐项标注（STAGE-167 D10）

原型附件里的 60 个主题逐项对照**真实实现**。这里不拿 HTML 演示或截图当验收：标「已实现」的项，在服务端有对应规则、事件里有对应字段、客户端有对应表现，并且有自动化测试；标「依赖」的项，引擎或协议还没有，客户端**故意不画**，等规则落地再补。

终端只做字符级表现：形态 = 人形/兽形身体 + 跨排位移与姿势 + 手持武器/飞行物 + 接触标记，不加载原版帧动画。所以「已实现」指这套标准下的实现，不是逐帧复刻。

## 剩余工作

按依赖排，都需要先改服务端规则或协议，不能只在客户端补动画：

1. 守护 / 镜 / 光三种精灵的战斗规则（A06 剩余部分）。
2. 属性加强、调和、极光（`StatusSet.field()` 认识 `buff`/`debuff`，以及全场属性变化）。
3. 坐骑身份与逐段分摊明细（`ride` 之外补 `mount` 与分摊数值）。
4. 多段攻击（爪、连击）的事件表达。
5. 打飞的方向与离场动效。
6. 队友 / 敌方换宠的服务端规则（客户端已按 `actor` 通用实现，规则支持即可生效）。

## 角色舞台补充验收（2026-10-18）

本次针对“有特效但没有单位身体”的反馈，替换正式 TUI 渲染，原有 60 主题的引擎依赖统计不因视觉改造而变更。

- `ui/battle/actor.rs`：人、宠、怪物、骑乘与倒地轮廓，走动、举手、挥击姿势。
- `position.rs` 与测试：跨排接触和回位、真实主人换宠、现场反击、忠犬代受和打飞隐藏。
- `weapons.rs` 与测试：各武器手持轮廓，飞行轨迹，回旋镖只扫事件的一排再回手。
- `spell_effect.rs`：施法者聚集与实际目标身体周围的元素/治疗/异常形态。
- `render_battle.rs`：80×24、120×40、200×60，以及二十个单位身体和原有菜单、消息、焦点回归。
- `client/examples/battle_preview.rs`：由正式渲染器导出逐帧 HTML，供暂停和拖动检查，不替代自动化测试和实际连服验收。
