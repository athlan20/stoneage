# 登录、注册与角色（一期）

本文覆盖从启动客户端到进入主界面的全部流程。视觉风格沿用 `demo/ratatui-demo/`，主界面见 `docs/ui.md`，世界地图见 `docs/map.md`。

这一段流程用**表单交互**：用 `Tab`、`↑↓`、`←→`、`Enter` 操作，不用主界面底部的命令行。进入游戏后使用场景和菜单，需要辅助命令时按 `/`。

STAGE-137：已有角色 Enter 先打开“进入游戏 / 删除角色 / 返回”；空栏位 Enter 进入创建。删除表单逐字匹配完整名字，Tab 切输入与按钮，按钮默认取消，明确选择“删除”才提交。建角 Esc 后退保留已填外形、名字、能力和出生地。Ctrl+C 与登录页退出按钮都打开默认取消的可见确认，确认后才退出进程并恢复终端。

## 流程

```text
启动 ──▶ 登录页 ──Enter──▶ 连接，hello ──▶ login ──▶ characters ──▶ 角色选择
           │  ▲                 │ 失败：回到登录页，在消息栏显示原因         │
           │  │                                                             ├─ 选中已有角色 Enter ──▶ enter_world ──▶ 主界面
           ▼  │ 注册成功后回来，账号自动填好                                 ├─ 选中空栏位 Enter ──▶ 创建角色 ──▶ create_character ──▶ 刷新 characters
         注册页（hello ──▶ register）                                        ├─ d 删除 ──▶ 输入角色名确认 ──▶ delete_character ──▶ 刷新 characters
                                                                             └─ Esc ──▶ 断开连接，回到登录页
```

- 客户端直接连接新的 Go 服务端（`server/`，需求 STAGE-2～4）。所有消息、字段、错误码以 **`docs/protocol.md`** 为准，本文只写界面和交互。
- 登录后按 `docs/protocol.md` 的心跳约定定期发送 `ping`；收到推送 `disconnect` 时回到登录页，并在消息栏显示原因。

## 启动参数

| 参数 | 作用 |
|---|---|
| `--server 地址` | 服务端地址，默认 `127.0.0.1:7065`；发布版默认是线上服务端（见 `docs/client.md`「安装」） |
| `--account 账号` | 预先填好账号 |
| 环境变量 `STONEAGE_PASSWORD` | 预先填好密码。**不提供命令行参数**，因为命令行参数会出现在 `ps` 的输出里 |
| `--character 名字或栏位` | 登录后自动进入指定角色 |
| `--unicode true\|false` | 图形字符开关，同 `docs/ui.md` |
| `--no-update-check` | 启动时不在后台查新版本（离线或内网使用），也可设环境变量 `STONEAGE_NO_UPDATE_CHECK=1`，见 `docs/client.md`「升级」 |

如果账号和密码都已提供，启动后直接登录，不停在登录页；再加上 `--character`，就直接进入游戏。这些参数主要供开发和调试用。客户端**不在磁盘上保存密码**。

## 登录页

```text
                ┌石器时代──────────────────────────────┐
                │                                      │
                │  线路   本地 127.0.0.1:7065       ◂▸ │
                │  账号   probe_                       │
                │  密码   ••••••                       │
                │                                      │
                │   [ 登录 ]   [ 注册 ]   [ 退出 ]     │
                └──────────────────────────────────────┘
                ┌消息──────────────────────────────────┐
                │ 系统  正在连接服务端…                │
                └──────────────────────────────────────┘
```

- **表单**：屏幕居中一个带边框的表单，下面是消息面板，用来显示连接进度和错误，配色同 `docs/ui.md`。
- **按键**：`Tab`/`↑↓` 在各项之间移动，线路一栏用 `←→` 切换；在任意输入框按 `Enter` 都是登录；「退出」按钮或 `Ctrl+C` 打开退出确认，默认取消；`Esc` 在登录页不起作用。
- **线路**：线路列表来自客户端的配置文件，格式到实现时再定。一期只有一条线路，默认选好：地址是 `127.0.0.1`、`localhost` 这类回环地址时显示「本地」，其他地址显示「线上」（发布版默认是「线上」）。
- **账号与密码**：格式见 `docs/protocol.md` 的 `register`，客户端先做同样的检查再发送。密码显示成 `•`。
- **登录失败**：留在登录页，清空密码，账号保留，在消息面板显示原因：连不上服务端时由客户端写说明；其余情况直接显示服务端返回的 `error.message`（如账号或密码错误、账号已锁定及剩余时间）。

## 注册页

```text
                ┌注册账号──────────────────────────────┐
                │  线路       本地 127.0.0.1:7065   ◂▸ │
                │  账号       ____                     │
                │  密码       ••••••                   │
                │  确认密码   ••••••                   │
                │                                      │
                │        [ 注册 ]     [ 返回 ]         │
                └──────────────────────────────────────┘
```

- 先在客户端本地检查账号、密码格式和两次密码是否一致，检查通过后再发送 `register`。`hello` 响应里 `register_enabled` 为 `false` 时，「注册」按钮置灰。
- 注册成功后回到登录页，账号自动填好，密码清空，由玩家自己登录一次。
- 注册失败时留在注册页，消息面板显示服务端返回的 `error.message`，如账号已存在、注册太频繁。

## 角色选择

```text
┌选择角色 · probe──────────────────────────────────────────────┐
│ 栏位  名字         Lv   所在地                                │
│                                                              │
│ > 1   ProbeHero    12   萨姆吉尔村                            │
│   2   (空)                                                   │
└──────────────────────────────────────────────────────────────┘
  Enter 进入/创建   d 删除   Esc 返回登录
```

- 用 `Table` 显示 `characters` 响应里的 `max_slots` 个栏位，没有角色的栏位显示“(空)”；表头黄色，选中行加粗并带 `> ` 前缀。所在地显示 `location.map_name`。
- 选中已有角色按 `Enter` 打开角色动作，选“进入游戏”再按 Enter 才发送 `enter_world`；选中空栏位按 `Enter`，进入创建角色。
- **删除**：角色动作里的“删除角色”（兼容 `d` 快捷键）打开专用表单。完整名字逐字相同后进入按钮选择，默认取消；明确选“删除”才发送 `delete_character`，成功后刷新列表。在途保持表单，不重复提交；错误保留原输入。

## 创建角色

分三步，顶部用 `Tabs` 显示当前步骤：`1外形  2名字与属性  3出生地`。`Enter` 进入下一步，`Esc` 回到上一步；在第一步按 `Esc`，回到角色选择。

### 1. 外形

- **外形**：12 种，用 `List` 列出，对应协议字段 `appearance.body`。选中的外形只用黄色加粗高亮，不画 `>` 箭头。
- **颜色**：用 `←→` 切换，对应 `appearance.color`（0–3）。同一个颜色序号在不同外形上是不同的颜色，客户端按下表显示颜色名。外形名和颜色名取自原版服务端 `gmsv/char/char_data.c` 中 `MetamoList` 表的注释：

  | 外形 | 名称 | 颜色 0 | 颜色 1 | 颜色 2 | 颜色 3 |
  |---|---|---|---|---|---|
  | 0 | 小矮子 | 红 | 绿 | 黄 | 灰 |
  | 1 | 赛亚人 | 灰 | 红 | 绿 | 黄 |
  | 2 | 辫子男孩 | 灰 | 黄 | 绿 | 红 |
  | 3 | 酷哥 | 红 | 绿 | 黄 | 灰 |
  | 4 | 熊皮男 | 灰 | 绿 | 黄 | 红 |
  | 5 | 大个 | 红 | 灰 | 黄 | 绿 |
  | 6 | 小矮妹 | 绿 | 黄 | 灰 | 红 |
  | 7 | 熊皮妹 | 绿 | 红 | 黄 | 灰 |
  | 8 | 帽子妹 | 黄 | 红 | 绿 | 灰 |
  | 9 | 短发夹妹 | 灰 | 黄 | 红 | 绿 |
  | 10 | 手套女 | 红 | 灰 | 绿 | 黄 |
  | 11 | 辣妹 | 黄 | 绿 | 红 | 灰 |

- **眼型、嘴型、图像编号**：界面上不显示，也不让玩家选；客户端固定发默认值 `appearance.eye = 0`、`appearance.mouth = 0`。协议和服务端仍支持 0–4，以后要开放时再加回界面。

### 2. 名字与属性

```text
┌名字与属性──────────────────────────────────────────────────┐
│ 名字    勇者小明_                                           │
│                                                            │
│ 能力点 剩余 4                     属性点 剩余 0             │
│ 体力   ████████░░░░  8            地 ██████░░░░  6          │
│ 腕力   ████░░░░░░░░  4            水 ████░░░░░░  4          │
│ 耐久力 ████░░░░░░░░  4            火 ░░░░░░░░░░  0  (与地互斥)│
│ 速度   ░░░░░░░░░░░░  0            风 ░░░░░░░░░░  0  (与水互斥)│
└────────────────────────────────────────────────────────────┘
  ↑↓ 选择项目   ←→ 减少/增加   Enter 下一步
```

- **名字**：规则见 `docs/protocol.md` 的 `create_character`（1–16 个字符、不能含空白、不能含敏感词、全服唯一）。客户端先检查长度和空白，最终以服务端结果为准。
- **能力点**：体力、腕力、耐久力、速度这 4 项，共 20 点。服务端只要求总和不超过 20，但界面在点数没分完时提示“还有 N 点未分配”，并要求玩家二次确认才能进入下一步。
- **属性点**：地、水、火、风这 4 项，共 10 点，必须全部分完。地和火只能有一个大于 0，水和风也一样，每项最多 10 点。给另一个允许的属性加点时，如果已经没有剩余点数，就从第一个非零的属性挪 1 点过来。这条规则来自原版 `LOGIN.CPP`。
- **显示**：点数用 `Gauge` 或 `LineGauge` 显示；互斥而不能加点的项目，用灰色加说明文字标出。

### 3. 出生地

- 中间显示 `docs/map.md` 的世界地图，四个出生村用黄色 `X` 标出，当前选中的一个高亮显示；用 `←→` 切换，`Enter` 提交。
- 出生地编号：0 萨姆吉尔、1 玛丽娜丝、2 加加村、3 卡鲁它那。
- 提交 `create_character`（字段见 `docs/protocol.md`）。成功后回到角色选择并刷新列表；失败时回到出错字段所在的那一步，在消息栏显示 `error.message`。

## 客户端版本门槛（STAGE-100）

握手时服务端会检查客户端版本（`docs/protocol.md` 5.1），登录页按下列方式处理：

- **版本过旧**：服务端回复 `CLIENT_TOO_OLD` 并断开。消息面板显示服务端的 `error.message`，例如「当前版本 0.1.0 过旧，需要升级到 0.2.0 以上，运行 stoneage update」，留在登录页，不自动重连。玩家升级后再按登录即可。
- **有新版本**：握手响应里的 `latest_client` 比当前版本新时，消息面板提示一行「有新版本 0.2.0，运行 stoneage update 升级」。这一条和启动后台检查的提示合并，同一次运行只出现一次。

登录、注册、角色选择这些表单页的消息面板，正文超过面板宽度时换行、续行缩进到标签后面（和「消息」页一样），保证升级命令这类长提示在屏幕上看得到全；世界页的底部消息栏仍是一行一条、过长截断（`docs/ui.md`「消息」）。
