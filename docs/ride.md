# 骑乘（设计，STAGE-121）

骑乘 = 学会骑乘课程 → 把合适的宠物骑上去 → 战斗里人宠合成一个单位。规则对照原版服务端源码，协议见 `docs/protocol.md` 5.47–5.49，界面见 `docs/ui.md` 宠物页，战斗见 `docs/battle-ui.md` 与 `docs/protocol.md` 第 10 章。

按三个需求依次开发：

| 需求 | 内容 | 依赖 |
|---|---|---|
| STAGE-122 | 骑乘训练师 NPC + 骑乘等级（`ride_level`）+ 课程 | 本文 |
| STAGE-123 | `pet_ride` / `pet_unride`、`state=ride`、联动限制、客户端宠物页 | STAGE-122 |
| STAGE-124 | 战斗：人宠合体、数值融合、伤害分摊、经验 | STAGE-123 |
| STAGE-149 | 骑乘与出战可并存：骑着 A 时可以把 B 设为出战，战斗里 A 合体、B 独立上格子 | STAGE-124 |

## 1. 和原版不同的地方（用户已定）

| 项 | 原版 | 这里 |

## 2. 骑乘等级与课程

出处：`gmsv/npc/npc_riderman.c`、`data/npc/family/riderman.conf`。

- 角色有 `ride_level`（原版 `CHAR_LEARNRIDE`），取值 0 / 40 / 80 / 120 / 200，新角色 0。**能骑的宠物等级上限就是它**：宠物等级必须 ≤ `ride_level`（200 即不限）。
- 四级课程**必须按顺序**学：

| 课程 | 学会后 `ride_level` | 学费 |
|---|---|---|
| 初级班 | 40 | 0 |
| 中级班 | 80 | 0 |
| 高级班 | 120 | 0 |
| 特级班 | 200 | 0 |

- 已学会该级（`ride_level` ≥ 该级）：“你已经学会X级班了呀。不需要再学了。”
- 没学前一级：“你必须先学过X级班才能来Y级班唷。”（X 是前一级）
- 成功：“恭喜你！你已经完成骑乘X级班了。可以骑乘 LvN 以下的宠物，请小心骑乘喔！”（特级班为“可以骑乘所有等级的宠物”）
- 学习不需要队伍、物品，不扣石币。

### 骑乘训练师 NPC

- 类型名「骑乘训练师」（原版 `riderman`），每村一个：萨姆吉尔（原版 floor 1040，坐标 61,45）、玛丽娜丝（2030，55,16）、加加（3030，50,21）、卡鲁它那（4030，16,35）。名字都叫“骑乘训练师”。收录进 `server/gamedata/npcs.tsv`（`tools/gen-npcs.py`），NPC 数量写死的地方一并更新。
- `talk` 弹 `npc_window` 菜单（台词逐字取自 `riderman.conf`，由 `gen-npcs.py` 生成 `npc-riderman.json`）：
  1. **关于骑乘宠物** → 子菜单「学习骑乘的技能 / 骑乘用宠物的条件」，各弹一页说明；
  2. **查询可骑乘的宠物** → 列出当前角色能骑的宠物种族（见 §3 第 7 条），原版是客户端的“可骑乘宠物”窗口（`WINDOW_MESSAGETYPE_SHOWRIDEPET`），这里改成文字页；
  3. **学习骑乘宠物** → 课程菜单（初/中/高/特），选一级直接学（原版有“学费确认”页，免费后保留确认页，写“学习骑乘X级班不需要学费。你确定要学习吗？”）。
- 特级骑乘训练师（`riderman2.conf`、家族外的特殊 NPC）原版被注释掉，不收录。

## 3. 上骑条件

出处：`gmsv/char/family.c` 的 `FAMILY_RidePet`。按这个顺序检查，第一条不满足就拒绝：

| # | 条件 | 错误码 | 说明文字（`error.message`） |
|---|---|---|---|
| 1 | 不在战斗中 | `IN_BATTLE` | — |
| 2 | 不在交易中 | — | 交易还没做，先不检查，做交易时补错误码 |
| 3 | 栏位有宠物 | `NO_PET` | — |
| 4 | 现在没有在骑别的 | `ALREADY_RIDING` | 已经在骑 N 号栏的宠物，先下骑 |
| 5 | 这只不是出战宠、待命宠（状态为 `rest`） | `PET_NOT_REST` | 出战/待命的宠物不能骑，先休息 |
| 6 | `ride_level` ≥ 宠物等级 | `RIDE_NOT_LEARNED` | 你目前只能骑乘等级小于等于 N 级的宠（N=`ride_level`）；`ride_level` 为 0 时写“你还没有学过骑乘，先去骑乘训练师那里学习” |
| 7 | 宠物忠诚 ≥ 100 | `RIDE_LOYALTY_LOW` | 该骑宠的忠诚小于 100 |
| 8 | 人物等级 + `ride_level_gap` ≥ 宠物等级 | `RIDE_LEVEL_GAP` | 你最高只能骑宠等级比你大 5 级的宠 |
| 9 | 宠物转生次数 ≤ 2 | `RIDE_TRANS_LIMIT` | 转生次数超过 2 次的宠物不能骑（STAGE-196 起检查；宠物转生窗口已在 STAGE-236 做完，次数由转生写入，也可由管理命令设定） |
| 10 | （人物外形，宠物种族）在骑乘表里 | `RIDE_NOT_MATCH` | 这只宠物不适合你的外形 |

- 倒下的宠物（HP 0）原版不检查，这里也**不**检查；因为战斗里宠物血量为 0 时伤害全由人承担，规则本身成立。
- `ride_level_gap` 是服务端配置（`.env`/配置文件，见 `docs/server.md`），默认 5。
- 忠诚是服务端现算的值（`docs/ui.md` 宠物页，公式见 `gamedata.Loyalty`），不是存的：人物等级 × 人物魅力 × 1.1 ÷ (宠物等级 × MODAI) × 100，截到 100 为止。**MODAI 按宠物种族不同**：MODAI 为 100 时新角色（魅力 60）1 级配套宠的忠诚是 66，到 2 级才够 100；但出生配套的虎和雷龙 MODAI 是 270、300，忠诚是 `人物等级 × 66 ÷ 270 × 100` 和 `人物等级 × 66 ÷ 300 × 100`，要到 5 级（忠诚 122、110）才够 100。这是原版公式的结果，不是 bug。

### 骑乘表（第 10 条）

只取原版**原生**的 `ridePetTable`（`gmsv/char/char_base.c`，不含 `_GM_METAMO_RIDE` 的 GM 行、族长/巴士形象行、`ride.txt` 位掩码扩展）。有效的搭配只有两类，和出生配套宠（`server/gamedata/newplayerpets.go`）是同一张表：

- **虎**：按人物**身体颜色**。红 → 格鲁西斯（模板 193）、绿 → 贝鲁卡（191）、黄 → 金格萨贝鲁（194）、灰 → 贝鲁伊卡（192）。判定看人物身体图像落在 `metamoImage` 的哪一行。
- **雷龙**：按人物**外形**。12 种外形各对应一种，模板 251 布洛多斯、252 布林帖斯、253 布拉奇多斯、254 斯天多斯、255 邦恩多斯，具体哪种外形对哪种以 `dragonByBody` 为准。

实现时在 `server/gamedata` 新增 `RideAllowed(bodyImage, speciesID) bool` 与 `RideableSpecies(bodyImage) []int`（后者给训练师的“查询”页用），直接复用 `metamoImage / tigerByRow / dragonByBody`。

## 4. 上骑、下骑

- 上骑成功：宠物 `state` 变为 `ride`，`pets_changed` 推送（包含 `ride` 状态），客户端宠物页状态列显示“骑乘”。人物的外形图在 TUI 里没有对应物，不处理。
- 下骑：`pet_unride`，宠物 `state` 回到 `rest`。没有骑时下骑：成功，不改任何东西、不推送（同 `pet_state` 设成相同状态）。
- 状态落库（`character_pets.state`），重连、重启保留。进入世界时若骑乘的宠物仍在栏位上，战斗/地图照常按骑乘处理。
- 战斗中、交易中不能上下骑；战斗里被击落马（落马术等）见 §7，本期不做。
- 骑乘时其他宠物照常可以设出战或待命（`pet_state`），骑着的那只不受影响；战斗里出战的宠物上格子，骑着的仍合体（§5）。

## 5. 战斗中的骑乘

出处：`gmsv/battle/battle_event.c`（`BATTLE_getRidePet`、`BATTLE_adjustRidePet3A`、`BATTLE_DamageCalc`、`BATTLE_DamageSub` 的分摊段）、`battle/battle.c`（速度、经验）。开启的是 `_BATTLE_NEWPOWER` 分支。

- **合体**：骑乘的宠物**不是单独的战斗单位**。己方人物的 `unit.ride = true`；战斗开始时 `battle_start` 里不出现这只宠物。**出战的另一只宠物**（STAGE-149）照常上格子，是独立单位，有自己的宠物指令（`needs` 里有 `pet`，协议 10.4）；没有出战宠物时 `needs` 里没有 `pet`。骑着的宠物不会被换上场，出战的宠物也不会被顶掉。没有出战宠物时，骑乘不替玩家顶上其他宠物（没有骑乘时“第一只顶上”的规则不适用，要玩家自己用 `pet_state` 设）。
- **数值融合**（人=人物战斗数值，宠=骑乘宠的战斗数值，`float` 运算后向下取整）：

| 数值 | 融合后 |
|---|---|
| 攻击力 | 近战：人×0.8 + 宠×0.8；投掷武器：人 + 宠×0.4 |
| 防御力 | (人 + 宠) × 0.7 |
| 敏捷（出手顺序） | 攻击方：近战 人×0.2 + 宠×0.8，投掷 人×0.8 + 宠×0.2；防御方：人×0.1 + 宠×0.9 |

融合后的值再进入现有伤害公式：被攻击时防御力再乘 0.70（`_BATTLE_NEWPOWER`），所以实际是 (人+宠)×0.7×0.7。属性（地水火风）不融合（`_BATTLE_NEWPOWER` 下只取人物）。

- **伤害分摊**：受到伤害 `damage`，若宠物 HP > 0：人承担 `damage × 宠防 ÷ (人防 + 宠防) + 1`，宠物承担 `damage − 人承担 + 1`（人防、宠防都 < 1 时按 1，防止除零）；宠物 HP 为 0 时全部由人承担。反射、吸收类效果按同一分摊处理。
- **回复分账**（STAGE-257，原版 `battle_magic.c` 的 `BATTLE_MultiRecovery`，`_MAGIC_REHPAI` 骑乘分支）：战斗内回复 HP（治疗精灵、战斗中的道具）时，骑着宠物的人物把总回复量按**缺口水位**拆给人和骑宠：人物那份 = 总量 × (人物缺口 × 100 ÷ 双方缺口和) ÷ 100（两步整数运算），骑宠得到其余部分。人、宠各自封顶自己的最大血量，某一方封顶后多出来的**不回灌**另一方。双方都满血时人物那份为 0。骑宠血量回到 1 以上时清掉倒下标记，之后的伤害又分摊给它（救回后继续骑着）。分账依据是缺口，不是最大血量，也不看等级。MP 不参与，气力照旧只给人物。战斗外的回复（`magic_field.c`）不分给骑宠。例（治愈 Lv1，威力 80）：人 100/200、宠 50/100 → 人得 52、宠得 28；人 200/200（满）、宠 50/100 → 人得 0、宠得 50（封顶）；人 100/200、宠 100/100（满）→ 人得 80、宠得 0；人 100/200、宠 0/100（倒下）→ 人得 40、宠得 40 并救回。战报只写人物的 `heal`，骑宠的回复量由战斗结束的 `pets_changed` 带出（协议不单独显示骑宠回血）。
- **经验**：击杀得到的经验，人物照旧；骑乘的宠物另按“同一套等级差修正后的经验 × 0.6”获得（`battle.c` 的 `nowexp *= 0.6`），并且击杀数 +1。出战的另一只宠物（若有）按它自己的等级算等级差（STAGE-244，不再复用人物那份），等级低于人物时拿到的经验可以比人物多。宠物升级、写回数据库的规则同普通出战宠。
- **宠物血量**：战斗结束写回骑乘宠物的血量；宠物 HP 降到 0 时，原版代码里没有自动下骑的处理，继续骑着（伤害全由人承担，见上）。
- **战斗中的可见性（STAGE-250）**：骑宠不是单位，它的血量由己方人物单位的 `mount` 对象下发（`protocol.md` 10.2）：`name`、`hp`、`max_hp`、`hp_pct`，`battle_start` 与 `joined` 给初始值，每回合 `battle_round` 的 `state` 里的人物项刷新，分摊后的血量当回合就能看到。骑宠归零后 `mount.hp_pct` 为 0，人物仍带 `mount` 且 `ride` 为 `true`。客户端把它显示在顶栏第二行（`docs/battle-ui.md` 总体布局）。
- **逃跑、换宠、召唤宠物**：骑乘时 `battle_command` 的换宠无效（原版 `BattleCommandDispach` 把骑乘栏位的换宠当成不换）。

## 7. 不做（本期以后另议）

- **落马**：被敌方“落马术”命中（50% 概率）、媚惑、乌力化等会让人落马，战斗结束时提示“落马了”。依赖这些敌方技能，新服务端现在都没有，先不做；做的时候 `battle_round` 里要有落马事件，战后 `state` 回 `rest`。
- 驯骑装备（`ITEM_RIDE`）、族长专用骑宠（`FM_LEADER_RIDE`）、会员骑宠（`VIP_RIDE`）、`ride.txt` 的 `LOWRIDEPETS` 位掩码、GM 骑所有宠、白虎等 modern patch 映射：私服扩展，不是原版 2.5。
- 骑乘外形图（`rideNo`）：TUI 没有精灵，只在石器百科有展示，百科已有。

## 8. 验收（整体）

1. 新角色（0 级骑乘）去训练师，依次学完四级，`status.ride_level` 依次变成 40 / 80 / 120 / 200，跳级、重复学都有提示；
2. 角色升到 2 级后，把配套虎或配套雷龙骑上去：宠物页显示“骑乘”，再骑下来回到“休息”；
3. 换颜色不对的虎、等级过高的宠、忠诚不够的宠，各有明确提示（对应 §3 的错误码）；
4. 骑乘中放生、寄放、卖宠、改状态被拒；
5. 骑着虎打一场野怪（没有出战的宠物）：人物卡片有“骑”标记，没有宠物指令；伤害由人宠分摊，击杀后宠物有 0.6 倍经验；
5a. 骑着虎再设一只宠物出战（STAGE-149）后开战：人物卡片有“骑”标记，出战宠单独一个单位、有自己的宠物指令，虎不上格子；想把骑着的虎设为出战或待命，被拒绝并说“骑乘中的宠物不能改状态，先下骑”；想骑已出战的宠物，被拒绝（`PET_NOT_REST`）；
6. 协议用例（`docs/protocol/cases/`）、服务端测试、客户端场景、冒烟同步更新。
