# 自动战斗设置（STAGE-173）

需求：STAGE-173
《【系统】自动战斗基础设置与方案管理》。本文是这份设置在客户端里的落地说明：入口、五栏、出招优先级、
方案文件。托管的界面与状态见 `docs/battle-ui.md`「观察模式与托管」。

## 一句话

玩家把「人物和战宠每回合做什么、什么时候补血补气、打到什么程度停、出招多快」保存成方案，
托管每回合按方案出一招。**仍然是客户端出招**：发的是和手动完全一样的 `battle_command`，
服务端照常校验和结算，协议没有新增消息。

## 入口与按键

| 入口 | 路径 |
| --- | --- |
| 顶层菜单（主入口） | `Esc` 游戏菜单 → 「自动战斗」（第 10 页，`page 10` / `page 自动战斗` 也能进） |
| 系统页 | 系统 → 「自动战斗设置」（第 11 行） |
| 战斗中 | `Tab` 战斗控制 → 「自动战斗设置」 |

三处打开的是**同一份**配置。顶层页进去就是五栏编辑器（Esc 回游戏菜单）；
系统页和 Tab 面板里是同一块编辑器叠在行表上（Esc 先回行表 / 面板）。
数字键只到 9，所以顶层页没有数字快捷键。

| 键 | 作用 |
| --- | --- |
| `Tab` / `Shift+Tab` | 换栏（行动 / 恢复 / 挂机 / 捕捉 / 方案与播放） |
| `↑` `↓` `Home` `End` | 在当前栏里选行 |
| `←` `→` | 调整这一项（开关、枚举、数值按 5 一档、精灵/技能栏位循环） |
| `Enter` | 执行：新建/删除方案、保存并应用、放弃改动 |
| `Esc` | 有改动时问「继续编辑 / 保存并应用 / 放弃改动」（默认继续编辑）；没改动直接退出 |

- 编辑期间本机自动出招与结果自动关闭**暂停**（服务端倒计时照常），给玩家改配置的时间。
- 不可用的项变灰，`Enter` 说明原因（例如人物动作不是「精灵」时，精灵栏位不能选）。
- 普通字符不抢页面按键；命令仍从 `/` 进。

## 五栏

| 栏 | 项 |
| --- | --- |
| 行动 | **默认攻击目标**（合击顺序 / 随机）、人物常规动作（攻击/精灵/防御）、人物精灵、首回合单独设置、首回合人物动作与精灵、战宠常规动作（攻击/技能/防御）、战宠技能、首回合战宠动作与技能 |
| 恢复 | 人物自动补血 + 门槛（默认 30%）、**补血精灵**（自动 / 指定身上的某一个）、战宠自动补血 + 门槛（默认 30%）、人物自动补气 + 门槛（默认 20%，关闭）、**补气物品名单**（空＝不限）、回复来源顺序（先道具 / 先精灵，**默认先精灵**：新建方案和内置兜底方案都是先精灵；已存的方案照存档里写的，不被改掉；存档里没写这一项的按先精灵）。自动认补血精灵时按效果认（治愈 / 滋润 / 恩惠都认，己方全体的恩惠优先）。**自动复活**（开，默认开：出战宠倒下时复活它）、**复活来源**（自动（先精灵后道具）/ 只用精灵 / 只用道具，默认自动）、**复活后优先带防御的精灵**（开，默认开）；详见下文「自动复活（STAGE-262）」；**战后自动吃肉回血**（开，默认开）、**战后吃肉门槛**（5–95%，默认 90%）、**战后自动丢弃肉类道具**（开 / 关，默认关，从关切到开要确认）；详见下文「战后吃肉与丢弃（STAGE-260）」；**打输后提示并停止**（默认开，STAGE-265，见下文「打输后提示并停止」） |
| 挂机 | **连续遇敌**（只读，真实开关）、**遇敌区域**（只读，当前选区）、自动逃跑 + 自身血量门槛 + **逃跑敌人名单**、补给不足时停止、人物目标等级、战宠目标等级、队伍最低人数 |
| 捕捉 | 自动捕捉、**抓宠方式**（边战斗边抓 / 逃跑抓，默认边战斗边抓，见下文「抓宠方式」）、削血到 HP 比例（5–95%，再多一档 **满血抓**，见下）、**捕捉目标名称**（Enter 编辑，可用 `\|` 一次输入多个，空＝不限）、等级上下限（Enter 手输，0＝不限）、**资质筛选**四行（体力 / 腕力 / 耐久力 / 速度：不限、0、−1、−2、−3，`←→` 循环）、**抓宠丢弃记录**（末尾一行，Enter 打开只读列表，见下） |
| 方案与播放 | 当前方案（←→ 切换）、新建、删除（需确认）、保存并应用、放弃改动、结果窗口自动继续、**出招延迟**、**手动让位** |

数值范围：HP/MP 门槛 5–95%（步进 5；捕捉的削血到另有 100，见「自动捕捉」），等级 0–200（0 表示不限；`←→` 步进 5，`Enter` 可手输 0–200 的整数，见下），队伍人数 0–10（0 表示不限）。

### 默认攻击目标（STAGE-173 追加）

| 取值 | 行为 |
| --- | --- |
| **合击顺序**（默认） | 敌方**前排从上到下、再后排从上到下**取第一个活着的：`18 → 16 → 15 → 17 → 19 → 13 → 11 → 10 → 12 → 14`（敌方侧的协议号）。人物和战宠取同一个目标，同回合同目标才可能被判成合击 |
| 随机目标 | 每次出招在活着的敌人里随机一个 |

- 「从上到下」用的是战场显示顺序（`slots::ROW_ORDER`），和屏幕上看到的编号 1→5、6→10 一致。
- 每回合重新算：目标倒下后自然顺延到下一个，不需要额外配置。
- 分身（服务端代打）不由客户端下指令，客户端只能控制人物和战宠。组成分身队时（`party_clone`）带上当前生效的方案（STAGE-195），服务端的分身按这份方案出招（协议 5.57）：目标、补血、首回合、常规动作和自动捕捉回避照着做；逃跑、补气、换宠、出招延迟、停止保护分身不做。方案在组队那一刻收下，之后改方案要重新组队才生效。没带方案或版本不对，分身就是默认的普通攻击。

### 出招节奏（STAGE-173 追加）

托管原来把「收到 `battle_turn` 后等 1500ms 出招」写死在代码里，实际用起来觉得慢。
现在两个值都进方案、可在「方案与播放」栏用 ←→ 调：

| 项 | 档位 | 默认 | 说明 |
| --- | --- | --- | --- |
| 出招延迟 | **即时（0）** / 300 / 500 / 1000 / 1500 / 3000 ms | **500 ms** | 收到回合结算后等多久自动出招；选「即时」就是算完立刻发下一条，不等 |
| 手动让位 | 1000 / 2000 / 3000 / 5000 / 8000 ms | 3000 ms | 玩家按键或打命令后，自动出招顺延多久 |

- 两者独立：延迟调小只是“托管更快出手”，按键接管时仍按让位时间退开，不会因为延迟小就抢不到手动机会。
- 改完要「保存并应用」，**从下一个未提交的决策阶段**生效；已经排好的这一次出招不重排（想立刻用新延迟就在战斗外改好再开挂机）。
- 只影响本机客户端出招的时机，不影响服务端 30 秒回合倒计时和结算。
- 「即时」是 0ms（不是 50ms）：`battle_turn` 一到就算下一招，主循环战斗中是 33ms 一帧，
  所以最多差一帧就发出去。嫌太快想留手动窗口就往右调一档。

**结算回放的播放方式不在这里设**（STAGE-173）：1× / 2× / 跳过统一在系统页的「默认回放」里切，
战斗中没有 `Space` / `f` 快捷键。选「跳过」时下完指令直接出结果、进下一回合。

### 托管中的战斗画面（STAGE-173 追加）

一开托管，战斗界面就不再请你选行动：

- 轮到本机下指令时，指令条**不再摆动作网格**，改成
  `自动挂机中 · 0.4s 后出招 · Tab 设置 · 8 停止自动挂机 · 7 停止自动遇敌`，
  下面一行写「要手动打：先按 8 停止，这一场继续手动打完」。
- 数字、方向键、Enter、Esc 被拦下并写一条提示，不改选择、不发指令；文字出招命令（`a e3` 之类）同样被拒。
- 仍然有效的是两个出口：`8` 停止自动挂机（同时按现有规则关后续遇敌）、`Tab` 打开战斗控制面板
  （里面有「自动战斗设置」和「自动挂机：开／关」）；底部提示行在自动战斗时统一列 `8 停止自动挂机`、`7 停止自动遇敌`、`Tab 自动战斗设置`。
- **`8` / `7` 在哪个阶段都认**：下指令、结算、等待，甚至 `Tab` 面板或本设置页开着时按下都有效；
  只有正在打字时（命令栏、输入行有字、暗号窗口、确认框、方案命名、名单录入）才算普通字符。
  - `8` 停止自动挂机（按规定单向连带关闭后续遇敌）；
  - `7` **只**停自动遇敌，自动出招继续，这一场照常打完。
- 战斗**结束后**（没有战斗在跑）`8` 仍是普通的数字键，不会停挂机；那时用 `Tab` 面板或系统页停。
- 结算 / 等待阶段指令条写「自动挂机中 · 8 停止自动挂机 · 7 停止自动遇敌」。
- 停止后本场继续，按键立刻恢复成正常选招；想接着挂机再按一次 `8` 或从面板/系统页开启。
- 结算回放阶段不受影响：`Space` 跳过、`f` 倍速照常可用。

## 出招优先级（全部已接入）

固定顺序，每一步只产出一条指令；配置关着或来源没有就往下走：

0. **中断判断与停止保护**（`auto_tick`，先于出招）：断线、agent 接管、手动停止、停止保护命中。
1. **自动逃跑**（M10）：条件命中就逃，其余都不做。逃跑排在补血前面，且先请求关闭后续遇敌。
   例外：**逃跑抓**（STAGE-285）且本场有合格捕捉目标时，敌人名单不让位就逃不了——名单判定跳过，抓宠优先；
   自己血量到逃跑门槛仍然先逃（保命）。
2. **自动复活**（STAGE-262）：出战宠倒下、来源可用就先救它，排在人物补血前面（见下文）。
3. 人物自己补血（≤ 门槛）：按来源顺序在回复道具与补血精灵之间取（精灵可以是「自动」认，也可以是玩家指定的那一个）。
4. 战宠补血（≤ 门槛）：由**人物出手**——喂药或放精灵，顺序同第 3 步的「回复来源顺序」；宠物自己只能攻击/技能/防御。
   单体精灵（治疗他人，如滋润）目标指到出战的宠，己方全体的（恩惠）不带目标、一次回人物和宠物；倒下的宠不补，交给第 2 步。
5. 人物补气（≤ 门槛）：用背包里、且在「补气物品」名单里的补气道具。
6. **自动捕捉**（M13）：先削血、到门槛再捕捉；捕捉期间战宠防御。
   **逃跑抓**（STAGE-285）时，本场没有合格目标就在这一步之前直接逃（不算「自动逃跑」的条件，也不关遇敌）。
7. 首回合动作：只在 `turn == 1` 用一次，被前面几步占用就不补做。
8. 常规动作：按「默认攻击目标」攻击；精灵/技能按栏位与名字核对后使用；没有活敌就防御。

失效与兜底：

- 精灵或技能**栏位还在但名字对不上**（换装、重学、换宠）→ 不硬套旧栏位，提示「已失效，改攻击」。
- MP 不够、`ally_down`（复活类）→ 不进常规动作的自动候选（复活由第 2 步「自动复活」单独处理）。
- 复活被服务端拒绝 → 精灵栏位 / 道具槽位本场拉黑，同一只宠每场最多试 2 次（见下文）。
- 同一阶段最多重试 3 次、每次隔 300ms；道具被拒的槽位本场拉黑（沿用 STAGE-42）。
- **逃跑被拒不重试**：下一回合重新判断条件，避免同一阶段反复发无效指令。

## 补血精灵（M06 追加）

「恢复」栏的「补血精灵」决定补血时用哪一招，`←→` 在 **自动 → 身上的每个精灵 → 自动** 之间循环：

| 取值 | 行为 |
| --- | --- |
| **自动**（默认） | 按服务端给的效果文字认回复精灵（以「回复自己 HP」「回复己方一个 HP」「回复己方全体 HP」开头，含治愈、滋润、恩惠；旧服务端没有效果文字时退回按名字认），多个里先取**己方全体**的，再取**栏位最靠前**、MP 够的那个 |
| 指定某一个 | **只用它**。栏位和名字都对得上才生效；MP 不够时**不会偷偷换成别的治愈精灵**，直接走道具 |

- 列表就是角色当前的精灵列表（角色页/战斗里精灵栏看到的那一份）；装备或精灵变了，这一项会显示「（已失效）」，托管回落到「自动」。
- 只影响补血；攻击用的精灵仍然由「人物常规动作 = 精灵」+「人物精灵」决定。
- 战宠补血也读这一项，但**只能对自己**的精灵（治愈的精灵，效果是「回复自己 HP」）落不到宠物身上：指定成这类时
  宠物这一步不用精灵、直接喂药；「自动」则会优先挑己方全体的恩惠，没有全体才挑治疗他人的单体。

## 自动逃跑（M10）

两个触发条件是**或**的关系，满足任一条就逃：

| 触发 | 说明 |
| --- | --- |
| 自身血量 ≤ 门槛 | 默认 15%，5–95% 步进 5；只看自己，不看战宠 |
| 场上敌人命中名单 | 名单按名字**包含匹配**，满血也逃。名单为空表示只看血量 |

- 逃跑前先发 `encounter off`（关后续遇敌）；已经关着或正在关就不重复请求。
- 本场**不允许逃跑**（`battle_start.allow.escape` 为假）时不发逃跑，改照常打完，并在战斗记录里写「本场不能逃跑（原因）」。
- 服务端拒了逃跑：不重试，下一回合重新判断；成功逃离后本机自动出招**停止**，要不要重开由玩家决定。
- 与停止保护同时命中时**停止保护优先**（它在出招之前判断，直接停机，不会先跑一次）。

## 停止保护（M11）

命中任一条件就立即可停：先关本机自动出招，再请求 `encounter off`，等服务端确认（流程与手动「停止自动挂机」完全一样）。
命中的原因会**全部**写在一行消息里，例如：

```
自动挂机已停止：停止保护（补给用完、人物已到 50 级、队伍 1 人，少于 3 人）
```

| 条件 | 判定 |
| --- | --- |
| 补给不足时停止（默认开） | 只算**战斗内**：补血/补气开着，而且当前已经低于门槛，却背包里没有可用的回复/补气道具、也没有治愈系精灵 |
| 人物目标等级 | 人物等级 ≥ 目标（0＝不启用） |
| 战宠目标等级 | 出战宠等级 ≥ 目标（0＝不启用） |
| 队伍最低人数 | 队伍人数 < 目标（0＝不启用；单人按 1 人算） |
| 抓宠时宠位满 | 自动捕捉开着且随身宠物已有 20 只（服务端 `MaxPetSlots`，STAGE-346） |

停止后**不自动重开**：补给、等级、队伍条件恢复也不会偷偷继续，要玩家自己按「自动挂机」。

## 自动捕捉（M13）

| 步骤 | 行为 |
| --- | --- |
| 筛选 | 名字包含匹配（空＝不限）+ 等级区间（0＝不限）+ 必须是 `monster` + 等级不超过人物 +5（服务端规则） |
| 选谁 | 合格目标里按「合击顺序」取第一个（前排从上到下、再后排） |
| 削血 | 目标 HP% 高于「削血到」→ 用**单体普攻**打它（不用群攻，也不换目标） |
| 捕捉 | 到门槛后改发 `capture`，目标是同一个单位 |
| 保护 | 只要有合格目标，本机战宠就一直**防御**；人物也不会兜底去打它 |
| 收尾 | 宠位满触发停止保护，不自动放生 |

**削血到「满血抓」（STAGE-264）**：`capture.hp_pct` 取 `100` 表示满血抓——不削血，合格目标满血也直接发 `capture`。
档位是在 5–95% 之上多的一档，`←→` 从 95% 再按一下就到；往下回到 95%。右侧说明写「不削血，直接抓；高血量目标几乎抓不到」，
原版抓宠概率随血量降低而升高，满血抓的成功率通常很低，这是预期。`hp_pct` 为 `100` 时判断「血量高于门槛就先削血」天然不成立，
所以不会误削血。旧方案里 5–95 的值读进来不变，没有改动存档格式。

**等级上下限手输（STAGE-264）**：行表上按 `Enter` 打开输入框，输入 0–200 的整数，`Enter` 确定，`Esc` 取消；0 表示不限。
`←→` 仍按 5 步进，所以 1–4 级用手输设（例如只抓 1 级：上下限都输 `1`）。拒绝的输入（提示里说明原因，输入框不关，可以改）：
空、负数（如 `-3`）、小数、文字、全角数字、超过 200。下限和上限都不是 0 时，**下限不能大于上限**：不接受、草稿不动，
输入框留着让玩家改（不会静默交换）。注意 `←→` 步进不做这个检查，可能把下限调到大于上限，那时捕捉一个也抓不到。

已知限制：普攻仍可能把目标打死（需求原文也说明不能保证必捕获）；本机只管人物和战宠，拦不住其他玩家或服务端分身。

## 抓宠方式（STAGE-285）

**说人话**：专抓某只宠的时候，遇到一堆不是目标的怪，是照常打完，还是干脆跑掉重新刷。

捕捉栏的「抓宠方式」决定这一场不值得打的怪群怎么办，`←→` 在两个取值之间循环，默认「边战斗边抓」：

| 取值 | 行为 |
| --- | --- |
| **边战斗边抓**（默认） | 与加这一项之前完全一致：每场都照常打，场上有合格目标就削血 → 抓 |
| **逃跑抓** | 本场**没有**合格捕捉目标：第一回合直接逃，专心刷新目标；本场**有**目标：照常削血 → 抓，且不逃 |

- 目标判定沿用上面「自动捕捉」那张表（名字、等级、必须是 `monster`、不超过人物 +5）。
- 逃跑抓的逃跑**不看「自动逃跑」开关**（它是抓宠策略，不是保命策略）；本场 `battle_start.allow.escape` 为假时不发，
  照常打完并在战斗记录写「本场不能逃跑（原因）」。
- **跑掉的那一场不关后续遇敌、也不停自动挂机**：日志写「逃跑抓：这一场没有目标，继续等下一场」，挂机继续刷。
  这是它与 M10 自动逃跑最大的区别——后者逃跑成功会停挂机并写「自动挂机已关闭：已经逃离战斗」。
- 判断按的是**方案**而不是单场：只要「抓宠方式」是逃跑抓，「自动捕捉」开着，那么这一场无论是没有目标主动跑、
  还是血量到门槛保命跑，**都不停挂机**（血由战后吃肉补回来，循环才能继续）；手动按逃跑也算。
- 只有打输（`lose`）照旧停挂机。
- 想让它一直刷下去，遇敌要用**连续遇敌**（开关式 `encounter on`，或按区域遇敌的 `infinite`）；
  **单次遇敌**（`once`，例如「1级宠物」的「直接开战」）本来就是一场打完就停，逃跑后服务端也会关掉遇敌（STAGE-152 的 `encounterOnceDone`），
  那时挂机还在、但不会再有下一场，这是遇敌模式本身的语义，不是逃跑抓的缺陷。
- 「自动捕捉」关着时这一行不能改（灰行，提示「自动捕捉关着」）。
- 旧方案文件没有 `capture.mode` 字段，读进来按「边战斗边抓」，行为与加这一项之前逐字一致。
- 只影响本机托管：服务端分身本来就不做逃跑（协议 5.57），方案推过去时带着这个字段但服务端不用。

## 资质筛选与丢弃记录（STAGE-264 第 4、5 条）

**筛选档位（`keep`）**：捕捉栏的「体力、腕力、耐久力、速度」四行，每项是一个档位阈值，取值 不限、0、−1、−2、−3，
`←→` 循环（不限 → 0 → −1 → −2 → −3 → 不限，从不限往左是 −3）。含义是**最差不低于**这一档：「体力 −2」表示体力档位不能比 −2 更差，−3 的抓到了就放生。
档位 0 为满，越负越差。四项都满足才留下（AND），只设一项就只看它。四项全不限就是没有这个功能时的行为。
−4 不单列，等同不限。行上写着「不限 / 0 档（满） / −2 档」和括注「最差不低于 −2 档；0 为满」。
自动捕捉关着时资质行不能改（和削血、等级行一样，提示「自动捕捉关着」）。

**什么时候发**：托管自动捕捉发 `battle_command` 的 `capture` 时，只带有阈值的项，即 `"keep": {"vital": -2}`（协议 10.5）；
四项全不限就**不带 `keep` 字段**，指令与之前逐字一致。手动输入的 `c` 命令不带 `keep`，只有托管的自动捕捉。
分身目前不自己捕捉（协议 5.57「不做」），所以方案里的 `keep` 现在只对本机自动捕捉生效；随 `party_clone` 推给服务端的方案会带上它，服务端暂不使用。

**被筛掉的怎么显示**：服务端抓成功后按 `keep` 筛，不达标的放生：`capture` 事件 `ok` 为真，没有 `pet_slot`，带 `discarded`。
客户端只看 `discarded` 是否存在来判断是否放生（不拿 `pet_slot` 缺失当依据；STAGE-268 起服务端 `pet_slot` 为 0 时也会出现，缺字段只表示“没有栏位”）。
放生的**不当作抓到宠物**：不占宠位、宠物列表不变、不触发新宠物的逻辑。战斗记录写一行
「抓到 乌力 Lv1，资质不合格已放生：体力 −1 < 0」（原因是服务端给的第一个不达标项），战斗画面上捕捉的结果写「放生」，并进丢弃记录。
宠位已满时服务端先看宠位、不看资质，所以宠位满的不会变成「抓成功被丢弃」；这时这次捕捉判失败（`ok` 为 false，怪物留在场上，协议 10.5、STAGE-267），和客户端的「抓宠时宠位满 → 停止保护」互补。

**丢弃记录页**：捕捉栏最后一行「抓宠丢弃记录」，`Enter` 打开只读列表，`Esc` 返回设置页。
每条三行：时间（`MM-DD HH:MM`，UTC）与名字、等级；四项资质，如 `体力 21(−1) 腕力 10(−4) 耐久力 15(−2) 速度 27(0)`；原因。最新在上，
光标可以上下选。列表第一行是「清空记录」，`Enter` 后弹出确认，**默认选「取消」**（`←→` 切换，`Enter` 执行，`Esc` 取消）。
超出 80×24 的长行按显示宽度截断并加 `…`，不错行；记录多时跟着光标滚动。

**记录文件**：与方案文件同一个服务器目录下的 `capture-log.json`，即 `<根目录>/<服务器>/capture-log.json`
（根目录同方案文件，见「方案文件」）。内容按角色分组：

```json
{"version": 1, "characters": {"勇者": [
  {"at": "2026-10-21 04:12:33", "name": "乌力", "level": 1,
   "quality": [{"stat": "vital", "points": 21, "tier": -1}, {"stat": "strength", "points": 10, "tier": -4},
               {"stat": "toughness", "points": 15, "tier": -2}, {"stat": "dexterity", "points": 27, "tier": 0}],
   "reason": "体力 −1 < 0"}
]}}
```

- `stat` 用协议的键名（`vital` / `strength` / `toughness` / `dexterity`），界面换成体力 / 腕力 / 耐久力 / 速度。
- `at` 是 UTC 时间；客户端不做时区换算。
- 每个角色最多 50 条，超出丢最旧的；清空只清这个角色的记录。
- 不进方案、不推给服务端；重启客户端后仍在。
- 文件读不出来（损坏）当空记录，界面照常打开；写的时候先把坏文件改名为 `capture-log.json.corrupt`，再写新的，玩家的原内容留着。

**不做 / 限制**：容量 50 条、记录只读，这次**不做成可配置**（需求里的「可配置」本次没做）。
记录只来自托管的自动捕捉：手动 `c` 命令不带 `keep`，服务端不会放生它抓到的宠物。

## 补气物品（M07）

「补气物品」是一份名字名单，空名单表示不限（按槽位最靠前的补气道具自动挑）。填了名单就只吃名单里的物品（包含匹配），
名单里的都不在背包时**不补气**，不会乱吃别的药。

## 名单怎么改

「逃跑敌人名单」「捕捉目标名称」「补气物品」三行按 `Enter` 打开行内编辑器：

| 键 | 作用 |
| --- | --- |
| 直接打字 | 填新名字（回车前不会生效）；可用 `\|` 或全角 `｜` 一次输入多个（如 `乌力\|凯比`） |
| `Enter` | 把输入的名字加入名单：按分隔符切开，去首尾空白，丢掉空项，去掉输入里和名单里的重复（提示里会说跳过了几个）；一个都加不进去时输入框保留 |
| `↑ ↓` | 在已有名单里选（选中的用【】标出） |
| `Delete` | 删掉选中的那一条 |
| `Esc` | 退出名单编辑，回到行表 |

改完仍要「保存并应用」。

## 自动复活（STAGE-262 B 段）

「恢复」栏三行：**自动复活**（开 / 关，默认开）、**复活来源**（自动（先精灵后道具）/ 只用精灵 / 只用道具，默认自动）、**复活后优先带防御的精灵**（开 / 关，默认开）。自动复活关着时后两行不能改（灰显并说明「自动复活关着」）。

- **只管出战宠**（单位号 `you + 5`）。人物自己倒下是战斗失败，不归这里。
- **触发**：出战宠倒下（血量 0）且人物还活着，复活开着，本宠试数没满 2 次。
- **精灵**：`status.magic` 里 `target_type == ally_down`、MP ≤ 当前 MP 的。**按 `target_type` 认，不按名字**。
  - 防御类（复活光 / 镜 / 守护，编号 280 / 290 / 300，`magic.tsv` 的 `revive_defend`）优先，前提是「复活后优先带防御的精灵」开着。
    认法：效果文字带「次物理攻击」（服务端 `defendText`：吸收 / 反射 / 无效都写这句）。效果文字为空（旧服务端）时才按名字含「复活光 / 复活镜 / 复活守护」认。
    普通复活精灵（50–53）的效果只写「复活己方一个倒下的单位，HP 约 N」，不带这句。
  - 同组里取栏位最靠前的。MP 都不够 → 不产出精灵，走道具。
- **道具**：背包 5–19 格里 `target_type == ally_down` 的（复活药 100 / 300 / 500、萨顿家的秘药、回魂之玉、真诚的眼泪、铁壁之石）。
  **数值取效果文字里的第一个数字**：「气绝回复成耐力300」→ 300，「从气绝回复成600的耐久力」→ 600。取**最小的那份先用**（100 → 300 → 500 → 600），同数字取槽位靠前的，别拿回魂之玉去救一只残血宠。
  道具不当回复药用：自动补血 / 补气 / 补给判断都跳过 `ally_down` 的道具。
- **每场限制**：同一只宠每场最多发 2 次复活指令（不论成败）；被服务端拒绝（`INVALID_TARGET` / `ITEM_UNUSABLE` / `NOT_ENOUGH_MP`）的精灵栏位或道具槽位本场拉黑，下一次重试换一个来源。不弹窗、不停止挂机。
- **没有可用来源**（没精灵、没药、MP 不够，或试满了）：不产出复活指令，照常补血 / 攻击，行为与改动前一致；同一只宠每场只写一行「复活失败」。
- **战斗记录**：`自动挂机：复活 贝鲁卡（复活精灵 Lv3）`、`自动挂机：复活 贝鲁卡（复活药(300)）`；没有来源时 `复活失败：没有可用的复活来源（贝鲁卡仍倒下）`，试满了则为 `复活失败：已试 2 次，贝鲁卡仍倒下`。
- **关着时**：完全不产出复活，与改动前逐字节一致。
- 旧方案文件（没有这三项）读入时按默认值生效；保存后文件里带上这三项。

## 战后吃肉与丢弃（STAGE-260）

「恢复」栏末尾三行：**战后自动吃肉回血**（开 / 关，默认开）、**战后吃肉门槛**（5–95%，步进 5，默认 90%）、**战后自动丢弃肉类道具**（开 / 关，默认关）。三行都是 `←→` 调整；恢复栏行数多于区域时，窗口跟着焦点行走（80×24 下也能看到最后一行）。

- **触发**：战斗结算收起（`close_battle`，有结算、挂机开着）后跑一轮，回到世界才动手；战斗中不发任何指令。挂机停了、agent 接管、断线、又进了战斗，或人物血量为 0，这一轮直接放弃：不写记录，也不停挂机。两项都关时什么都不做。
- **顺序**：先吃肉，再丢肉。每一步只发一条请求，回包之后才判断下一步，判断前先读一次背包、宠物和状态。
- **吃肉**（吃肉开着时）：
  1. 人物血量 ≤ 门槛 → 给人物吃（`item_use`，不传 `target`），吃到血量 > 门槛，或肉吃完为止。
  2. 人物达标后，出战宠（状态为出战、血量 > 0）血量 ≤ 门槛 → 喂宠（`item_use`，`target` 为宠物栏位 + 1，即 1–20，STAGE-346）。宠物没出战、已倒下、或血量够，跳过。
  3. 肉不够补到门槛 → 不停挂机，战斗记录写「战后补血：肉不足，人物 X% / 战宠 Y%」（没出战写「未出战」）。人物没达标就不轮到宠物。
- **肉的判定**（按背包里的名字和效果文字判断，不读物品表；解析同自动补血的 `heal_power`）：
  - **吃回血的肉**：名字含「肉」，效果文字能解析出 HP 回复量（如「耐久力40前後回复」→ 40）。魅力肉粽（名字或效果含「魅」）不吃。
  - **不吃的肉**：气力肉（「气力N前後回复」，解析不出 HP）、治状态的肉（「毒 / 混乱 / 酒醉 / 石化状态回复」，没有数字）。
  - **丢弃的肉**：名字含「肉」的都丢（HP 肉、气力肉、治状态肉）；魅力肉粽不丢。
  - **选法**：一次吃一份，回复量小的优先（同样多取格子靠前的），只看背包 5–19 格；目标类为「无」的（不能用的）跳过。喂宠只认「他人」类目标（`ally` / `ally_all`），专给自己用的（`self`）不喂宠。
  - **拉黑**：同一格被服务端拒绝（如 `ITEM_UNUSABLE`）的，本场不再吃这一格；只影响吃肉，丢弃照常。
  - **上限**：单场最多吃 **10 份**（人物和宠物合计），到上限写「战后吃肉已到 10 份上限，剩下的不吃了」。建议值 5 份在人物后期血量上千时吃不满，所以定为 10。
- **记录**：每吃一份写 `战后补血：对人物使用了 烤肉，血量回复 34`（喂宠写 `对乌力（战宠）使用了 …`）。
- **丢弃**（丢弃开着时，在吃肉之后执行；吃肉关着就直接丢）：
  - 从背包 5–19 格挑肉（判定同上），格子靠前的先丢；整格丢（`item_drop`，`confirm: "yes"`，不传 `count`）。装备格 0–4 不动。
  - 被拒绝（`EMPTY_SLOT` 之外）：这一格本场拉黑、跳过，不重试；`EMPTY_SLOT` 不计失败，下一次读背包自然跳过。
  - **上限**：单场最多发 **20 次**丢弃请求（失败的也算），到上限写「战后丢弃已到 20 次上限，剩下的肉留在背包」。
  - 每丢成功一件写 `战后丢弃：5 号 烤肉 ×3`（格子、名字、数量）；一轮结束写汇总「战后丢弃：丢弃 N 件，失败 M 件」（都为 0 不写）。
- **错误码**：`CHARACTER_DEAD`、`IN_BATTLE`、`CONTROLLED_BY_AGENT`、`CONTROLLED_BY_PLAYER` 放弃这一轮，写「战后处理中止（错误码）」。
- **丢弃的确认**：设置页里从「关」切到「开」弹一次确认，默认「取消」，确认后才写进草稿（还要「保存并应用」）；之后重进游戏不再确认。从「开」切到「关」不问。
- **旧方案文件**（没有这三项）读入时按默认值生效：吃肉开、门槛 90%、丢弃关；保存后文件里带上三项，`version` 升到 2。
- **不改的**：战斗内补血（门槛默认 30%）不受影响，战斗内没有新增指令；协议不新增消息，沿用 `item_use`（5.31）、`item_drop`（5.28）、`pets`、`status`、`inventory`。

## 打输后提示并停止（STAGE-265）

方案里的开关「打输后提示并停止」（恢复栏末尾，默认开；旧存档缺这一项按开）。开着时，**挂机开着、或无限遇敌进行中**，
战斗结果为打输（`battle_end` 的 `lose`，原地复活和被打飞都算）就：

1. 响一声提示音；
2. 停止自动挂机，关闭自动遇敌（先关本机自动出招，再在在线时发 `encounter off`；只开挂机、遇敌本来是关的，不发请求）；
3. 消息栏写一行「被打输了，已停止自动挂机和自动遇敌」，后面接着发送结果（「正在关闭自动遇敌」，服务端确认后「自动遇敌已关闭」）。

| 情形 | 行为 |
| --- | --- |
| 胜利、逃跑、平局 | 不触发（逃跑仍是旧的「自动挂机已关闭：已经逃离战斗」） |
| 手动战斗打输（挂机和遇敌都没开） | 不响，行为同旧版 |
| 观察方（agent 操控中） | 不处理，沿用 agent 的规则 |
| 开关关闭 | 与旧版一致：打输只关挂机，消息「自动挂机已关闭：战斗失败」，遇敌不动 |

判断在 `src/app/battle/net.rs` 的 `battle_end` 分支，停止和文案在 `src/app/battle/loss.rs`。

### 提示音

- 文件：`client/assets/sounds/lose.wav`（WAV，单声道 11025 Hz 8 位，约 0.5 秒）。编译期用 `include_bytes!` 嵌进二进制，
  不引入音频 crate（Linux 上 rodio/cpal 需要 alsa 开发库，会拖累发布构建）。
- 播放入口：`src/app/alert.rs` 的 `play_lose_alert()`，唯一的调用方是上面的打输处理。
- 运行时把嵌入的字节写到系统临时目录的 `stoneage-client-lose.wav`（已存在且大小一致就不重写），再起一个播放子进程，**不等待**，
  stdin/stdout/stderr 全部接到 null，不往终端写任何东西（否则会破坏界面）。播放器按平台依次尝试：

| 平台 | 命令 |
| --- | --- |
| macOS | `afplay <文件>` |
| Linux | `paplay <文件>`，不在则 `aplay -q <文件>` |
| Windows | `powershell -NoProfile -Command "(New-Object Media.SoundPlayer '<文件>').PlaySync()"` |

- 找不到播放器、spawn 失败、写临时文件失败或平台不在列表里，退回终端响铃（BEL，`\x07`）。播放失败不报错、不弹窗。
  播放器能起来但没有声卡或音频服务时检测不到，不会回退。
- 替换声音：换掉 `client/assets/sounds/lose.wav` 即可（保持 WAV；`alert.rs` 的测试检查 `RIFF….WAVE` 头和长度）。
  要换成别的格式，改 `alert.rs` 里的 `candidates()` 播放器列表，并同步这里。
- 测试：单元测试里 `play_lose_alert` 不发声，只计次数（`lose_rings()`）；集成测试在场景开头调 `alert::set_muted(true)` 静音。

## 方案文件

| 项 | 说明 |
| --- | --- |
| 位置 | Windows：`%APPDATA%\stoneage\auto-battle\<服务器>\<角色>.json`；其他平台：`$XDG_CONFIG_HOME/stoneage/auto-battle/...`（没有就用 `~/.config`） |
| 环境变量 | `STONEAGE_CONFIG_DIR` 可以指定根目录（测试与便携版用） |
| 隔离 | 按「服务器 + 角色」一个文件：换服、换角色都不串 |
| 格式 | `{version, active, profiles: [...]}`，每个方案含全部栏的字段 |
| 损坏 | 读不懂或版本更高 → 按默认方案打开并提示；**保存前先把原文件备份成 `.bak-<时间戳>`**，不静默覆盖 |
| 写法 | 先写 `.json.tmp` 再改名，避免写一半断电 |
| 不落盘 | 挂机/遇敌**运行状态**只在内存：重连、切角色、读方案都不会自动开始挂机或打开遇敌 |

## 与播放设置的关系

方案里只带「结果窗口自动继续」（托管时结果窗口 2.5 秒后自动关）。
回放速度与「跳过」**只在系统页设**（1× / 2× / 跳过 三档循环），设置页里不再重复放一份。
